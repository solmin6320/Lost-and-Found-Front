읽은 것 : `README.md`(PM 정리) · `00_안건.md` · 다섯 의견서 · `03_보안결정.md` · 스크린샷(`scr03_detail_other-photo_390_light_fold` · `scr01_list_390_light_user_fold` · `scr01_list_intent-lost_390_light_fold` · `scr01_list_filtersheet_390_light` · `scr02_create_errors_390_light` · `scr03_detail_mine-photos_390_light` · `scr03_detail_delete-dialog_390_light` · `scr01_list_1440_light_user_fold`) · `src/`(TextField · tokens · reset · 날짜 · 알림 영역) · `docs/화면정의서.md` · `docs/디자인품질기준.md`. 리포 파일은 고치지 않았다.

기준 : 기준 스킬 일곱 개 + UX 5법칙. `impeccable`은 런처가 없어 설명서(`SKILL.md` · `craft-floor` · `mode-operate` · `quieter` · `polish` · `layout` · `clarify` · `critique` 머리)를 직접 읽었다. 이 화면은 impeccable 분류로 **Operate(일을 끝내러 온 화면)**다 — "표현보다 훑어보기 · 일관성 · 익숙한 조작이 먼저"이고, 세계관은 글꼴 · 색 · 밀도 · **대표 동작 하나**로만 들어온다. 우리의 대표 동작은 이미 있다(의도 두 면 + 포스터). 그래서 이번 토론의 답은 거의 다 "더하지 말고 정확하게"다. `web-design-guidelines`는 최신 규칙을 받아 코드와 대 봤다(`touch-action: manipulation` · `overscroll-behavior: contain` · `color-scheme` · `theme-color` · `…` 표기 · 숫자 고정폭은 이미 지켜져 있다 — 새로 걸린 것은 C에 적었다).

## 0. 한 줄 입장

1차에서 나는 "필요한 곳에 강조가 없다"를 **떠 있는 것 · 붙는 것으로 메우려 했다.** 다른 담당의 근거를 읽고 그 방향을 거둔다. 휴대폰 상세의 하단 고정 줄, 목록의 떠 있는 글쓰기 버튼, 붙는 칩 줄을 **모두 들이지 않고**, 입구는 **흐름 안, 판단하는 순간의 자리**에 둔다. 대신 그 입구가 약해 보이지 않게 **모양(선 버튼 · 아이콘)과 자리**로 강조한다. 한 화면에 붙는 것은 헤더 하나(폼은 제출 줄)로 끝낸다.

## 목록 C — 새로 찾은 모순 · 누락

### C-1. 의견서끼리 · 문서 · 코드와의 모순, 새 기준 스킬이 잡은 것

- **UI2-1 · 제안 문구 속 기호를 아이콘처럼 쓰고 있다** — RV-1 `↓` · RV-2 `→` · 내 UI-11 `✓ 주인에게…` · README 3.8. 근거 : impeccable `craft-floor` "유니코드 기호 · 이모지를 아이콘 대신 쓰지 않는다", 맛 스킬 9.F 스크롤 신호 금지, 보안 조건 13(시스템 표시는 글자로 흉내 낼 수 없어야 — 사용자는 제목에 `✓`를 칠 수 있다). 제안 : 셋 다 Phosphor 아이콘(`aria-hidden`)으로, 시스템 문장은 아이콘 + 면. **P1**
- **UI2-2 · "부드럽게 옮겨 간 뒤 포커스"는 휴대폰에서 키보드가 안 뜬다** — UI-4 · AR-3 · RV-1 모두 "스크롤 → 포커스". iOS 브라우저는 누른 그 순간(같은 이벤트 안)에 `focus()`해야 키보드를 띄운다. 부드러운 스크롤이 끝난 뒤 포커스하면 칸만 테가 생기고 키보드가 안 떠 한 번 더 눌러야 한다. 웹 가이드라인 "모바일 자동 포커스는 아껴서"도 같은 쪽. 제안 : 누른 처리기 안에서 바로 `focus()`, 이동은 브라우저에 맡기고 `scroll-margin`(이미 `CommentSection.module.css:176`에 있다)으로 헤더에 안 가리게. 부드러운 스크롤은 넓은 화면 · 마우스에서만, 모션 줄이기면 즉시. **P0(①과 함께)**
- **UI2-3 · RV-2의 "유형 색 글자"는 대비가 안 된다** — `--lost-400` 글자는 흰 종이 위 약 1.7:1, 대비를 맞춘 `--lost-700`은 갈색이라 개념 색으로 읽히지 않는다. 제안 : 잉크 + 밑줄, 뜻은 말이 싣는다(A의 RV-2). **P1**
- **UI2-4 · AR-4 + UI-11/RV-5 : 글쓴이 완료 글에서 같은 사실을 두 번 말한다** — 배지 아래 "주인에게 돌아간 물건이에요." 바로 밑에 관리 칸의 "완료된 글은 상태를 바꿀 수 없어요". impeccable `clarify` "한 번만". 제안 : 글쓴이에게는 관리 칸 안 한 줄로 합치고, 방문자에게만 배지 아래 줄. **P1**
- **UI2-5 · 댓글 상대 시간(내 UI-14(b))은 데이터와 부딪힌다** — API D3 : `createdAt`이 시간대 오프셋 없는 서버 시계 값이라 운영 시간대(개선 목록 M5)가 정해지기 전엔 9시간 어긋날 수 있다. "3분 전"이 "9시간 전"으로 보이면 연락 판단을 그르친다. 제안 : 시간대 결정 뒤로 보류. 넣을 때는 `Intl.RelativeTimeFormat`(웹 가이드라인 "날짜는 `Intl`로"). **P1(보류 결정)**
- **UI2-6 · API-1(상태 여러 개 고르기)과 AR-2(상태 바로 반영 · 닫힘)가 부딪힌다** — 여러 개 고르기는 한 번 눌러 끝나지 않는다. 또 RV-4 고름 표시(채운 점)와 여러 개 고르기 관례(체크 상자)가 갈린다. 제안 : 백엔드 머지 전 = 상태 하나 고르기(채운 점 · 바로 반영), 머지 뒤 = 상태 체크 상자 + [적용하기]. 두 단계를 화면정의서에 함께 적는다. **P1**
- **UI2-7 · 예시를 안내 글로 옮기는 안(내 UI-9(b))은 문서 결정을 바꾸는 일이다** — 화면정의서 495행 "장소 · 제목의 예시는 도움말 줄에 둔다". 그런데 필터 시트 장소 칸은 이미 안내 글 `예: 강남역`(`PostFilterFields.tsx:69`)이라 지금도 둘이 어긋난다. 제안 : 안내 글로 통일하고 495행을 고친다. 조건 : 칸 이름은 늘 위에(맛 스킬 4.6 "안내 글을 이름으로 쓰지 않는다"), 안내 글 대비 4.5:1(지금 `--text-muted` 종이 위 5.6:1 · 검색칸 바탕 위 5.1:1 — 통과). **P2**
- **UI2-8 · 자기 화면을 가리키는 헤더 버튼 처리가 셋으로 갈린다** — 설정 톱니 = "지금 여기" 면, 등록 화면 [+] = 그대로, 로그인 화면 [로그인] = 숨김(AR-9 · RV-13, ✅로 분류됨). 제안 : 셋 다 옅은 면 + `aria-current="page"`. 숨김 + 자리 잡기는 헤더 오른쪽에 빈 구멍을 만든다. **P2**

- **UI2-12 · 다이얼로그 한 창 안에서 말투가 섞인다** — `scr03_detail_delete-dialog_390_light` 제목 "삭제할까요?" · 본문 "사라집니다. 되돌릴 수 없습니다." 반면 `front-design-rules` 문구 예시가 합니다체다. RV-7을 하면 스킬 예시도 함께 해요체로(문서 · 스킬 · 화면이 같은 말). **P2**

## 5법칙 점검(이번 최종 입장 기준)

1. 힉스 : 필터 시트 선택지 16 → 6~7, 같은 입구가 한 화면에 둘 보이지 않음, 기본값(완료 제외)은 결과가 없을 때만 말한다
2. 피츠 : 연락 · 글쓰기 입구를 판단하는 순간의 자리(본문 끝 · 결과 제목 아래)로, 위험 동작 16px, 누르려는 순간 생기거나 움직이는 목표 0
3. 제이콥 : 대화 끝 입력칸 · 칩 아래 펼침 칸 · 체크 상자 = 여러 개 · 빨간 오류 문장 · 지금 여기 표시는 관례 그대로, 생김새(떠 있는 둥근 버튼 · 하단 줄)는 들이지 않음
4. 근접성 : 입구는 그 일을 말하는 문장 바로 아래, 완료 사실은 관리 칸 안 한 번, 묶음은 간격으로
5. 폰 레스토프 : 화면마다 잉크 채움 하나 이하(상세 = 댓글 제출, 목록 = 넓은 화면 헤더 [글 올리기]뿐 · 휴대폰 0, 폼 = 올리기), 빨강은 14px 문장 한 줄, 색만으로 가르지 않음(아이콘 · 말 함께)
