### ① 상세 — 환경마다 입구는 정확히 하나

| 환경 | 입구 | 자리 |
|---|---|---|
| 폭 48rem 미만 **그리고** 높이 40rem 이상(390×844 · 375×667 등 세운 휴대폰) | 하단 댓글 줄 `[댓글 남기기]` + 수(작게) | 화면 아래, `safe-area`, 등록 폼 제출 줄과 같은 틀 |
| 그 밖 전부(넓은 화면 · 568 휴대폰 · 가로 휴대폰 · 200% 확대) | RV-1 글자 링크 `댓글로 연락하기` + 수 + 아래 화살표 **아이콘** | 메타 줄(글쓴이 · 등록 · 조회) 바로 아래 — 본문 "댓글로 알려 주세요"와 붙은 자리 |

- 둘은 한 컴포넌트, 같은 미디어 쿼리로 하나만 그린다 — 한 화면에 같은 입구 둘은 없다
- **RV-1 자리만으로는 휴대폰 첫 화면에 안 들어온다**(실측) : `scr03_detail_other-photo_390_light_fold`에서 본문 첫 줄이 y≈790, 그 아래 메타 줄 → 링크는 y≈880~920(본문 2줄 기준), 첫 화면 844 밖이다. 긴 본문(`…other-poster`, 주소 9줄)이면 훨씬 아래. 1440은 메타 y=482 · "댓글 45" y=569로 첫 화면 안이다 → 넓은 화면은 링크로 충분
- 줄을 붙이는 조건 · 숨기는 조건 : 진짜 입력칸(비로그인은 로그인 안내 칸)이 화면에 들어오면 숨긴다(`IntersectionObserver` — 스크롤 리스너 금지, `design-taste` 5.D). 스크롤 **방향**으로는 숨기지 않는다
- 누르면 : 클릭 처리 안에서 바로 입력칸에 `focus()`(iOS는 사용자 동작 안에서만 키보드를 연다 — 비동기 스크롤 뒤로 미루면 키보드가 안 뜬다), 스크롤은 줄 · 헤더에 가리지 않게 `scroll-padding`. 모션 줄이기면 즉시
- 비로그인 : `[로그인하고 댓글 남기기]` → `loginPath(here + '#comment')`. 돌아오면 상세가 `#comment`를 보고 **입력칸 영역(제목)** 으로 스크롤 · 포커스 — 입력칸 자체에 포커스를 주지 않는다(웹 가이드라인 "휴대폰에서 autoFocus 피하기", 사용자가 누르지 않은 키보드)
- 완료 글 : 줄의 버튼은 선 버튼(채운 강조를 끝난 글에 쓰지 않는다) · 짧은 알림(`showFlash` — 상세가 쓴다, `PostDetailPage.tsx:114`)은 줄 위로 비켜 뜬다

### ② 글쓰기 입구 — 왜 내가 지는가

- **내 안의 결함(AR2-1)** : AR-1은 "의도 면이 화면에 보이는 동안 숨김"이다. [주웠어요]를 누르면 화면은 그 자리에 머물고 의도 면이 그대로 보인다(`scr01_list_intent-lost_390_light_fold`) — **습득자가 올릴 결심을 하는 바로 그 순간에 버튼이 없다.** RV-2 링크는 같은 순간 결과 제목 아래(390에서 y≈450)에 보인다
- 2열 사진 격자에서 오른쪽 아래 버튼은 오른쪽 카드의 제목 · 장소를 가리고(`scr01_list_scroll-mid_390_light`), 짧은 알림 · 200% 확대와 겹친다(`ui-ux-pro-max` Fixed Positioning "고정 요소를 겹겹이 쌓지 말 것")
- 그래서 : RV-2 링크(의도를 골랐을 때만 · 결과 4건 이하 · 0건이면 숨김) + **헤더 [+]가 보던 의도를 싣는다**(`?type`, 이름표 · `aria-label`도 `습득 글 올리기`로 — `impeccable clarify` "버튼 이름은 일어날 일을 말한다") + 목록 끝 칸 그대로
- 헤더 [+]를 빼지 않는다 — 떠 있는 버튼을 안 들이니 UI "하지 말 것 1"의 전제가 없다. 온보딩 1층 3단계 대상도 그대로(바꿀 것 0)
- "같은 입구는 한 화면에 하나"의 셈 : **헤더는 셈에서 뺀다**(어느 화면에나 있는 길 — 비로그인 설정의 [로그인] 둘을 둔 1차 AR-9와 같은 판단). 본문 안의 같은 입구(RV-2 링크 · 목록 끝 칸 · 빈 상태 버튼)는 동시에 하나만. 이름은 어디서나 같은 말(`습득 글 올리기`) — `design-taste` 4.5 "같은 의도에 다른 이름 금지"

### ③ 필터 — 쪼개도 탭은 늘지 않는다

| 과업 | 지금(네 묶음 한 시트) | AR-2(칩 = 묶음) |
|---|---|---|
| 카테고리 하나 | 칩 → 지갑 → [적용하기] = **3**, 선택지 16 | 칩 → 지갑(바로 반영 · 닫힘) = **2**, 선택지 6 |
| 카테고리 + 상태 | 칩 → 지갑 → 연락중 → [적용하기] = **4** | 칩 → 지갑 → 칩 → 연락중 = **4** |
| 카테고리 + 장소 | 칩 → 지갑 → 장소 입력 → [적용하기] = **3** + 입력 | 칩 → 지갑 → 칩 → 입력 → [적용하기] = **4** + 입력 |

- 조건 둘을 거는 경우도 탭은 같거나 하나 많을 뿐이고, 대신 **매번 조건 하나가 바뀐 결과를 바로 본다**(바뀐 값은 칩 `카테고리: 지갑 ×`가 말한다). 가장 흔한 과업(조건 하나)은 탭 3 → 2, 선택지 16 → 6
- **[초기화] 문제는 없애서 푼다**(API 지적) : 카테고리 · 상태 시트에는 [초기화] · [적용하기]가 없다 — 고르면 끝이고, "전체"(⑧ 뒤에는 `완료 빼고`)가 곧 되돌리기다. 장소 · 기간 시트만 `[지우기](이 묶음만)` + `[적용하기]`. 모두 지우기는 칩 줄 맨 앞 `[전체 해제]` 한 곳(이미 있다)
- 넓은 화면(48rem 이상) : 가운데 다이얼로그 + 뒤 흐림 대신 **누른 칩 바로 아래 펼침 칸**(팝오버 — 뒤를 덮지 않는다, Esc · 바깥 누름으로 닫고 칩으로 포커스 복귀). `impeccable` craft-floor "가로막을 이유도 포커스를 지킬 이유도 없는 일에 모달" · operate "Modal as first thought"가 지금 모습을 정확히 가리킨다
- 중간안(누른 묶음만 펼친 접이식 한 시트)은 반대 — 접힌 묶음을 펴는 탭이 늘고, 시트는 여전히 화면을 덮는다
- 휴대폰 묶음 시트 높이 : 카테고리 ≈ 2줄 · 상태 ≈ 1줄 + 뜻 한 줄 → 화면의 약 35~40%(지금 81%)

### ④ "한 화면에 붙는 것 총량" — 제안 규칙 (수치)

헤더 57 · 제출 줄 / 댓글 줄 69 · 칩 줄 52 (CSS px, 실측 · 1차 의견서 값)

1. **붙는 것은 헤더 + 하나까지.** 둘째는 그 화면의 주 동작 줄 하나 — 폼 = 제출 줄, 상세 = 댓글 줄, 목록 = 칩 줄(⑥ [더 보기] 채택 시). **떠 있는 버튼(FAB)은 어느 화면에도 없다**
2. **둘째는 뷰포트 높이 40rem(640px) 이상에서만.** 40rem은 "헤더 + 69px 줄 = 126px ≤ 높이의 20%"가 성립하는 경계다(126 / 640 = 19.7%)
3. 높이 25rem(400px) 미만(400% 확대 · 아주 낮은 가로 화면)은 **헤더도 붙이지 않는다**(검토 항목 — 지금 동작을 바꾸는 일)
4. 붙은 줄은 포커스된 요소를 가리지 않는다 — `scroll-padding-top / bottom` = 붙은 높이 + 8(웹 가이드라인 "sticky가 포커스를 가리면 안 된다") · 같은 일을 하는 진짜 요소가 화면에 들어오면 붙은 줄을 숨긴다 · 방향에 따라 숨겼다 보이지 않는다 · 짧은 알림은 붙은 줄 위로 · **입력칸은 붙이지 않는다**(키보드)
5. 높이 판정은 **레이아웃 뷰포트 미디어 쿼리**(`min-height: 40rem`)로 한다 — `visualViewport`로 재면 키보드가 올라올 때마다 줄이 켜졌다 꺼진다

|---|---|---|---|
| 844 | 390×844 휴대폰 | 헤더 + 줄(제출 · 댓글) / 헤더 + 칩 줄 | 126 · **14.9%** / 109 · 12.9% |
| 667 | 375×667 휴대폰 | 〃 | 126 · **18.9%** / 109 · 16.3% |

- 1차 "하지 말 것 4"의 목록 칸을 "글쓰기 버튼" → "칩 줄(조건부)"로 고친다

### ⑧ 완료 글 기본 제외 — 데이터 담당 질문에 대한 답

- **기본값** : 목록(SCR-01)은 모든 의도 · 검색 · 필터에서 **완료를 뺀다.** 의도 면 숫자도 같은 기준(API-1) — "12건 보기"를 누르면 12장이 나온다. **내가 쓴 글(SCR-07)은 빼지 않는다**(자기 기록이고 탭이 이미 상태를 가른다)
- **"완료 포함" 입구 = 필터 상태 묶음 한 곳.** 선택지는 넷 그대로(힉스 — 늘지 않는다) : `[완료 빼고](기본)` `[게시중]` `[연락중]` `[완료]`. 지금의 `전체`(완료까지 섞어 보기)는 없앤다 — 끝난 글을 진행 중인 글 사이에 섞어 볼 과업이 없다. 끝난 글이 궁금하면 `[완료]` 하나
- 결과 고지(누르기 전에 · 한 번) : 상태 묶음의 뜻 한 줄 끝에 `완료된 글은 기본으로 빼고 보여요.` — 다른 곳(첫 화면 · 결과 제목)에는 되풀이하지 않는다. 칩은 기본일 때 값 없이 `상태`, 다른 값을 고르면 `상태: 완료 ×`
- 목록 끝 "주인에게 돌아간 물건 N건" 신뢰 줄은 **두지 않는다** — 첫 화면 요청 +1(D8 표 훑기), 요소 +1, 급한 사용자의 과업과 무관
- **백엔드 요청 방식 : `status` 여러 값(`List<PostStatus>` + `in`)**. 이유 — `완료 빼고`가 `status=OPEN&status=IN_PROGRESS`로 주소에 사실대로 남고, `excludeDone=true&status=OPEN` 같은 겹치는 조합이 생기지 않는다. 프론트는 `client.ts:118` `QueryValue` 배열 지원 + 기본값은 주소에 쓰지 않는다(`/`가 어느 기기에서나 같은 목록)
- 머지 전에는 지금 모습 그대로(앞에서 흉내 내지 않는다 — API 하지 말 것 3)
- 완료 확인 다이얼로그에 한 문장 추가(AR2-8)

## 목록 C — 새로 찾은 모순 · 누락

- **AR2-1 · 내 AR-1의 자기모순** — "의도 면이 보이면 버튼을 숨긴다"와 "첫 방문 습득자가 [주웠어요]를 누른 순간 올리는 입구가 없다"를 같은 안이 풀겠다고 했다. 누른 직후 의도 면은 화면에 남는다(`scr01_list_intent-lost_390_light_fold`). → AR-1 철회(②)
- **AR2-2 · 1차 사실 정정 : 댓글 칸에는 앱 안 이탈 확인이 없다** — 1차에 "`useLeaveGuard`는 글 폼 · 댓글에만"이라 적었고 README 3.13에 옮겨졌는데, 틀렸다. `useLeaveGuard`를 쓰는 곳은 `PostForm.tsx:172` 하나뿐이고 댓글은 `beforeunload`만 건다(`CommentSection.tsx:287-294`). 댓글을 반쯤 쓰다 `목록으로` · 헤더 로고 · [서비스 안내]를 누르면 **확인 없이 사라진다.** 댓글 수정 칸(`CommentItem`)도 같다
- **AR2-3 · 설정 화면 이탈 확인의 해법 — "쓰던 칸 등록부" 하나** (1차 질문 3의 답)
  - 문제의 뿌리는 둘 : 설정 · 댓글에 앱 안 이탈 확인이 없다 + React Router의 `useBlocker`는 **한 번에 하나만** 동작한다. 설정(닉네임 · 비밀번호 두 폼), 상세(댓글 입력 + 댓글마다 수정 칸)에 폼마다 `useLeaveGuard`를 붙이면 서로 덮는다
  - 해법 : 화면(라우트)마다 **막는 곳은 하나**, 칸들은 "쓰던 글자가 있다"만 등록한다(`useUnsavedField(id, dirty)` → 레이아웃의 등록부 → 하나의 `useLeaveGuard(등록부.any)`). 같은 등록부를 **SE-5 로그아웃 확인**도 읽는다 — 판정 기준이 하나라 "어떤 화면은 묻고 어떤 화면은 안 묻는" 어긋남이 없다
  - 설정의 dirty : 닉네임이 지금 값과 다름 · 비밀번호 세 칸 중 하나라도 글자가 있음. 확인 문장은 1.7 공통(`[계속 쓰기]` 기본 포커스 `[나가기]`). 비밀번호 변경 성공 → 로그인 이동 전에 `allowLeave()`
  - [서비스 안내]는 바꾸지 않는다 — 이탈 확인이 모든 출구(로고 · 메뉴 · 뒤로가기 · 안내)를 한 번에 막는다. 버튼마다 예외를 두는 것보다 단순하다
- **AR2-4 · ④와 ⑥은 한 묶음이다** — 지금은 쪽을 넘기면 결과 제목(칩 줄 바로 아래)으로 데려가므로 칩이 늘 가깝다(화면정의서 SCR-01 ③ "페이지를 넘기면 결과 제목으로"). [더 보기]는 위로 데려가지 않는다 → 96장(390에서 약 4,139 × 4 ≈ 16,500px)을 내린 뒤 조건을 바꾸려면 그만큼 되돌아가야 한다. [더 보기]만 들이고 칩 줄을 안 붙이면 피츠가 지금보다 나빠진다
- **AR2-5 · 글자 기호를 화살표로 쓴다** — RV-1 `댓글로 연락하기 · 45 ↓`, RV-2 `습득 글 올리기 →`. `frontend-design`은 "링크 · 버튼 글자 끝에 붙인 →"를 생성물의 흔한 티로, `impeccable` craft-floor는 "유니코드 기호를 아이콘 대신 쓰기"를 거부 목록에 둔다. 우리 규칙도 "문자 기호를 아이콘처럼 쓰지 않는다"(`front-design-rules`). → Phosphor 화살표 아이콘(`aria-hidden`) 또는 없음. 가운뎃점도 한 줄 하나까지(`design-taste` 9.F)
- **AR2-6 · RV-1 자리는 휴대폰 첫 화면 밖이다** — ①-상세의 실측. "방문자 첫 화면에 주 동작이 없다"(README 3.1)는 RV-1만으로는 닫히지 않는다
- **AR2-7 · 넓은 화면 필터 다이얼로그는 새 기준이 잡는 패턴** — `impeccable`(craft-floor · operate)이 "가로막을 필요 없는 일에 모달"을 기본값의 실패로 적는다. 1차에서는 피츠(누른 칩과 먼 가운데)만 근거로 댔는데, 이제 근거가 둘이다(③)
- **AR2-8 · 완료 기본 제외가 만드는 "내 글이 사라졌다"** — 글쓴이가 상세에서 [완료로 바꾸기] → `목록으로`를 누르면 방금 그 글이 목록에서 빠져 있다. 결과 고지 규칙(누르기 전에 · 한 번)대로 완료 다이얼로그 문장에 더한다 : `완료된 글은 목록 기본 보기에서 빠져요. 내가 쓴 글에는 남아요.`(`PostOwnerPanel.tsx:210` 다음 줄). ⑧ 머지와 함께
- **AR2-9 · 등록 화면의 헤더 [+]는 눌러도 아무 일이 없다** — 같은 경로라 이탈 확인을 안 타고(`useLeaveGuard.ts:36` 경로 비교), 폼은 `?type`을 처음 한 번만 읽는다(`PostCreatePage.tsx:31`). ②에서 [+]가 의도를 싣게 되면 주소만 `?type=LOST`로 바뀌고 화면은 `FOUND` 그대로인 어긋남까지 생긴다. → 등록 화면에서는 `aria-current="page"` + 누름 무시(UI-6 (d)의 옅은 면과 함께)
- **AR2-10 · 내 글 관리를 올리면(AR-4) 삭제 다이얼로그 겹침을 다시 잰다** — SE-1의 실측(390 [완료로 바꾸기] x 202–325 ↔ 확인 버튼 x 199–354)은 지금 자리 기준이다. 패널이 사진 앞(y≈260 근처)으로 오면 가운데 다이얼로그의 확인 버튼과 세로로도 가까워질 수 있다. 보안 안전 조건 12 그대로
- **AR2-11 · 같은 의도의 이름이 셋** — 헤더 `글 올리기`(이름표), 목록 끝 `+ 분실 글 올리기`, RV-2 `분실 글 올리기 →`. 의도를 골랐으면 셋 다 `분실 글 올리기` · `습득 글 올리기`로(②). `design-taste` 4.5 "같은 의도 · 같은 이름"

## 5법칙 점검표 (이번 입장 전체)

1. **힉스** : 필터 한 번에 보이는 선택지 16 → 6(카테고리) · 4(상태), 상태 선택지 수는 ⑧ 뒤에도 4 그대로, 기본값 `완료 빼고`를 묶음 뜻 줄에서 드러낸다. 글쓰기 입구는 본문 안 동시에 하나
2. **피츠** : 상세 입구는 키 큰 휴대폰에서 엄지 자리(≈0px 이동), 그 밖은 본문 바로 아래. 위험 동작 16px. 떠 있는 버튼 0 — 카드 · 알림 가림 없음. 붙는 것 합계 ≤ 높이 20%
3. **제이콥** : 오류 빨강 · 사진 피드 [더 보기] · 칩 아래 펼침 · 목록 끝 다음 행동 — 동작과 자리만 관례, 생김새(하단 탭바 · 떠 있는 원형 버튼)는 들이지 않는다
4. **근접성** : 연락 입구는 "댓글로 알려 주세요" 문장 바로 아래, 펼침 칸은 누른 칩 바로 아래, 글쓰기 링크는 결과 제목 바로 아래
5. **폰 레스토프** : 상세에서 채운 강조는 댓글 줄 하나(입력칸이 보이면 그 [댓글 남기기]로 넘어감), 목록 첫 화면은 의도 면 한 묶음. 화살표는 글자 기호가 아니라 아이콘, 색만으로 구분하는 `:visited`는 뺀다

판단 메모 — 법칙끼리 부딪힌 곳 : ②에서 피츠(엄지 자리)와 "사용자 먼저"(가리지 않음 · 확대 사용자)가 부딪혀 후자를 따랐다. ①에서는 같은 둘이 부딪히지만 상세는 한 열이라 가릴 것이 적고 높이 조건으로 확대 사용자를 빼서 피츠를 따랐다.
