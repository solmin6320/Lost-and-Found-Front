## 2. 한눈에 — 다섯이 공통으로 본 것

1. **지금 디자인의 뼈대는 맞다.** 개념 색(마리골드 · 코발트)이 늘 같은 뜻, 사진 피드 · 포스터에 템플릿 티 없음, 누르는 면 44px 미만 0곳, 가로 넘침 0, 색만으로 구분되는 곳 0곳. 바꿀 것은 **빼기와 옮기기**다
2. **문제는 강조 과잉이 아니라 "필요한 곳에 강조가 없다"** — 연락(댓글) 입구, 완료된 글의 상세, 방금 틀린 칸
3. **거리(피츠)가 가장 크다.** 과업 탭 수는 이미 짧다(6~9). 대신 조작에 닿으려고 내리는 거리가 900~2,800px — 상세의 댓글 입력, 글쓴이의 내 글 관리, 휴대폰 글쓰기 입구
4. **위험 동작이 자주 쓰는 동작에 붙어 있다** — [수정][삭제] 8px, 댓글 수정 · 삭제 4px, 삭제 다이얼로그 [삭제하기]가 여는 버튼 바로 위에 뜬다(두 번 누르면 삭제)
5. **법칙을 기계적으로 쓰면 나빠진다**(반대 검토) — 전부 크게, 떠 있는 버튼 · 붙는 막대 늘리기, 색 강조 늘리기, 쪼개고 줄이기

## 3. 주제별 정리

### 3.1 상세 — 연락(댓글) 입구 ⚖️ 쟁점 ①

| 무엇이 문제인가 | 제안 |
|---|---|
| 글은 "댓글로 알려 주세요"라는데 입력칸이 댓글 맨 끝(5개 글 y≈2,160 · 45개 글 y=3,440). 방문자 첫 화면에 주 동작이 없다. 비로그인은 로그인하고 돌아오면 다시 맨 위 | **UI-4 · AR-3** 휴대폰 하단 고정 줄 [댓글 남기기 · 45] → 입력칸으로 데려가 포커스, 입력칸이 보이면 줄을 숨김, 입력칸 자체는 붙이지 않음(키보드) / **RV-1** 떠 있는 막대 대신 메타 줄 아래 흐름 안 글자 링크 `댓글로 연락하기 · 45 ↓` |

- 합의 : 입구가 필요하다 · 입력칸 자체를 화면 아래에 붙이지 않는다 · 넓은 화면은 "댓글 N" 제목 옆
- 쟁점 : 휴대폰에서 **하단 고정 줄**(피츠 · 잘 보임)이냐 **흐름 안 링크**(가림 없음 · 확대 사용자)냐. 로그인 뒤 입력칸 복귀(RV-1 선택안)는 `authRedirect` · `RouteFocus` 규칙과 함께 본다
- 관련 : API — 새 댓글은 목록 끝에 붙는다(서버 정렬 고정), 입력칸 위치를 바꾸면 "방금 남긴 댓글"을 입력칸 옆에 보여 줘야 한다

### 3.2 휴대폰 글쓰기 입구 ⚖️ 쟁점 ②

| 무엇이 문제인가 | 제안 |
|---|---|
| 휴대폰 입구는 화면 맨 위 [+](보이는 36px, [?] [⚙]와 같은 무게) 하나. 의도 모드의 [+ 분실 글 올리기]는 목록 끝(≈1,500 ~ 4,000px 아래). 첫 방문한 습득자가 [주웠어요]를 누르면 올리는 화면이 아니라 목록이 나온다 | **AR-1** 목록 · 내가 쓴 글 오른쪽 아래 글쓰기 버튼(의도에 따라 이름 · 색 · `?type=`), 의도 면이 보일 때는 숨김 / **RV-2** 의도를 골랐을 때만 결과 제목 아래 글자 링크 `습득 글 올리기 →`(결과 4건 이하 · 0건이면 숨김) / **UI 하지 말 것 1** 떠 있는 버튼을 들이면 헤더 [+]는 뺀다 — 둘 다 두지 않는다 |

- 합의 : 헤더 [+]도 보던 의도(`?type`)를 싣는다 · 한 화면에 같은 입구가 동시에 둘 보이지 않는다
- 쟁점 : 떠 있는 버튼(국내 앱 공통 관례의 자리) vs 흐름 안 링크(카드 · 배지 · 알림을 가리지 않음). 떠 있는 버튼이면 헤더 [+]를 뺄지. 온보딩 3단계 대상도 따라 바뀐다

### 3.3 위험 동작의 거리 — [수정][삭제] · 댓글 · 확인 창

| 무엇이 문제인가 | 제안 |
|---|---|
| [수정][삭제] 8px · 댓글 수정 · 삭제 4px · 확인 칸 [취소][삭제하기] 8px · 삭제 다이얼로그 [삭제하기]가 여는 [삭제] 바로 위(1440에서 약 50×14px 겹침) | **SE-1** 🔒 확인 버튼은 열린 뒤 0.5초 안의 포인터 누름 무시 · **RV-3** 세 곳 모두 16px, 순서 · 크기 그대로 · **UI-5 · AR-7** [삭제]를 줄 오른쪽 끝으로 |

- 확정 : SE-1(누름 무시, 버튼은 옮기지 않음)
- ✅ 합의에 가까움 : 간격 16px(RV-3)
- ⚖️ 남은 것 : [삭제]를 오른쪽 끝으로 보내는 안 — 보안 담당은 "390에서 다이얼로그 [삭제하기] 자리로 옮겨 두 번 누름 위험이 커진다"고 반대. PM 1차 의견 : 16px + 모양 차이로 충분, 양 끝 배치는 채택하지 않는 쪽

### 3.4 헤더 ✅

| 무엇이 문제인가 | 제안 |
|---|---|
| 휴대폰 누르는 면 4개가 4px 간격 · 설정이 톱니와 계정 메뉴 두 곳 · 비로그인 [+]와 [로그인]이 같은 선 상자 · 로그인 · 가입 화면에도 [로그인] · 설정 화면에 로그아웃이 없다 | **UI-6 · AR-6** 로그인하면 톱니를 빼고 계정 메뉴 "설정" 하나로(비로그인은 톱니 유지 — 화면 모드), 간격 8~12px · **UI-6** [로그인]은 글자 버튼 · **AR-9 · RV-13** 로그인 · 가입 화면에서 헤더 [로그인] 숨김(자리는 유지) · **AR-6** 설정 화면 끝에 조용한 [로그아웃] · **RV-12** 360 이하는 로고 규칙 때문에 간격 유지 |

### 3.5 필터 ⚖️ 쟁점 ③

| 무엇이 문제인가 | 제안 |
|---|---|
| [카테고리] 칩 하나를 눌러도 네 묶음 · 누를 것 16개가 화면 81%를 덮고, [적용하기]를 한 번 더 · 넓은 화면은 누른 칩과 먼 가운데 다이얼로그 · 고른 칸이 선 굵기로만 다르다 | **AR-2** 칩 하나 = 그 묶음 하나, 카테고리 · 상태는 누르면 바로 반영하고 닫힘, 장소 · 기간은 [적용하기] 유지, 넓은 화면은 칩 바로 아래 펼침 / **RV 반대 6** 칩마다 쪼개면 조건 둘을 걸 때 두 번 연다 — 네 묶음 한 시트 유지(지금도 누른 묶음으로 포커스) / **API** 쪼개면 [초기화]는 "이 묶음만"으로 뜻을 바꿔야 / **API-5** [적용하기 · 12건] 미리 보기(P2, 인덱스 뒤) |

### 3.6 스크롤해도 검색 · 필터 ⚖️ 쟁점 ④

- **AR-5** 칩 줄을 헤더 아래 붙이기(맨 앞 [돋보기] → 맨 위 검색칸), 높이 30rem 미만 · 200% 확대는 붙이지 않음
- **RV 반대 3** 헤더 + 검색 + 칩이면 844 화면의 20%, 작은 휴대폰 30% — 붙는 것은 헤더 하나
- **API** 검색칸을 두 벌 두면 치던 글자가 갈린다 — 붙일 거면 한 벌만
- 3.1 · 3.2와 함께 "한 화면에 붙는 것의 총량"으로 정한다(AR 하지 말 것 4 : 목록 = 글쓰기, 상세 = 댓글 줄, 폼 = 제출 줄, 그 이상은 없음)

### 3.7 선택 · 오류 표시 체계 ⚖️ 쟁점 ⑤

| 무엇이 문제인가 | 제안 |
|---|---|
| "두꺼운 잉크 선" 하나가 선택 · 오류 · 포커스를 다 맡는다. 오류 문장이 다음 칸 이름과 같은 모양(14px · 굵기 600 대 700 · 같은 색)이라 "! 제목을 적어 주세요"가 칸 이름처럼 읽힌다. 같은 "고름"이 화면마다 네 모양 | **UI-1** 오류 문장 · 틀린 칸 테두리만 `--danger-text`(아이콘 · 문장 유지), 오류가 떠 있는 동안 그 칸 도움말 숨김 · **UI-2** 글자 선택지 = 잉크 채움, 그림 칸 = 선 + ✓, 탭 = 밑줄, 의도 = 색 면 + ✓ · **RV-4** 필터 고른 칸에 작은 표시만 더하고 면은 채우지 않음, 빨강은 삭제 전용 유지 · **RV 질문** ✓는 이미 "완료" 뜻 — 고름 표시는 채운 점으로? |

- 쟁점 : 오류에 빨강을 쓸지(**"빨강은 삭제 전용" 결정을 바꾸는 일** — 삭제와 오류 모두 "멈춰서 보라"라 충돌하지 않는다는 시각 담당 vs 유지하자는 사용자 담당). 둘 다 동의하는 최소안 : 오류가 떠 있는 동안 도움말 숨기기 + 선택 표시를 모양으로 가르기

- **RV-10** 온보딩 테 안을 누르면 안내를 닫고 그 동작을 그대로 실행(지금은 닫기만 해서 "여기를 누르세요"가 약속을 어긴다)
- **UI-13** 어둡게 주 버튼 채움 한 단계 낮춤(#ECEDEF → #D5D8DD, 대비 약 12.5:1) — 가장 눈부신 면이 버튼이 되지 않게
- 발견(화면 흐름) : **설정 화면에 이탈 확인이 없다** — 새 비밀번호를 치다 헤더 [서비스 안내]를 누르면 목록으로 떠나 잃는다

### 3.14 목록 넘기기 ⚖️ 쟁점 ⑥

- **AR-8** 휴대폰은 [24건 더 보기]로 이어 붙이기(P2, L) · **API-2** 자동 무한 스크롤이 아니라 [더 보기]를 누를 때마다 `size=24×page`로 한 번에 다시 받기(96건까지, 주소에 펼친 쪽 수, 새로고침 · 뒤로가기 1건 복원, P1, M)
- 합의 : 자동 무한 스크롤은 하지 않는다(새로고침 · 공유 · 뒤로가기가 깨지고 목록 끝 "찾는 물건이 없나요?"에 닿지 못한다)
- 쟁점 : 방식(API-2 권장)과 착수 시점, 새 글이 끼어 한 칸 밀릴 때 "새 글 1건 [보기]"로 따로 알릴지

### 3.15 데이터로 받치는 체감 속도 ✅

- **API-3** 상세 로딩 중 목록 캐시의 제목 · 배지 · 첫 사진을 먼저 그린다(추가 요청 0) · **API-4** 등록 성공 뒤 마지막 목록 하나 + 의도 건수만 미리 다시 받고 "방금 올린 글" 한 번 표시(메모리만) · **API-6** `:visited`로 이미 본 글 제목 한 단계 흐리게(요청 · 저장소 0) · **API-7** 검색어가 카테고리와 맞으면 "[전자기기로 좁히기]" 제안(요청 0) · **API-8** 내가 쓴 글 중복 요청 4 → 3

## 4. 하지 말아야 할 것 (다섯 의견서에서 모음)

1. **전부 크게** — 44px는 누르는 면의 하한이지 보이는 크기의 목표가 아니다. 오조작은 크기가 아니라 **가로 간격과 확인**으로 막는다
2. **떠 있는 것 · 붙는 것을 늘리기** — 한 화면에 채운 강조 하나. 스크롤 방향에 따라 헤더를 숨겼다 보이기 금지(누르려는 순간 움직인다)
3. **강조를 더해서 강조 만들기** — 한 구역에 색 면 한 묶음 + 잉크 채움 하나. 움직임 · 깜빡임으로 강조하지 않는다
4. **힉스를 "지우기"로** — 결과 고지 · 개인정보 줄은 개수가 아니라 안전. 사진 피드를 고르는 일은 힉스의 대상이 아니다. 등록 폼을 여러 단계로 쪼개지 않는다
5. **제이콥을 "생김새 따라 하기"로** — 따를 것은 동작과 자리. 하단 탭바 같은 겉모습은 들이지 않는다(목적지가 셋뿐)
6. **상세를 모달 · 옆 패널로** — 주소 공유 · 뒤로가기 · 스크롤 복원이 깨진다
7. **내가 쓴 글 카드에 상태 · 수정 · 삭제 버튼** — 카드 전체가 링크라 오터치
8. **백엔드가 못 하는 일을 앞에서 흉내 내기** — 받은 24장에서 완료 빼기, 한 쪽 안에서만 재정렬, 잠금 시간 추정
9. **카드에 손을 올리면 상세 미리 받기** — 조회수 쓰기
10. **되돌릴 수 없는 확인을 "되돌리기 알림"으로 대체**, 사용자 글의 전화번호 · 주소를 누르면 바로 걸리게, 개인 흔적을 `localStorage`에, 보안 경고 되풀이
