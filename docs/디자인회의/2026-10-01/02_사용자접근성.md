## 0. 먼저 — 이번에 내가 틀렸던 것

1. **RV-1의 자리(메타 줄 아래)는 첫 화면 문제를 풀지 못한다.** 다시 재 보니 390 상세에서 메타 줄은 y≈900(사진 글) ~ y≈1,277(긴 본문 글, `scr03_detail_other-poster_390_light`)로 **첫 화면(844) 밖**이고 "댓글 N" 제목 바로 위다. 45개 글에서 2,480px를 건너뛰게 해 줄 뿐, "첫 화면에 주 동작이 없다"(UI-4 · AR-3)는 그대로 남는다
2. **"떠 있는 버튼이 오른쪽 카드의 상태 배지를 가린다"(1차 역효과 2)는 과장이었다.** 배지는 사진 **왼쪽 위**다(`scr01_list_scroll-mid_390_light`). 오른쪽 아래 버튼이 가리는 것은 지나가는 카드의 제목 끝 · 장소 줄이고, 스크롤하면 비켜난다
3. **"붙는 막대 170px · 844의 20%"(역효과 3)는 AR-5가 내지 않은 안을 친 것이다.** AR-5는 검색칸을 붙이지 않는다(칩 줄 + 돋보기만). 실제는 헤더 57 + 칩 줄 52 = **109px(844의 12.9%)**
4. **"칩마다 쪼개면 조건 둘에 두 번 연다"(역효과 6)는 탭 수로 따지면 틀렸다.** 바로 반영이면 조건 둘 = 칩 → 값 · 칩 → 값 **4탭**, 지금 한 시트 = 칩 → 값 → 값 → [적용하기] **4탭**. 같다. 남는 반대는 탭 수가 아니라 **키보드 · 다중 선택**이다(표 B ③)
5. 1차에서 "삭제 다이얼로그는 관례대로다"라고 적었지만 **두 번 누르면 확인까지 눌리는 자리(SE-1)를 놓쳤다.** 보안 담당이 맞다

## 표 B · 쟁점 ①~⑧ 최종 입장

### ① 상세 연락 입구 — 가림 면적 계산

가정 : 헤더 57(56 + 선 1) · 붙는 줄은 SCR-02 제출 줄과 같은 틀(선 1 + 위 12 + 버튼 44 + 아래 `max(12, 안전 영역)`) = **69**, 홈 막대 안전 영역 34가 있는 기기는 **91**. 글자 200%는 rem 값이 두 배다(헤더 3.5rem → 112, 버튼 2.75rem → 88).

| 화면 | 붙는 것 합 | 보이는 높이 대비 | 게이트 `min-height: 40rem` |
|---|---|---|---|
| 320×568 | 57 + 69 = 126 | **22.2%** | 꺼짐(35.5rem) |
| 375×667 | 57 + 69 = 126 | **18.9%** | 켜짐(41.7rem) |
| 390×844(홈 막대) | 57 + 91 = 148 | **17.5%** | 켜짐 |
| 390 · 브라우저 도구 막대 펼침(보이는 높이 약 660, 추정) | 126 | **약 19%** | 켜짐 |
| 데스크톱 1440×900 · 200% 확대 → 720×450 | 57 + 69 = 126 | **28.0%** — 720은 48rem 미만이라 휴대폰 배치가 되어 줄이 **생긴다** | 꺼짐(28.1rem) |
| 390×844 · 브라우저 기본 글자 200% | 112 + 147 = 259 | **30.7%** | 꺼짐(26.4rem) |
| 375×667 · 글자 200% | 112 + 137 = 249 | **37.3%** | 꺼짐 |
| 흐름 안 입구(모든 경우) | 0 | 0% | — |

미디어 쿼리의 rem은 페이지가 아니라 브라우저 기본 글자 크기를 따르므로 **데스크톱 확대 · 기본 글자 키움에서는 줄이 저절로 꺼진다.** 휴대폰 시스템 글자 크기가 웹 기본값으로 넘어오는지는 기기마다 달라 실기기 확인이 필요하다. 손가락으로 벌려 확대(핀치)하는 사람에게는 게이트가 듣지 않는다 — 그래서 흐름 안 입구가 늘 따로 있어야 한다.

| | 내용 |
|---|---|
| 내 입장 | 둘 다 두되 **동시에 보이지 않게.** ⓐ 모든 폭 : 흐름 안 입구를 **배지 줄 오른쪽**(지금 (i) 자리 — UI-8이 (i)를 배지 바로 뒤로 옮기면 비는 자리)에 `댓글 45개 · 연락하기`(아이콘 + 글자, 채움 없음). 제목 아래라 390 · 320 · 200% 확대 어디서나 첫 화면에 든다(y≈210). ⓑ 휴대폰 + 높이 40rem 이상 : 하단 고정 줄 [댓글 남기기 · 45]는 **ⓐ가 화면 위로 나간 뒤에만** 나타나고 입력칸(또는 로그인 권유 칸)이 들어오면 숨는다 |
| 양보 | "떠 있는 막대 금지"를 접는다. 667 · 844에서 17~19%는 입력 화면(SCR-02)과 같은 무게이고, ①이 긴 본문 · 45개 댓글을 읽는 내내 입구가 따라와야 한다는 피츠 논거가 맞다. 메타 줄 자리 안은 철회(첫 화면 밖) |
| 지키는 것 | 568 · 200% 확대 · 글자 200%에서는 줄 없음(가림 0, 흐름 입구만) · 입력칸은 붙이지 않음(키보드) · 줄은 스크롤 방향이 아니라 위치 기준으로만 나타남 · 줄이 있는 동안 `html:has()`로 `scroll-padding-bottom`을 줄 높이만큼(키보드로 댓글의 [수정][삭제]를 돌 때 줄 밑에 가리지 않게 — WCAG 2.4.11, `ui-ux-pro-max` focus-not-obscured) · 짧은 알림(`Flash.module.css:9`, 아래 24px 고정)은 줄 위로 · 이동은 즉시(RV2-14) |
| 로그인 뒤 복귀 | 된다 — `safeRedirectPath`가 조각(`#`)을 남긴다(`authRedirect.ts:29`). 다만 `ScrollMemory.tsx:86`(새 화면은 맨 위)과 `RouteFocus`(h1 포커스)가 조각을 무시하므로 "조각이 있으면 그 대상으로" 예외가 필요하다(M). 포커스는 **입력칸이 아니라 댓글 제목**으로 — 스크립트로 입력칸에 포커스하면 일부 휴대폰에서 누르지도 않았는데 키보드가 올라와 화면 절반을 덮는다(web-design-guidelines "autoFocus는 데스크톱 · 꼭 필요할 때만"). 쓰던 댓글 복원(`commentDraft`)은 그대로 |
| 타협안 한 줄 | **흐름 입구는 늘, 붙는 줄은 넉넉한 화면에서만, 둘이 같이 보이는 순간은 없다** |

| | 내용 |
|---|---|
| 읽는 법 | 적색 · 녹색 계열 색각 이상에게 오류 빨강은 **진한 올리브 · 황토로 보이고 칸 이름과 밝기 차가 1.7:1 남짓**이다 — 사실상 "조금 다른 진한 글자"다. 색은 그들에게 거의 일하지 않는다. 그들을 지키는 것은 `!` 아이콘 · 칸 바로 아래 자리 · **오류 동안 도움말 숨김(UI-1 b)**이다. 정상 시각(다수)에게는 빨강이 가장 빠른 신호다. 해는 없고 이득만 있다 |
| 내 입장 | **양보.** 오류 글자 · 틀린 칸 테두리에 빨강을 허용한다. 규칙 문장을 "빨강 = 삭제 전용" → **"빨강 = 멈춰서 볼 것(삭제 · 오류). 빨강 채움은 되돌릴 수 없는 확인 버튼만"**으로 고친다 |
| 조건 | (b) 도움말 숨김은 색과 무관하게 필수 · `!` 아이콘 유지 · 테두리 2px(비텍스트 3:1 — 밝게 7.4 · 어둡게 8.1로 통과) · 포커스 링은 잉크(`--focus-ring`, 빨강과 겹쳐도 갈린다) · 수정 화면(SCR-04)은 [사진 전부 삭제](빨강 글자 버튼)와 오류 문장이 한 화면에 설 수 있다 — 버튼은 휴지통 아이콘 · 버튼 모양, 오류는 `!` + 문장으로 모양을 가른다 · `--error-text`는 별칭 토큰으로 따로(나중에 값만 바꿀 수 있게) |
| ✓ vs 채운 점 | **단일 선택 = 채운 점(라디오 모양), 다중 선택 = 네모 ✓(체크박스 모양), 동그라미 ✓ = 완료 상태 아이콘.** 지금 필터는 실제로 라디오라(`PostFilterFields.tsx:157`) 관례와 맞고, 상태 '완료' 칸을 골랐을 때 ✓가 두 뜻으로 겹치지 않는다. 그림 칸(종류 · 화면 모드)의 모서리 ✓는 그대로(이미 익숙하고, 바꾸면 흔들린다) |

## 부록 · 5법칙별 이번 발견

- **힉스** : 필터는 누른 묶음만(③ 양보) · 기본값을 글자로 보이기(⑧ `상태 : 진행 중`) · 상태 다섯 선택은 단일 선택이라 결정이 한 번 · 결과 고지 · 개인정보 줄은 줄이지 않음(유지)
- **피츠** : 첫 화면 연락 입구(①) · 엄지 자리 글쓰기(②) · 위험 동작 16px(통일) · AR-4로 [삭제]와 다이얼로그 [삭제하기]가 겹치지 않게 됨 · **가림도 피츠의 비용**이다 — 붙는 것은 `min-height: 40rem`에서만 · [더 보기] 때 카드가 손 밑에서 움직이는 일(⑥)
- **제이콥** : 빨간 오류(⑤ 양보) · 단일 = 점 · 다중 = 네모 ✓ · 앵커 이동은 즉시 · 헤더 버튼 자리는 모든 화면에서 같게(헤더 [+] 유지) · 같은 오류에는 한 말투
- **근접성** : 연락 입구를 제목 · 배지 옆에 · (i)를 대상 뒤에 · 검색 0건의 회복 동작을 빈 상태 안에 · [로그아웃]은 비밀번호 칸과 떼기
- **폰 레스토프** : 시트 안 잉크 채움 하나(UI-2 부분 반대) · `:visited`로 중요한 글을 흐리게 하지 않기 · '완료'만 보기에서는 흑백을 끔 · 색각 이상에게는 색이 아니라 `!` · 자리 · 도움말 숨김이 강조를 맡는다
