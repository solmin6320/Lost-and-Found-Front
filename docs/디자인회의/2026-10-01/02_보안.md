## 한 줄 결론

다른 네 담당의 편의 제안은 **거의 전부 안전 조건만 붙이면 받을 수 있다**. 반대는 하나(UI-5 · AR-7 [삭제] 오른쪽 끝)뿐이다.
대신 확정된 SE-3의 판정 시점("칸을 벗어날 때")이 **댓글에서는 거의 늘 제출과 동시**라 경고가 늦게 뜬다 — 구현 세부를 바꿔야 한다(C-4).
⑦ 본문 URL 자동 링크는 **조건부로 보류를 푼다**(조건 7 + 3). 사용자가 아홉 줄 주소를 손으로 복사하는 지금이 호스트를 또렷이 보여 주는 링크보다 안전하지도 않다.

### B-⑦ 본문 · 댓글 URL 자동 링크 — 최종 입장

**조건부 채택 — 보류를 푼다.** 이유 : 지금은 공공 분실물 사이트 주소가 글자로 9줄이고(`scr03_detail_other-poster_390_light`), 사람들은 그 글자를 길게 눌러 복사해 **어차피 연다**.
글자로 둘 때 사용자는 호스트를 스스로 찾아 읽어야 하고, 링크로 바꾸면서 **호스트를 따로 또렷이** 보여 주면 닮은 주소를 알아볼 기회가 오히려 커진다. 위험(피싱 주소에 우리 신뢰를 얹기)은 아래 조건으로 줄이고, 남는 위험은 "누르기 전에 어디로 가는지 보인다"로 받는다. 사용자 먼저 원칙상 계속 보류할 근거가 약하다.

지킬 것 — 1차 조건 7개(정규화 뒤 `http:` · `https:`만, 계정 정보 주소 제외 · 보이는 글자 = 실제 주소 · 호스트 따로 표시 · 퓨니코드 호스트는 링크 안 함 · `target="_blank" rel="noopener noreferrer nofollow ugc"` · "우리 서비스 밖 주소" 표시 · 끝 구두점 · 괄호 처리 · 단위 테스트)에 **셋을 더한다**.

8. **SE-8 접기와 합칠 때 호스트는 접지 않는다** — 접는 것은 경로 뒷부분만(`www.example.go.kr/…/notice?id=…` 꼴). 조건 2 "보이는 글자 = 실제 주소"는 "호스트는 전부 보이고 경로는 앞부분이 보인다"로 적는다
9. **React 요소로만 만든다** — 본문 문자열을 쪼개 `<a>` · 글자 조각 배열을 돌려준다. HTML 문자열 · `innerHTML` 금지라 Trusted Types(`trusted-types 'none'`)를 바꿀 필요가 없다. `href`는 `new URL(...).href`(정규화한 값)
10. **`tel:` · `mailto:`는 만들지 않는다**(조건 6 유지), 한 글 · 한 댓글에 링크 5개까지(나머지는 글자), 우리 출처 주소도 같은 규칙(새 창 · 같은 표시) — 앱 안 이동으로 바꾸는 분기를 만들지 않는다(같은 출처 판정 실수 = F1 같은 우회)

### C-2 SE-1 구현 세부 — "열린 뒤 0.5초 안의 포인터 누름 무시"

- **자리** : `shared/ui/ConfirmDialog.tsx`의 확인 버튼 하나에 넣으면 글 삭제 · 완료 · 작성 취소 · SE-5 로그아웃 확인이 모두 받는다. 댓글 인라인 확인([삭제하기])은 다른 자리에 뜨지만 같은 훅(`useArmAfterOpen(500)`)을 붙인다 — 비용이 같고 규칙이 하나가 된다. 온보딩 테 실행(A18) · 붙는 댓글 줄(A2)도 같은 훅
- **시계** : `showModal()` 바로 뒤에 `openedAt = performance.now()`. 다시 열 때마다 새로 잰다. 요청 실패로 창이 열린 채 남은 경우는 다시 재지 않는다(열린 지 오래다)
- **판정 이벤트** : 확인 버튼의 `onPointerDown`에서 `pressStartedAt = performance.now()`를 적고, `onClick`에서 가른다
  1. `event.detail === 0` → **키보드 · 보조기기가 만든 click** → 바로 실행(Enter · Space). [취소]는 판정하지 않는다(늘 바로)
  2. 이 버튼에서 받은 `pointerdown`이 있고 `pressStartedAt - openedAt < 500` → **무시**. 누름의 **시작 시각**으로 가르는 이유 — 0.3초에 닿아 0.7초에 뗀 탭도 두 번 누름의 둘째 탭이다
  3. `pointerdown` 기록이 없는데 `detail > 0`(일부 보조기기) → `performance.now() - openedAt < 500`이면 무시
  4. 무시는 **아무 표시 없이**(모양 · `aria-disabled` 바꾸지 않음 — 03 결정). `dblclick`을 따로 다루지 않는다
- **바깥 누름 닫기도 같은 0.5초** : 지금은 두 번 누름의 둘째 탭이 바깥(backdrop)에 떨어지면 창이 열리자마자 닫혀 "안 눌리네?"로 다시 누르게 된다(D SE2-6)
- **시험**(가짜 시계) : 열자마자 포인터 누름 → `onConfirm` 0회 · 0.6초 뒤 → 1회 · 0.4초에 누르기 시작해 0.7초에 뗌 → 0회 · 0초에 Enter(`detail 0`) → 1회 · 0초에 [취소] → 닫힘 · 닫고 다시 열면 다시 0.5초 · 요청 중(`pending`)은 지금처럼 무시 · 0.2초 바깥 누름 → 닫히지 않음

### C-3 SE-3 구현 세부 — 감지 패턴 · 오탐 시험

**어디서** : 글 등록 · 수정의 **제목 · 장소 · 설명**, 댓글 쓰기 · **댓글 수정** 칸(D SE2-2). **기기 안에서만**, 서버 · 로그로 보내지 않는다. 남이 쓴 글을 그릴 때는 감지하지 않는다(가리기는 서버 몫).

**전처리** : NFKC(전각 숫자 `０１０` → `010`) → URL 구간 제거(C-12) → 판정. 띄어쓰기로 쪼갠 숫자 · 한글 숫자("공일공")는 노리지 않는다 — 정직한 사용자를 돕는 장치이지 걸러 내는 방어선이 아니다(우회는 늘 된다).

| 종류 | 패턴(개념) | 문장(하나만, 위가 우선) |
|---|---|---|
| 주민등록번호 | `(?<!\d)\d{2}(0[1-9]\|1[0-2])(0[1-9]\|[12]\d\|3[01])[-\s]?[1-8]\d{6}(?!\d)` — 생년월일이 맞는 날짜일 때만, 뒷자리가 숫자 일곱 개일 때만(`1******` 가린 값은 통과) | `주민등록번호 같은 숫자가 있어요. 올리면 누구나 봐요.` |
| 카드 번호 | 숫자 16개(4-4-4-4 구분 또는 붙여 씀) **+ 룬 검사 통과**, 15개(4-6-5) | `카드 번호 같은 숫자가 있어요. 올리면 누구나 봐요.` |
| 휴대전화 | `(?<!\d)(?:\+?82[-.\s]?1\|01)[016789][-.\s]?\d{3,4}[-.\s]?\d{4}(?!\d)` | `전화번호가 들어 있어요. 올리면 누구나 봐요.` |
| 지역번호 | `(?<!\d)0(?:2\|[3-6][1-5])[-.\s]?\d{3,4}[-.\s]?\d{4}(?!\d)` | 같음 |
| 대표번호 | `(?<!\d)1[568]\d{2}[-.\s]\d{4}(?!\d)` — **구분 문자가 있을 때만**, 뒤에 `원 · 명 · 개 · 년 · 번 · m`이 붙으면 제외 | 같음 |

**걸리면 안 되는 것(오탐 시험 — 필수)**

- 날짜 · 시각 : `2026-09-24` · `2026.09.24` · `20260924` · `09-24` · `9/24 14:30` · `09:00-18:00` · `월~금 9시부터 6시까지`
- 버스 · 노선 : `7016번` · `N62` · `6411` · `M7731` · `간선 470` · `9401번 버스` · `2호선 222번 출구`
- 금액 : `50,000원` · `100000원` · `1,000,000` · `사례금 30만 원` · `1500-2000원`
- 기간 · 수량 : `1990-2020` · `1600-1700년대` · `1800-2000명`
- 그 밖 : 우편번호 `06236` · 학번 `20231234` · 운송장 `123456789012`(12자리) · 16자리지만 룬 실패 `1234 5678 1234 5678` · 가린 번호 `010-****-1234` · `900101-1******` · 주소 안 숫자 `https://…/0212345678`

**걸려야 하는 것** : `010-1234-5678` · `01012345678` · `010 1234 5678` · `010.1234.5678` · `+82 10-1234-5678` · `０１０-１２３４-５６７８` · `02-123-4567` · `031-1234-5678` · `1588-1234` · `900101-1234567` · `9001011234567` · 룬 통과 16자리(시험용 공개 번호) · 같은 칸에 전화 + 주민 → 주민 문장 하나

**표시** : 칸 바로 아래 한 줄(C-5 자리), 폼 `.privacy` 무게(C-1), `aria-live="polite"`는 **처음 뜰 때만** 읽힌다(같은 문장을 되풀이해 읽지 않는다). 판정 시점은 C-4.

## D — 새로 찾은 모순 · 누락

- **SE2-1 (SE-3 시점)** "칸을 벗어날 때 판정"은 댓글에서 사실상 제출과 동시다 → 경고가 공개 뒤에 뜬다. C-4로 바꾼다(PM 확인)
- **SE2-2 (SE-3 범위 누락)** 03 결정은 설명 칸 · 댓글 칸만 말한다. ⓐ **제목**은 목록 카드로 가장 널리 퍼지는 칸인데 빠졌다 ⓑ 장소 칸 ⓒ **댓글 수정 칸에는 지금 개인정보 안내가 하나도 없다**(`CommentItem.tsx:143` `CommentField`에 `hint` 없음) — 상시 문장을 지우면 쓰기 · 수정 모두 감지가 유일한 신호다 ⓓ 수정 화면 · 되살린 초안(이어서 쓰기)도 같은 판정
- **SE2-3 (콘텐츠 위조 통로 하나 더)** `?keyword=`를 제목 문장에 넣는 UI-10(a)는 SE-7이 막은 것과 같은 길이다(A15)
- **SE2-4 (API-3 + RouteFocus)** 캐시 머리의 `h1`이 먼저 그려지면 `RouteFocus`가 거기에 포커스를 주고, 진짜 응답이 오면 `PostDetailSkeleton` → `PostDetail`로 **요소가 바뀌어 포커스가 body로 빠진다.** 머리를 두 상태가 함께 쓰는 한 요소로 두거나, 캐시 머리의 제목은 `RouteFocus`가 기다리는 대상에서 뺀다(`data-pending`). 탭 제목도 진짜 응답 뒤에만(A11 ④)
- **SE2-5 (320 측정 누락)** 1차 측정은 390 · 1440뿐이다. 320은 다이얼로그 버튼 두 칸이 좁아져(확인 버튼 왼쪽 x가 390보다 왼쪽) **지금 배치에서도 [삭제]가 [삭제하기]에 걸칠 수 있다**(추정 — 재야 함). RV-3 16px는 [삭제]를 오른쪽으로 더 민다. SE-1이 실제 방어선이고, 간격 값은 320 측정으로 정한다(C-2)
- **SE2-6 (다이얼로그 바깥 누름)** 두 번 누름의 둘째 탭이 바깥에 떨어지면 창이 열리자마자 닫힌다(`ConfirmDialog.handleClick`). 위험은 아니지만 "안 눌리네?" → 다시 누름 → 이번엔 확인까지. 바깥 닫기도 0.5초 보호(C-2)
- **SE2-7 (복귀 길이 둘)** 로그인 뒤 컴포저로 데려가는 길이 이미 있다(세션 만료 → `CommentDraftOffer` 스크롤 · 포커스). `#comment`(A4)를 더하면 둘이 겹친다 — 우선순위 "쓰던 댓글 제안 > `#comment`"를 정하고, `here`(`pathname + search`, 조각 없음)에 조각을 붙이는 곳은 **[로그인하고 댓글 남기기] 링크 하나**로 한정
- **SE2-8 (공용 기기 잔여 위험 문서화)** `:visited`(API-6) · 검색칸 자동완성을 풀 경우(API 1-A "최근 검색어" 가장 싼 방법)는 **로그아웃으로 지워지지 않는다.** 보안명세서 3장 "브라우저 저장소" 표 밖의 일이라 지금 문서에 자리가 없다 — "브라우저가 기억하는 것(우리가 지우지 못함)" 줄을 더한다. 자동완성은 검색칸에서 계속 끈다(`autoComplete="off"` 유지)가 보안 쪽 권고
- **SE2-9 (`?page=` 뜻 바뀜)** API-2로 `page`가 "펼친 쪽 수"가 되면 옛 공유 링크 · 남이 만든 큰 값이 `size` 곱셈으로 서버 한도(100)를 넘는다 → 상한 4로 자르기(A8). 보안명세서 2장 표 "쪽 번호" 줄도 같이 고친다
- **SE2-10 (SE-5 · 다른 탭 로그아웃)** SE-5는 **이 탭에서 누른 로그아웃**만 지킨다. 다른 탭에서 로그아웃하면(`authChannel` `{type:'logout'}`) 받은 탭은 쓰던 글 보관까지 지우고 로그인 화면으로 가 **글자가 확인 없이 사라진다** — SE-5가 막으려던 바로 그 손실이다. 제안 : 받은 탭에 쓰던 글자가 있으면 바로 떠나지 않고 그 자리에 한 줄 `다른 창에서 로그아웃했어요. 쓰던 글은 이 기기에 남기지 않아요.` + [로그인] — 글자는 화면에만(읽기 전용), 저장소에 넣지 않는다. 또 SE-5의 "쓰던 글자가 있나"를 헤더가 알려면 폼 · 댓글 · 댓글 수정이 알리는 **메모리 등록소**가 필요하다(`useLeaveGuard`와 같은 자리, 새 저장소 키 없음). 설정의 비밀번호 칸은 대상에서 뺀다(비밀번호를 기억시키는 쪽으로 흐르지 않게)
- **SE2-11 (로그인 문장과 칸 붙이기)** 서버 오류를 칸에 붙이는 `fieldOfMessage`가 **문장 머리말 글자**로 가른다(`validation.ts:56-60`). 해요체 · 서버 문구 변경이 생기면 조용히 폼 위 한 줄로 떨어진다. 안전 문제는 아니나 RV-7과 묶어 백엔드에 "오류 응답에 필드 이름"을 보고 목록으로(보고만)
- **SE2-12 (자동 링크 + 감지 · 접기 교차)** ⑦을 채택하면 C-11 · C-12 두 규칙이 함께 들어가야 한다 — 따로 구현하면 접힌 링크가 호스트를 숨기거나, 주소 안 숫자에 "전화번호가 있어요"가 뜬다
