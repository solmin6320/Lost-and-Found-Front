# 개발 단계

한 번에 다 만들지 않는다. **한 단계 = 그 화면에 필요한 기반 + 화면 1개 정도.**

## 단계마다 지키는 것

- 각 커밋이 단독으로 `npm run build` · `npm run typecheck` · `npm run lint` 를 통과한다
- 화면은 **320 / 375 / 768 / 1440** 에서 실제로 렌더링해 본다
- `docs/디자인품질기준.md` 0장 체크리스트가 "끝났다"의 정의다
- 단계 끝에 `front-review` 검수 → 치명·경고를 고친 뒤 다음 단계로
- 커밋은 **완결된 기능 묶음**(에이전트 1회당 2~3개 — 예: 코드 묶음 하나 + 문서 하나), 푸시는 **작업 끝에 한 번** (2026-09-25 변경)

## 단계 0 — 환경설정 ✅

Vite + React + TypeScript, 라우팅 9개 자리표시자, 디자인 토큰, TanStack Query.

## 단계 1 — 인증 기반 + 목록 화면(SCR-01) ✅ 재설계 완료 · 본인 확인 대기

모든 화면이 기대는 기반을 먼저 만들고, 그 위에 첫 화면을 올린다.

| | 내용 |
|---|---|
| API 레이어 | HTTP 클라이언트(`credentials: 'include'`, 오류에 `status`·`code`), 백엔드 DTO → TS 타입, 게시글 목록 API |
| 인증 | 액세스 토큰 **메모리** 저장, 401 재발급 **단일 비행**, 앱 시작 시 재발급 시도, 인증 Context(Context + useReducer) |
| 공통 UI | 유형·상태 배지, 버튼, 스켈레톤, 빈 상태, 오류 상태, 시트(좁은 화면 바텀 시트 · 넓은 화면 다이얼로그) |
| 레이아웃 | 헤더 — 로고 · 글 올리기 · 로그인/내 정보 |
| SCR-01 | 의도 선택(잃어버렸어요 · 주웠어요), 검색, 필터 칩 + 시트(카테고리·상태·장소·기간), 사진 피드, 페이지, 의도별 다음 행동, 네 가지 상태 |

**만들지 않는 것** : 로그인 화면(헤더의 로그인 버튼은 `/login` 자리표시자로 간다), 온보딩.

**구현하면서 바뀐 판단** (2026-09-24, 1차)
- [더 보기] 대신 **페이지 이동**, 우하단 고정 버튼 대신 **헤더의 [+ 글 올리기]** — 재설계 뒤에도 유지

**SCR-01 재설계** (2026-09-25) — 1차 화면을 본인이 거부했다. 이유는 셋 : **딱딱하고 칙칙함 · 분실/습득 구분이 약함 · 너무 없어 보임.**
본인이 고른 방향은 **의도 우선 + 사진 피드**다. 자세한 정의는 `docs/화면정의서.md` SCR-01.

| | 1차 | 재설계 |
|---|---|---|
| 색 | 회청 잉크 + `#EDF1F4` 캔버스, 색은 유형 배지에만 | 중성 잉크 + 흰 종이, **색은 개념에 붙는다** — 분실 마리골드 `#FFBF2E` · 습득 코발트 `#2F5CE0`(9/26 `#2F5FB1`로 조정)를 면으로 크게 |
| 분실/습득 | 필터 버튼 하나 + 작은 배지 | 첫 화면 맨 위 **의도 선택** 두 칸. `잃어버렸어요` → 습득 글, `주웠어요` → 분실 글(엇갈림) |
| 필터 | 1024 이상 왼쪽 열 | 모든 폭에서 칩 한 줄 + 시트(넓은 화면은 다이얼로그). 유형은 칩 · 시트에서 뺐다 |
| 목록 | 모바일 1열 가로형, 작은 카테고리 아이콘 | 정사각 사진 피드 2 · 3 · 4열. 사진 없는 글은 **포스터**(유형 색 바탕 + 칠한 카테고리 그림) |
| 카드 메타 | 작성자 · 조회수 | 뺐다. 제목 · 장소 · 분실습득일만 |

- 로고 · 파비콘도 새 팔레트로(꼬리표 두 장이 겹친 모양)
- 백엔드 목록 썸네일(`thumbnailUrl`)은 2026-09-26 백엔드 머지 뒤 단계 2 작업에서 연결했다(아래)
- 쓰지 않게 된 `PostFilterPanel` · `ActiveFilterList` · `CategoryIcon` · `useMediaQuery`는 지웠다(`useMediaQuery`는 단계 4에서 다시 만들었다 — 넓은 화면 마우스에서만 사진을 끌어 옮기는 **동작**을 가르느라. 모양은 여전히 CSS 가 바꾼다)

**검수 반영 · 시각 체계 정리 · 설정 화면 앞당김** (2026-09-26) — `front-review` 검수에서 나온 SCR-01 구조 흠(본인 승인)을 고치고,

## 단계 2 — 로그인 · 회원가입(SCR-05, SCR-06) ✅ · 온보딩 1층 ✅

2026-09-26. 온보딩(1층 투어)은 이번에 하지 않고 자리만 남겼다. 정의는 `docs/화면정의서.md` SCR-05 · SCR-06.

| | 내용 |
|---|---|
| 목록 썸네일 | 백엔드 `PostListResponse.thumbnailUrl`(없으면 `null`)을 타입에 넣고 카드로 넘긴다. 받는 동안 옅은 면 → 다 받으면 사진이 떠오른다(투명도만). 깨지면 포스터 |
| API | `signup`(`POST /api/auth/signup`, `skipAuth`) · `useLogin` · `useSignup`(가입 → 같은 값으로 바로 로그인). 둘 다 `retry: 0` |
| 로그인 | `?redirect=` 앱 안 경로만(`app/authRedirect.ts` — `//` · `\` · 제어 문자 · 로그인/가입 자신 차단), 로그인 상태면 되돌림, 돌아갈 곳을 누르기 전에 알림(개념 색), 비밀번호 변경 뒤 안내, 401 폼 위 한 줄 → 비밀번호 칸 전체 선택, 423 잠금 안내(이메일 단위 — 이메일을 바꾸면 풀림), 400 필드 아래 |
| 회원가입 | 세 칸(이메일 · 비밀번호 8~20자 · 닉네임 n/20, 앞뒤 공백 자름), 벗어날 때 검사, 409 이메일 · 닉네임 필드 아래, 무엇이 공개되는지 도움말, 성공 → 바로 로그인 → 돌아갈 곳(목록이면 온보딩 신호 `PostListEntryState`) |
| 공통 틀 | `AuthLayout` — 휴대폰 한 줄, 태블릿은 폼 아래 글 두 갈래 안내, 넓은 화면 두 칸(왼쪽 제목 · 안내, 오른쪽 폼). 추후 OAuth(구글 · 네이버) 자리 `alternatives`(미구현, 버튼 없음) |
| 모션 | 본인 원칙 "부드럽게 이어 주는 화면" — 폼 오류 · 안내 등장(4px · 200ms), 사진 떠오름, 화면 모드 교차 전환(View Transitions). 모션 줄이기면 즉시 |

**화면정의서와 달라진 판단**
- 가입 성공 뒤 : "로그인 화면 + 안내" → **바로 로그인하고 목록(또는 돌아갈 곳)**. 방금 친 값을 다시 치게 하지 않는다
- 423 : "폼 전체를 잠금" → **그 이메일만 잠금**. 서버 잠금이 이메일 단위라 다른 계정은 로그인할 수 있어야 한다
- 401 문장 자리 : 폼 하단 → **폼 맨 위**(잠금 안내와 같은 자리)

**온보딩(2026-09-26)** — 설계와 구현 결과는 `docs/온보딩설계.md` 3 · 4 · 7장

| | 내용 |
|---|---|
| 1층 | 가입 직후 한 번 3단계(의도 선택 두 칸 → 검색 · 필터 → 헤더 `[글 올리기]`). 1단계 대상을 "첫 카드 배지"에서 **의도 선택 두 칸**으로 바꿨다(늘 그 자리 · 서비스 구조). 잉크 테로만 강조(어두운 막 없음), 좁은 화면 바텀 시트 · 넓은 화면 대상 옆 카드, 대상까지 부드럽게 스크롤, 포커스 가둠 · Esc · 연 자리로 복귀, `onboarding:v1:done` |
| 입구 | 헤더 `서비스 안내`(물음표) — 누구나 언제든. 22.5rem 미만(320)은 로고 글자를 접고, 360은 글자를 줄여 살린다 |
| 2층 | 결과 제목 줄 `이름표 안내`(누르면 펼침, `shared/ui/Toggletip`) · 필터 시트 상태 도움말 한 줄. 빈 상태 · 의도 칸 한 줄은 단계 1에 이미 있다 |

**남은 것** : 세션 만료 때 `/login?redirect=` + "로그인이 만료됐습니다" 로 보내는 동작(지금은 조용히 비로그인 — 표시 자리만 있다)

|---|---|

| 댓글 | 오래된 순 · `(수정됨)` · `글쓴이` 표시 · [더 보기 n개](받으면 새 첫 댓글로 포커스) · 방금 쓴 댓글은 [더 보기] 아래에 바로 · 300자 카운터 · 공개 안내 한 줄 · 제출 중 잠금 · 인라인 수정 · 인라인 두 번 확인 삭제 · 비로그인은 로그인 권유(돌아옴) |

| 앱 | `ScrollMemory` — 새 화면은 맨 위, 뒤로가기는 떠난 위치(목록 스크롤 유지). 목록 카드는 `fromList`를 실어 상세 [목록으로]가 뒤로 간다. 헤더 `서비스 안내`가 상세에서는 이름표 안내를 연다(`usePageGuide`) |

**화면정의서와 달라진 판단**
- 장소 · 분실습득일 · 종류를 메타에서 떼어 **본문 앞 핵심 정보**로 — "내 물건인가"를 먼저 가린다
- 완료를 스위치의 세 번째 칸이 아니라 **떨어진 버튼**으로 — 모양으로 "오가는 것"과 "마지막"을 가른다
- 없는 글 문장은 프론트 빈 상태 문구 — 잘못된 주소는 요청을 보내지 않아 서버 문장이 없다
- 요청 중 잠금은 `disabled` 대신 `aria-disabled` — 누르던 버튼에서 포커스가 빠지지 않게(다이얼로그 · 스위치 · 댓글 버튼 전부)
