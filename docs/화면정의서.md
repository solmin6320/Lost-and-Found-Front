## 0. 제품 전제

사용자는 **물건을 잃어버린 직후** 또는 **길에서 뭔가를 주운 직후**에 이 서비스를 연다.
차분히 둘러보는 서비스가 아니다. 모든 화면 결정은 이 전제에서 나온다.

- 모바일 우선(375px 기준). 데스크톱은 넓어진 모바일로 취급한다
- 목록에서 "내 물건인가"를 **1초 안에** 판단할 수 있어야 한다
- 글을 쓰는 사람은 한 손으로, 불안한 상태로 입력한다. 필수 입력을 늘리지 않는다

## 1. 전 화면 공통 규칙

### 1.1 표기 규약

서버는 Enum 문자열을 준다. 화면에는 항상 한글을 쓴다.

| 필드 | 값 → 표기 |
|---|---|
| `type` | `LOST` → **분실** · `FOUND` → **습득** |
| `status` | `OPEN` → **게시중** · `IN_PROGRESS` → **연락중** · `DONE` → **완료** |
| `category` | `WALLET` 지갑 · `ELECTRONICS` 전자기기 · `CARD` 카드 · `CLOTHES` 의류 · `ETC` 기타 |

날짜는 `lostFoundDate`(분실·습득일)와 `createdAt`(등록일)을 **반드시 구분해 라벨을 붙인다.**
둘 다 "날짜"로 쓰면 사용자가 어느 쪽 기준인지 알 수 없다. 목록 필터의 기간은 `lostFoundDate` 기준이다.

### 1.2 색과 배지

**색은 개념에 붙는다**(2026-09-25 재설계). 이 서비스에는 두 갈래뿐이다 — 잃어버림과 주움.

| 개념 | 색 | 쓰는 곳 |
|---|---|---|
| 잃어버림 | **마리골드** — 배지 · 버튼 면 `#FFBF2E` + 글자 `#3D2600`(8.6:1) · 넓은 면(의도 선택) `#F5BE3D`(8.4:1) · 흰 바탕 위 글자 `#8A5A00`(5.9:1) | LOST 글의 배지 · 포스터, `물건을 잃어버렸어요`, 분실 글 올리기 |
| 주움 | **코발트** — 면 `#2F5FB1` + 흰 글자(6.2:1) · 흰 바탕 위 글자 `#204488`(9.4:1) | FOUND 글의 배지 · 포스터, `물건을 주웠어요`, 습득 글 올리기 |

> **2026-09-26 조정** — 코발트 `#2F5CE0` → `#2F5FB1` : 원래 값은 Tailwind 기본 파랑 `#2563EB`와 ΔE 3.6으로 사실상 같았다(AI 기본값처럼 보인다).
> "보관소 · 안내 창구의 믿음직한 파랑"으로 채도를 낮췄다(ΔE 31.8). 마리골드는 **넓은 면만** `#F5BE3D`로 낮췄다 — 채도 100% 노랑을 큰 면으로 오래 보면 지친다.
> 배지 · 버튼은 사진 위에서도 튀어야 해서 `#FFBF2E` 그대로다. 전후 비교 스크린샷을 남겼고, 원래 색으로 되돌릴 수 있다.
> **어둡게**에서는 넓은 면이 `#CF9E3E`(글자 7.2:1) · `#3765B8`(글자 5.3:1)로 한 단계 가라앉는다. 값은 `tokens.css` 2장

- ⛔ **"색을 쓰는 곳은 유형 배지뿐" 규칙은 폐기했다.** 회청 잉크와 회색 캔버스뿐인 화면이 칙칙하고 초라해 보인 원인이었다.
  두 색은 배지뿐 아니라 **면**(의도 선택, 사진 없는 글의 포스터, 등록 권유)으로 크게 쓴다
- 색은 보여주는 글이 아니라 **사용자가 한 일**을 따른다. `잃어버렸어요`는 습득 글을 보여주지만 분실 색이다
- 두 색은 노랑 ↔ 파랑이라 적록색각이상에서도 갈라지고(적록 시뮬레이션 면 ΔE 105 이상), 명도가 0.57 대 0.12(어둡게 0.38 대 0.14)라 흑백에서도 밝은 면 / 어두운 면으로 갈린다
- 나머지(글자 · 선 · 공통 버튼)는 중성 잉크와 흰 종이로 조용히 둔다. 값과 대비는 `src/shared/styles/tokens.css` 머리 주석에 있다

배지는 두 축을 **색으로 섞지 않는다.** 유형과 상태는 다른 정보다.

| 축 | 표현 |
|---|---|
| 유형 (분실/습득) | **채운 배지.** 위 두 색의 면 + 글자 |
| 상태 (게시중/연락중/완료) | **외곽선 배지 + 아이콘.** 색을 쓰지 않는다. 라벨 · 아이콘(게시중 확성기 · 연락중 말풍선 · 완료 체크) · 선 굵기로 가른다 |

- 색만으로 구분하지 않는다. **배지에는 항상 한글 라벨이 함께 있다**
- 배지 모서리는 4px — 물건에 붙이는 이름표 모양이다. 누르는 필터 칩(알약)과 모양으로 갈린다
- 사진 위에 겹칠 때(`surface="photo"`)는 배지가 불투명한 바탕과 테(`--badge-ring`)를 가진다 — 연락중은 종이색 칸, 완료는 잉크 도장(체크 아이콘 + 완료)
- 상세 제목 아래(`surface="detail"`)는 종이 위 외곽선 그대로이고 **완료만 목록과 같은 잉크 도장**이다(2026-10-03 회의 UI-11) — 같은 상태는 같은 모양. 목록에서는 끝난 글을 조용하게, 상세에서는 "이미 돌아갔다"를 분명하게
- **완료는 목록에서 눈에 덜 띈다.** 목록 카드는 사진 · 포스터를 흑백으로 낮추고 대비를 조금 줄이며(`grayscale` + `contrast(0.88)`), 글자를 한 단계 흐린다. 반투명으로 만들지 않는다 — 흰 사진이 빈 칸처럼 보이고, 제목이 4.5:1 아래로 떨어진다
- **빨강 = 멈춰서 볼 것**(2026-10-03 회의 ⑤) — 방금 틀린 것(오류 문장 · `!` 아이콘, `--error-text`)과 되돌릴 수 없는 동작(삭제). **빨간 채움은 되돌릴 수 없는 확인 버튼(`[삭제하기]`)만.** 개인정보 안내 · 경고 · 상태에는 빨강을 쓰지 않는다. 배지 · 면에 빨강이 없는 이유가 이것이다. 틀린 칸의 테두리는 빨강이 아니라 잉크 두 겹이다(1.7)

### 1.3 네 가지 상태 — 모든 화면이 전부 가진다

하나라도 빠지면 화면이 거짓말을 한다.

| 상태 | 공통 규칙 |
|---|---|
| 로딩 | 스피너가 아니라 **스켈레톤.** 실제 콘텐츠와 같은 높이·같은 자리를 차지해 레이아웃이 튀지 않는다 |
| 비어 있음 | 빈 화면은 오류처럼 보인다. **왜 비었는지 + 다음에 할 일**을 화면이 말한다 |
| 오류 | 백엔드 `ErrorResponse.message`를 **그대로** 보여준다. 프론트가 문구를 새로 짓지 않는다 |
| 권한 | 권한 없는 사용자에게 수정·삭제·상태 변경 버튼을 **보이지 않게** 한다. 비활성화가 아니라 숨김 |

> **오류 문구를 프론트가 짓지 않는 이유.** 백엔드 `ErrorCode`가 이미 한글 문장을 가지고 있다
> (`"존재하지 않는 게시글입니다"`, `"이미 사용 중인 닉네임입니다"`). 프론트가 따로 지으면
> 같은 상황에 두 개의 문장이 생기고, 백엔드가 문구를 고쳐도 화면은 안 바뀐다.
>
> 프론트가 직접 쓰는 문구는 **빈 상태 / 확인 다이얼로그 / 결과 고지(인라인) / 도움말 / 보내기 전 검사 / 연결 실패**다.
> 전부 **해요체**로 쓴다(2026-10-03 회의 ⑦). 응답 자체가 없을 때(네트워크 끊김, 타임아웃)는 한 문장 :
> `"연결하지 못했어요. 네트워크를 확인하고 다시 시도해 주세요."`(`shared/lib/http/errors.ts`)
>
> **보내기 전 검사**는 화면이 먼저 막는 문장이라 해요체다(`제목을 적어 주세요` · `댓글은 300자까지 쓸 수 있어요` · `사진은 5장까지 올릴 수 있어요` · `시작 날짜는 끝 날짜보다 늦을 수 없어요`).
> 같은 이유로 **서버가** 막으면 서버 `message`(합니다체)가 그대로 온다 — 바꾸려면 백엔드 `ErrorCode`다. 서버 문장의 첫 낱말로 칸을 가리는 규칙(`이메일` · `비밀번호` · `닉네임` …)은 그대로 두고,
> 프론트 검사 문장도 칸 이름으로 시작한다(`features/auth/model/validation.ts`).

### 1.4 오류 응답 → 화면 동작

응답 형식은 `{ "code": "POST_NOT_FOUND", "message": "존재하지 않는 게시글입니다" }` 하나로 고정이다.
**`code`로 분기하고 `message`를 보여준다.** 상태 코드만 보고 분기하면 401이 네 종류라 구분이 안 된다.

| HTTP | code | 화면 동작 |
|---|---|---|
| 401 | `INVALID_ACCESS_TOKEN` | 화면에 아무것도 띄우지 않고 `POST /api/auth/reissue`를 **1회** 시도한다. 성공하면 원래 요청을 재시도, 실패하면 1.5의 세션 만료 처리 |
| 401 | `INVALID_CREDENTIALS` | 로그인 폼 맨 위에 `message` 한 줄. 입력값은 지우지 않는다(SCR-05) |
| 401 | `REFRESH_TOKEN_MISMATCH` `INVALID_REFRESH_TOKEN` | 세션 만료 처리(1.5) |
| 403 | `FORBIDDEN_ACCESS` | 남의 글을 건드린 것이다. 상세 화면으로 되돌리고 `message`를 띄운다 |
| 404 | `POST_NOT_FOUND` `MEMBER_NOT_FOUND` | 화면 본문 전체를 빈 상태로 바꾸고 `message` + `[목록으로]` |
| 409 | `DUPLICATE_EMAIL` `DUPLICATE_NICKNAME` | **해당 입력 필드 아래**에 `message`. 상단 배너로 몰지 않는다 |
| 409 | `INVALID_STATUS_TRANSITION` | 상태 컨트롤 옆에 `message`. 상세를 다시 불러 현재 상태를 맞춘다 |
| 423 | `ACCOUNT_LOCKED` | 로그인 폼 위 잠금 안내 + 비밀번호 · 버튼 잠금. 이메일을 바꾸면 풀린다(SCR-05) |
| 400 | `INVALID_INPUT` | 필드별 인라인. 어느 필드인지 알 수 없으면 제출 버튼 위에 한 줄 |
| 400 | `PASSWORD_MISMATCH` | "현재 비밀번호" 필드 아래 인라인 |
| 400 | `INVALID_IMAGE_EXTENSION` `EXCEEDED_IMAGE_COUNT` | 업로드 영역 아래 인라인. **단, 둘 다 UI가 먼저 막으므로 여기까지 오면 안 된다** |
| 405 · 500 | `METHOD_NOT_ALLOWED` `INTERNAL_SERVER_ERROR` | `message` + `[다시 시도]` |

### 1.5 인증과 권한

| | |
|---|---|
| 액세스 토큰 | JS 메모리에만 둔다. localStorage에 쓰지 않는다. 새로고침하면 사라진다 |
| 리프레시 토큰 | httpOnly 쿠키. 프론트 코드가 읽지도 쓰지도 않는다 |
| 새로고침 복구 | 앱이 뜰 때 `POST /api/auth/reissue`를 1회 호출한다. 성공하면 로그인 상태를 되살리고, 실패(401)하면 조용히 비로그인으로 둔다. **이때는 로그인 화면으로 보내지 않는다** |
| 세션 만료 처리 | 메모리 토큰을 비우고 `/login?redirect={현재경로}` 로 이동. 로그인 화면 상단에 `"로그인이 만료됐어요. 다시 로그인해 주세요."` — **쓰던 글자가 있는 곳만** 보낸다 : 등록 · 수정 화면(SCR-02), 상세의 댓글 입력칸(SCR-03, 쓰던 글자가 있을 때), 내가 쓴 글(SCR-07, 로그인이 필요한 화면). 쓰던 글자는 보관하고 "로그인하면 쓰던 글(댓글)을 이어서 쓸 수 있어요."를 덧붙인다. 다른 화면은 조용히 비로그인이 된다 |
| 다른 창에서 로그아웃 | (2026-10-03 회의 SE2-10) 쓰던 글자가 **없으면** 만료와 같다(로그인이 필요한 화면은 로그인 화면 + `"다른 창에서 로그아웃했어요."`). 쓰던 글자가 **있으면** 화면을 떠나지 않는다 — 글 폼 · 댓글 칸 · 댓글 수정 칸을 **읽기 전용으로 남기고** 위에 `"다른 창에서 로그아웃했어요. 쓰던 글(댓글)은 이 기기에 남기지 않아요."` + `"아래 글자는 읽기만 할 수 있어요. 필요한 내용은 옮겨 두고 다시 로그인해 주세요."` + `[로그인]`. 글자는 **저장소에 넣지 않는다**(공용 기기 — 직접 로그아웃과 같은 규칙, 보안명세서 3장). 이 탭에서 고른 로그아웃(`isSelfLogout`)과는 등록부가 가른다(1.7) |

**작성자 본인 판정은 `memberId`로 한다. 닉네임으로 하지 않는다.**
닉네임은 바뀔 수 있어서(`[3.6]`) 비교가 깨진다.

- 로그인 응답(`LoginResponse`)에는 회원 식별자가 없다(`accessToken` `tokenType` `accessTokenExpires`뿐).
  로그인 성공 직후 **`GET /api/members/me`를 한 번 호출해** `id`·`nickname`을 메모리에 담는다
- `PostDetailResponse.memberId`, `CommentResponse.memberId`와 비교한다
- `PostListResponse`에는 `memberId`가 **없다**(닉네임만). 그래서 목록 카드에는 소유자 전용 동작을 두지 않는다.
  마이페이지(SCR-07)는 응답 전체가 내 글이므로 판정이 필요 없다

로그인이 필요한 화면에 비로그인으로 들어오면 `/login?redirect={원래경로}` 로 보낸다.
로그인에 성공하면 `redirect`로 되돌린다. 목록으로 떨어뜨리지 않는다.
돌아갈 곳에 붙어도 되는 조각(`#…`)은 상세의 **`#comments` 하나**다(문자열 비교, `app/authRedirect.ts`) — 상세의 로그인 권유 칸에서 로그인하면 그 글의 "댓글" 제목으로 돌아온다(SCR-03). 다른 조각은 떼고 경로만 따른다.
상세에서 로그인 · 가입으로 갈 때는 기록을 바꿔치기(replace)하고 상세의 진입 상태(`fromList` · 내가 쓴 글 탭)를 들고 다닌다 — 돌아온 상세의 `[목록으로]`가 보던 목록(필터 · 스크롤)으로 간다(API2-2). 진입 상태는 모양 검사 뒤 **새로 만든 값만** 넘긴다(`readReturnEntry`). 로그인 ↔ 가입 사이 이동도 바꿔치기라 기록에 로그인 칸이 쌓이지 않는다(API2-13).

### 1.6 결과 고지 — 누르기 전에, 한 번, 구체적으로

사용자가 누르기 **전에** 그 선택이 무엇을 바꾸는지 알아야 한다.
같은 내용을 두 번 묻지 않는다. 경고가 반복되면 사용자는 읽지 않고 누르는 법을 배운다.

| 되돌릴 수 | 형식 |
|---|---|
| 있음 | **인라인 한 줄.** 버튼·입력 바로 아래, 작고 흐리게. 진행을 막지 않는다 |
| 없음 | **확인 다이얼로그.** 결과를 문장으로 쓴다. "삭제"는 파괴적 색상, **기본 포커스는 "취소"** |

고지 대상은 여섯 가지다. 화면별 상세에 실제 문구를 적었다.

| 동작 | 알릴 것 | 형식 | 화면 |
|---|---|---|---|
| 게시글 등록 | 사진은 최대 5장 | 인라인 | SCR-02 |
| 게시글 수정 | 새 사진을 올리면 기존 사진이 **전부 교체**된다 | 인라인 | SCR-04 |
| 게시글 삭제 | 사진과 **댓글까지** 사라진다. 되돌릴 수 없다 | 다이얼로그 | SCR-03 |
| 상태 → 완료 | **되돌릴 수 없다** | 다이얼로그 | SCR-03(SCR-07 카드에서는 바꾸지 않는다) |
| 비밀번호 변경 | **이 기기 포함 모든 기기에서 로그아웃**된다 | 인라인 | SCR-08 |
| 닉네임 변경 | 기존 글·댓글의 이름이 **전부 바뀐다** | 인라인 | SCR-08 |

### 1.7 폼 공통

- 검증은 제출 시점이 아니라 **필드를 벗어날 때**. 제출 후 다섯 개가 한꺼번에 빨개지면 늦다
- 서버 검증 메시지는 **해당 필드 아래**에 붙인다. 상단 배너로 몰지 않는다
- **전송 중에는 제출·취소 버튼을 잠근다.** 사진 5장이면 몇 초 걸리고, 그 사이 중복 클릭이 들어가면 글이 두 개 만들어진다
  - 잠금은 `disabled`가 아니라 **`aria-disabled` + 누름 무시**다(2026-09-27 통일). `disabled`로 잠그면 누르던 버튼에서 포커스가 문서 맨 앞으로 빠진다. 요청 중에는 흐리지 않고 글자가 `…하는 중`으로 바뀐다
  - 지금은 할 수 없는 버튼(바꾼 게 없는 `[닉네임 저장]` · 계정이 잠긴 `[로그인]`)은 `Button`의 `unavailable` — 흐리게 그리고 누름 · 제출을 무시한다. 포커스는 남고 이유(`aria-describedby`)가 읽힌다
- 어느 칸의 문제인지 모르는 실패(연결 실패 · 서버 오류)는 **폼 한 줄**(`shared/ui/FormAlert` — 옅은 면 + 아이콘 + 굵은 글자, 빨강 없음)로 알리고 **포커스를 그 줄로 옮긴다.** 로그인 · 가입 · 글 쓰기 · 비밀번호 변경이 같은 줄을 쓴다
- 취소를 눌러도 이미 서버에 닿은 요청은 처리된다. 버튼 문구를 "취소"가 아니라 상황에 맞게 잠근 상태로 둔다
- 한 줄 칸의 Enter 는 다음 칸으로(한글 조합 중은 그대로). 입력 16px · `enterkeyhint` · 자동완성은 칸의 뜻대로(SCR-02)
- **오류 표시**(2026-10-03 회의 ⑤) — 오류는 칸 바로 아래 `!` 아이콘 + 문장, 색은 `--error-text`(밝게 `#A62018` · 어둡게 `#FF8F85`). 틀린 칸 테두리는 잉크 두 겹 그대로(빨갛게 칠하지 않는다). **오류가 떠 있는 동안 그 칸의 도움말(`hint`)은 숨긴다** — 칸 아래에는 오류 한 줄만. 결과 고지(`note` — 닉네임 · 비밀번호 변경 결과, 설명 칸 개인정보 줄)는 오류가 있어도 남는다(누르기 전에 읽혀야 한다)
- **알림은 한 번만**(UI2-9) — 칸을 벗어나며 생긴 오류 하나는 바로 읽어 준다(`role="alert"`). 제출이 막혀 여러 칸에 한꺼번에 붙을 때는 칸마다 읽지 않고, 포커스가 간 첫 칸이 `aria-describedby`로 읽는다. 글 폼은 남은 수를 제출 줄 위 한 줄이 알린다(SCR-02)
- **글자 수는 한도의 80%부터** 보인다(UI-9 c, `TextField.count.ts`) — 제목 · 장소 80 · 설명 4,000 · 닉네임 16 · 댓글 240. 그 전에는 화면에서 숨기고 스크린리더만 "최대 N자"를 읽는다. 넘치면 굵어진다
- 예시는 **입력칸 안 안내 글**(`placeholder`)로 둔다(UI-9 b). 칸 이름은 늘 위에 있다 — 안내 글을 이름 대신 쓰지 않는다

**쓰던 칸 등록부 — 이탈 확인은 하나**(2026-10-03 회의 AR2-3 · SE-5 · SE2-10, `shared/lib/dirtyRegistry.ts`)

React Router 의 `useBlocker`는 **한 번에 하나만** 동작한다. 칸마다 막는 곳을 두면 서로 덮어써 어떤 화면은 묻고 어떤 화면은 안 묻는다. 그래서

- **막는 곳은 레이아웃(`RootLayout`)에 하나**(`useDirtyLeaveGuard`)다. 앱 안 이동 중 **경로가 바뀌는 것**(로고 · 메뉴 · 뒤로가기 · 서비스 안내 등 모든 출구)과 새로고침 · 탭 닫기(`beforeunload`, 문장은 브라우저가 정한다)를 막는다. 같은 화면에서 `?` 뒤만 바뀌는 이동은 막지 않는다(쓰던 칸이 그대로다)
- **칸은 "쓰던 글자가 있다"만 알린다**(`useDirtyField`). 글자 자체는 담지 않는다 — 메모리에만 있고 저장소에 쓰지 않는다. 등록하는 칸 : 글 폼(SCR-02 · 04) · 설정의 닉네임(지금 닉네임과 다르게 고쳤을 때) · 비밀번호(두 칸 중 하나라도 글자가 있을 때) · 상세의 댓글 칸 · 댓글 수정 칸
- 막을지는 **이동하는 그 순간** 등록부를 읽어 정한다. 저장이 끝났거나 확인을 거친 이동은 `allowLeave()`로 한 번 풀고, 경로가 바뀌면 다시 막는다
- 확인 창 : 제목과 본문은 쓰던 칸 가운데 **먼저 등록한(화면 위쪽) 칸의 문장** — 글 `"쓰던 글을 두고 나갈까요?"` / `"나가면 쓰던 내용은 저장되지 않아요."` · 수정 `"고치던 글을 두고 나갈까요?"` / `"나가면 고친 내용은 저장되지 않아요. 글은 고치기 전 그대로 남아요."` · 댓글 `"쓰던 댓글을 두고 나갈까요?"` / `"나가면 쓰던 댓글은 저장되지 않아요."` · 그 밖(설정) 공통 문장. 버튼은 `[계속 쓰기]`(기본 포커스) · `[나가기]`
- 같은 등록부를 **로그아웃 확인**(1.10)과 **다른 창 로그아웃**(1.5)이 읽는다 — "어떤 화면은 묻고 어떤 화면은 안 묻는" 어긋남이 없다

### 1.8 이미지 공통

- 게시글당 **최대 5장.** 6장째를 고른 순간 UI가 막는다. 서버까지 보내고 400을 받지 않는다
- 확장자는 jpg / jpeg / png / gif만 고를 수 있게 `accept`로 제한한다
- 사진 없는 글이 많다. **자리표시는 포스터**로 만든다 — 유형 색의 연한 바탕 + 칠한 카테고리 그림(지갑 · 전자기기 · 카드 · 의류 · 기타) + 카테고리 이름. 회색 네모나 작은 아이콘 하나를 두지 않는다
- 목록 썸네일은 **1:1 고정 비율로 자른다.** 세로 사진 때문에 카드 높이가 들쭉날쭉하면 스캔이 안 된다
- `alt`는 "이미지"가 아니라 **게시글 제목**을 쓴다

### 1.9 접근성 최소선

- 모든 폼 입력에 `label`. placeholder로 대신하지 않는다
- 배지·상태를 색만으로 구분하지 않는다(1.2)
- 320 · 360 · 375 · 390 · 412 · 414 · 430 · 768px에서 가로 스크롤이 생기지 않는다(로그인 · 비로그인 모두, `scrollWidth <= clientWidth` 실측)
- 터치 대상 최소 44×44
- 포커스 링을 지우지 않는다
- 다이얼로그는 포커스를 가두고, Esc로 닫히며, 닫으면 열었던 버튼으로 포커스가 돌아온다
- **화면을 옮기면 포커스가 새 화면의 제목(`h1`)으로 간다**(2026-09-27, `app/RouteFocus`). 누른 링크가 사라져 포커스가 문서 맨 앞으로 빠지면 키보드 사용자는 헤더부터 다시 내려와야 하고, 스크린리더는 화면이 바뀐 것을 모른다
  - 경로가 바뀔 때만 옮긴다. 목록의 필터 · [더 보기]처럼 같은 화면 안의 주소 변경은 그 화면이 정한 곳으로 옮긴다(조건 → 결과 제목, [더 보기] → 새로 붙은 첫 카드)
  - `preventScroll` — 뒤로가기로 되돌린 목록 스크롤(`ScrollMemory`)을 밀지 않는다
  - **뒤로 · 앞으로(POP)는 떠날 때 누른 본문 링크로 돌아간다**(단계 6 마무리). 목록 · 내가 쓴 글 → 상세 → 뒤로 하면 누른 카드에 포커스가 있어 다음 Tab이 그다음 카드다(제목으로 보내면 스크롤은 카드 앞인데 다음 Tab에 화면이 맨 위로 튀었다).
    누른 링크의 `href`를 스크롤 위치와 같은 키(`location.key`)로 탭 메모리에 적는다. 0.6초 안에 그 링크가 없으면(지워진 글 · 다른 쪽) 제목으로 간다. 새로고침하면 잊는다
  - 화면이 먼저 포커스를 옮겼으면(이어 쓰기 묻기 · 폼 오류) 두고 본다. 제목이 불러온 뒤에 생기면 1.5초까지 기다리고, 끝내 없으면 탭 제목을 알림 영역으로 읽어 준다
- **탭 제목은 `화면 이름 | 분실물 찾기`**(`shared/lib/useDocumentTitle`) — 목록은 결과 제목(`최근 올라온 물건` · `누군가 주워 둔 물건` · `주인이 찾는 물건`), `로그인` · `회원가입` · `설정` · `내가 쓴 글` · `글 올리기` · `글 수정` · 글 제목 · `없는 글` · `없는 화면`
- 로그아웃하면 사라진 계정 메뉴 대신 그 자리의 `[로그인]`으로 포커스가 간다(헤더가 sticky 라 `preventScroll` — 그냥 옮기면 Chrome 이 스크롤을 헤더 제자리로 끌어 올린다)

### 1.10 공통 레이아웃

모든 화면이 공유한다.

```
┌──────────────────────────────────────────────┐
│ 헤더 (sticky, 56px)                            │
│  비로그인 [꼬리표] 분실물 찾기  [+ 글 올리기] [? 서비스 안내] [⚙ 설정] 로그인 │
│  로그인   [꼬리표] 분실물 찾기  [+ 글 올리기] [? 서비스 안내] [(사람) 닉네임 ▾] │
├──────────────────────────────────────────────┤
│                                              │
│  본문 (좌우 여백 16px, 640 이상 24px)            │
│                                              │
├──────────────────────────────────────────────┤
│ 푸터                                           │
└──────────────────────────────────────────────┘
```

- 본문 폭은 둘이다. **목록**은 페이지 폭(`--layout-page` 1216px)을 다 쓴다 — 1440에서 양옆이 비지 않게 피드 열을 늘린다.
  **읽는 화면**(상세 · 폼 · 설정)은 700px(`--layout-max`)로 좁힌다
- 헤더는 로고(목록으로) · `[+ 글 올리기]` · **서비스 안내(물음표)** · 그리고 로그인 상태에 따라 갈리는 끝 묶음이다. 로고는 마리골드 · 코발트 꼬리표 두 장이 겹친 모양이다.
  꼬리표 모양은 로고(와 파비콘) · '기타' 포스터 그림에만 쓴다. 다른 자리의 장식으로 되풀이하지 않는다
- 끝 묶음(2026-10-03 회의 UI-6)
  - **비로그인** : 설정(톱니) + `[로그인]`. `[로그인]`은 테두리 없는 **글자 버튼**(15px/700, 누르는 면 44px) — 선 상자는 `[+]` 하나만 남는다(UI-6 b)
  - **로그인** : 계정 메뉴 하나 — `사람 아이콘 + 닉네임 ▾`(내가 쓴 글 · 설정 · 로그아웃). **헤더 톱니는 없다** — 설정은 메뉴의 "설정" 하나로 간다(같은 목적지가 두 곳이면 헤더 목표가 넷이 된다, UI-6 c). 닉네임은 36rem 이상에서만 보인다. `[로그아웃]` 바로 아래 흐린 한 줄 `"이 기기에서는 7일 동안 로그인이 유지돼요."`(SE-9)
  - 로그인 · 가입 화면에서는 `[로그인]`을 **숨기되 자리는 남긴다**(`visibility: hidden` — 지금 그 화면이라 같은 목적지를 또 두지 않는다, 헤더가 흔들리지 않게, 포커스 · 읽기에서도 빠진다)
- **설정(톱니, Phosphor `Gear`)은 비로그인에게 보인다** — 화면 모드는 비로그인도 바꾼다. 누르면 `/settings`(SCR-08). 지금 설정 화면이면 옅은 면이 깔린다(`aria-current="page"`)
- **`[+ 글 올리기]`는 보던 의도를 싣는다**(2026-10-03 회의 ②) — 목록에서 `잃어버렸어요`를 골라 둔 동안(습득 글을 보는 중) 이름이 `분실 글 올리기`, 가는 곳이 `/posts/new?type=LOST`다(`주웠어요`면 `습득 글 올리기` · `?type=FOUND`). 결과 끝 등록 권유와 같은 이름 · 같은 유형이다. 휴대폰에서는 스크린리더 이름 · 이름표로, 넓은 화면에서는 글자로 보인다. 목록 밖에서는 `글 올리기`
  - 등록 · 수정 화면에서는 "지금 여기" 옅은 면을 깔고 넓은 화면의 잉크 채움도 거둔다(그 화면의 주 동작은 폼의 `[올리기]`다). **등록 화면에서는 `aria-current="page"`이고 눌러도 무시한다**(AR2-9) — 같은 경로라 이탈 확인을 타지 않고, 폼은 `?type`을 처음 한 번만 읽어서 누르면 주소만 바뀌고 아무 일도 없었다
  - 떠 있는 글쓰기 버튼은 두지 않는다(회의 ② — "의도 면이 보이면 숨는 버튼은 결심하는 순간에 없다"). 헤더가 늘 붙어 있어 `[+]`는 목록 어디서나 닿는다
- **서비스 안내(물음표, Phosphor `Question`)도 누구나 본다**(2026-09-26) — 온보딩 1층(`docs/온보딩설계.md` 3장)을 언제든 다시 연다. 안내는 목록 위에 뜨므로 다른 화면에서 누르면 목록으로 가면서 연다. 닫으면 이 버튼으로 포커스가 돌아온다
  - 그 화면에 자기 안내(온보딩 2층)가 있으면 목록으로 떠나지 않고 **그 안내를 연다**(2026-09-27) — 지금은 상세(SCR-03)의 `이름표 안내`, 등록 · 수정(SCR-02 · 04)의 `쓰는 요령`. 보던 글 · 쓰던 글을 잃지 않는다
  - 계정 메뉴 · 설정 화면 안에 두지 않았다 — "기능이 잘 보이게". 사용자가 직접 여는 안내가 자동 투어보다 완주율이 높다는 근거가 있어, 입구가 찾지 않아도 보여야 한다. 비로그인에게는 계정 메뉴가 없기도 하다
- 폭마다 무게가 바뀐다. **320px에서도 한 줄에 들어간다**(로그인 상태 포함). 오른쪽 묶음의 **누르는 면끼리 8px**(UI-6 a — 4px은 옆 버튼을 잘못 누른다, 모든 폭 같다). `[+]`의 보이는 칸은 36px이고 누르는 면은 양옆 4px씩 넓힌 44px이라, 오른쪽 이웃과 누르는 면끼리 8px이 되게 그만큼 더 띄운다

| 폭 | 로고 | `[글 올리기]` | 서비스 안내 · 설정 |
|---|---|---|---|
| 22.5rem(360px) 미만(320) | 꼬리표 두 장만. 글자는 링크 이름으로 남는다 | `[+]` 아이콘만. 이름은 숨긴 글자 · 이름표(툴팁) | 아이콘만. `aria-label` · 이름표 |
| 22.5rem ~ 23.43rem(360~374px) | 꼬리표 26px + 사이 4px + `분실물 찾기` 14px(한 단계 줄임) | `[+]` 아이콘만 | 아이콘만 |
| 23.44rem ~ 28rem(375 · 390 · 412 · 430) | 꼬리표 30px + `분실물 찾기` 16px | `[+]` 아이콘만 | 아이콘만 |
| 28rem ~ 48rem | 〃 | 글자 + 선만 두른 버튼 — 첫 화면의 두 색 면과 무게를 다투지 않는다 | 아이콘만 |
| 48rem 이상 | 〃 | 잉크를 채운 주 버튼 | 아이콘 + `서비스 안내` · `설정` 글자 |

> 22.5rem 미만에서 로고 글자를 접는 이유 — 오른쪽에 네 개(`[+]` 36 · 안내 44 · 설정 44 · 로그인/계정 68px)가 서면 320 폭에서 글자까지는 한 줄에 들어가지 않는다. 360(가장 흔한 안드로이드 폭)은 서비스 이름이 보이는 쪽이 사용자에게 낫다고 보고 글자를 14px로 줄여 살렸다(2026-09-27).
> 360~374px 로고 규칙(2026-10-04) — 간격을 8px로 넓히고 글자만 줄였더니 로고 링크와 `[+]`의 누르는 면 사이가 360에서 7px · 368에서 6px로 8px 규칙보다 좁았다(로고를 누르려다 `[+]`를 누른다). 글자를 13px 아래로 줄이면 이름이 흐려져서, 글자 14px은 두고 꼬리표를 26px · 사이를 4px로 줄였다. 실측(비로그인) 누르는 면 사이 360 13 · 374 27 · 375 13 · 390 28 · 412 50px, 가로 넘침 0.
> 기능 버튼을 메뉴 속에 감추는 것보다 로고 글자를 접는 쪽이 덜 잃는다. 첫 화면 제목(`잃어버렸나요, 주웠나요?`)이 무엇을 하는 곳인지 말한다.
>
> `[글 올리기]` 글자를 28rem(448px)부터 보이는 이유(2026-09-27 수정) — 글자가 서면 버튼이 64px 늘어 로고와 붙는 폭이 약 407px이다. 처음에는 24rem(384px)에서 켜 384~406px(iPhone 390 · 393)에서 헤더가 넘쳐 가로 스크롤이 생겼고, 412 · 414는 로고와 한두 글자 간격으로 붙었다. 28rem이면 로고와 41px 떨어진다. 휴대폰 폭은 전부 `[+]`(이름표로 이름이 보인다). 실측 로고 ~ 버튼 간격 : 320 54 · 360 27 · 375 33 · 390 48 · 412 70 · 430 88 · 448 41 · 768 133(로그인) / 237(비로그인)px, 모두 `scrollWidth = clientWidth`

- 이름표(툴팁)는 마우스를 올리거나 키보드로 닿았을 때 아래에 뜬다. 터치 기기에서는 띄우지 않는다(탭하면 바로 이동)
- 로그아웃 → `POST /api/auth/logout` `[3.4]`. 입구는 둘 — 계정 메뉴의 `[로그아웃]`과 설정 화면 끝의 `[로그아웃]`(SCR-08). 같은 동작이다(`app/layouts/useGuardedLogout`)
  - 되돌릴 수 있는 동작이라 평소에는 **확인 다이얼로그를 띄우지 않는다.** 단 **쓰던 글자가 있을 때만** 묻는다(2026-10-03 회의 SE-5) — 쓰던 칸 등록부(1.7)가 판정한다. `"쓰던 글을 두고 로그아웃할까요?"` / `"쓰던 글은 이 기기에 남기지 않아요."` · `[계속 쓰기]`(기본 포커스) · `[로그아웃]`. 쓰던 글은 여전히 보관하지 않는다(공용 기기)
  - 로그아웃을 고르면 등록부에 "이 창에서 고른 로그아웃"이라고 적는다 — 쓰던 칸이 다른 창 로그아웃(1.5)과 가른다. 쓰던 화면이 로그인 화면으로 옮겨질 때 이탈 확인을 다시 띄우지 않는다(방금 물었다)
  - 캐시는 **회원 것만 지운다**(2026-09-27) — 내 정보 · 내가 쓴 글 · 요청 기록(비밀번호 입력값). 공개 글 · 댓글은 두고 다시 받게만 한다. 통째로 비우면(`clear()`) 보던 상세가 스켈레톤으로 깜빡이고 스크롤이 튀었다. 세션 만료 · 비밀번호 변경도 같다(`AuthProvider`)
  - **글 상세 자체는 무효화하지 않는다**(2026-10-03 회의 API2-1) — 상세 요청은 조회수를 센다. 세션이 끊겨 다시 로그인하고 돌아온 같은 사람이 같은 글을 한 번 더 세지 않게. 상세에는 보는 사람에 따라 달라지는 값이 없다(내 글 판정은 화면이 `memberId`로 한다). 평소 1분 신선도를 따른다
- 첫 요소는 화면에 보이지 않는 `본문으로 건너뛰기` 링크다. Tab을 누르면 나타난다
- **한 화면에 붙는 것은 헤더 + 줄 하나까지**(2026-10-03 회의 총량 규칙, 디자인품질기준 8장) — 목록 = 칩 줄(SCR-01) · 상세 = 휴대폰 댓글 줄(SCR-03) · 폼 = 휴대폰 제출 줄(SCR-02). 둘째 줄은 화면 높이 `40rem` 이상에서만 붙는다. 떠 있는 버튼도 하나로 센다(그래서 두지 않는다). 짧은 알림(`Flash`)은 아래 붙은 줄 위로 비켜 뜬다(줄이 `useBottomInset`으로 `--bottom-inset`을 알린다 — 지금은 상세 댓글 줄. 폼 제출 줄은 `--form-bar-h`로 따로 재고, 폼에서는 짧은 알림이 뜨지 않는다 — 저장 뒤 상세로 옮겨 가서 뜬다)

### 1.11 화면 모드 (밝게 · 어둡게)

- 사용자가 설정 화면(SCR-08)에서 고른다. **한 번도 고르지 않았으면 기기 설정**(`prefers-color-scheme`)을 따른다
- 저장은 `localStorage` `theme:v1` = `'light' | 'dark'`. 비밀이 아니다. 저장소가 막힌 브라우저에서는 기기 설정을 따른다
- 첫 화면이 그려지기 **전에** `public/theme-init.js`가 `<html data-theme>`을 붙인다 — 깜빡이지 않는다. 인라인 스크립트는 CSP가 막아 같은 출처 파일로 둔다(보안명세서 4장)
- 다른 탭에서 바꾸면 이 탭도 따라 바뀐다(`storage` 이벤트). 기기 설정이 바뀌면 고르지 않은 사람의 화면도 바로 바뀐다
- 모든 컴포넌트는 의미 토큰만 쓴다. 어둡게의 값과 대비는 `tokens.css` 2장, 기준은 디자인품질기준 13장

```
넓은 칸(의도 칸 30rem 이상) : 의도 면 안이 한 줄 — 왼쪽 이름, 오른쪽 끝 "누가 주워 둔 물건 12건 보기". 높이 136 → 96
1024px 이상 : 검색창(44px)과 칩 줄이 한 줄에 선다(칩은 그 칸 안에서 줄을 바꾸고 줄 가운데에 맞춘다). 피드는 4열
```

**① 의도 선택 — 맨 위, 두 색 면**

분실/습득은 필터 하나가 아니라 이 서비스의 구조다. 첫 화면 맨 위에 헤드라인 `잃어버렸나요, 주웠나요?`와 큰 선택지 둘을 둔다.
헤드라인을 질문으로 둔 것은 두 선택지가 그 답이 되게 하기 위해서다.

⚠️ **사용자가 고르는 것과 보여줄 글이 엇갈린다.** 잃어버린 사람이 알고 싶은 건 "누가 주웠나"다.

| 선택지 | 색(사용자가 한 일) | 거는 조건 | 선택지 아래 한 줄 | 결과 제목 |
|---|---|---|---|---|
| (고르지 않음) | — | 없음 | — | `최근 올라온 물건` |
| `물건을 잃어버렸어요` | 마리골드 | `?type=FOUND` | `누가 주워 둔 물건 12건 보기` | `누군가 주워 둔 물건` |
| `물건을 주웠어요` | 코발트 | `?type=LOST` | `주인이 찾는 물건 13건 보기` | `주인이 찾는 물건` |

- **같은 묶음은 같은 뿌리의 말**(2026-10-03 회의 RV-9) — 습득 글은 어디서나 "주워 둔 물건"(면 둘째 줄은 칸이 좁아 `누가`, 결과 제목은 `누군가`), 분실 글은 어디서나 "주인이 찾는 물건". 같은 일을 하는 입구는 어디서나 같은 이름(`분실 글 올리기` · `습득 글 올리기` — 헤더 `[+]` · 결과 제목 아래 · 결과 끝)이다
- 두 선택지는 **링크**다(새 탭 열기 · 주소 공유). 검색어 · 필터는 그대로 두고 첫 묶음으로 간다
- 고른 쪽은 `aria-current`, 한 줄이 `… 보는 중`으로 바뀌고, 다른 쪽은 연한 면으로 물러난다(누르면 바로 갈아탄다)
- **전체로 되돌아가는 길**은 고른 선택지의 `[×]`(`선택 풀고 모든 글 보기`)다. 누르면 방금 풀린 선택지로 포커스가 돌아온다. Ctrl · Cmd · Shift로 새 탭에 열면 이 화면이 그대로라 포커스 이동을 예약하지 않는다
- 이미 고른 선택지를 **다시 누르면** 결과 제목으로 포커스를 옮긴다(더 펼쳐 둔 상태면 첫 묶음으로 가면서)
- 건수는 `GET /api/posts?type=FOUND&size=1`의 `page.totalElements`. 목록과 따로 불러와 **목록을 막지 않는다.** 불러오는 동안 숫자 자리를 비워 두고(글자가 밀리지 않는다), 실패하면 숫자 대신 `모두 보기`
- 건수는 유형 전체다. 그래서 **검색어나 필터가 걸려 있으면 선택지에서 숫자를 빼고 한 줄로 이어 쓴다**(`누가 주워 둔 물건 보기` — 두 줄로 끊으면 "보기" 한 단어가 둘째 줄에 홀로 남는다). 결과 제목 옆의 수(조건이 걸린 수)와 어긋나 헷갈린다. 수는 결과 제목 옆 한 곳에서만 말한다
- 좁은 화면에서도 **나란히 두 칸**이다. 위아래로 쌓으면 피드가 첫 화면 밖으로 밀린다. 문구는 `물건을 / 잃어버렸어요`, `누가 주워 둔 물건 / 12건 보기`처럼 두 선택지가 같은 자리에서 끊겨 줄이 맞는다. 375px 첫 화면에 첫 줄 카드의 사진 윗부분이 보인다
- **넓은 칸(의도 칸 30rem 이상, 컨테이너 쿼리)은 면 안이 한 줄**(UI-3, 👤 본인 확인 대기) — 왼쪽 이름(30px/800 그대로), 오른쪽 끝에 무엇을 보게 되는지 + 건수(16px/600). 두 줄 배치는 글자가 왼쪽 위에 몰리고 나머지가 글자 없는 채색 판이라 배너처럼 읽혔다. 높이 136 → 96 — 1440 첫 화면에 둘째 카드 줄이 들어온다. 화살표는 넣지 않는다(같은 화면 안에서 목록을 거르는 동작이다). 오른쪽 문구 두 조각은 칸이 모자라면 조각 사이에서만 접힌다. 고른 면의 `[×]`는 문구 뒤(세로 가운데, 면 끝에서 16px) — 1440에서 "12,345건 보는 중"까지 한 줄(문구 여유 51px). 휴대폰 · 200% 확대(칸이 30rem 미만)는 두 줄 그대로다. CSS 블록 하나라 되돌리기 쉽다
- 면에는 글자만 둔다. 예전의 귀퉁이 흐린 꼬리표 장식은 뺐다(2026-09-26) — 뜻 없이 로고 모양을 되풀이하는 워터마크였고, 꼬리표가 로고 · 빈 상태 · 기타 포스터와 네 곳에서 겹쳤다
- 넓은 면이라 마리골드는 한 단계 낮춘 `#F5BE3D`(1.2)를 쓴다

**② 검색 · 필터 — 검색은 크게, 필터는 칩 하나 = 묶음 하나**

- 검색창은 의도 선택 바로 아래, 옅은 면으로 채운 칸(휴대폰 52px — 엄지가 닿는 큰 칸, 64rem 이상 44px — 옆 칩 줄과 높이를 맞춘다, UI-12). Enter(휴대폰의 [검색])에서 보낸다. 보내면 **결과 제목으로 포커스를 옮긴다**(`blur()`로 버리지 않는다 — 휴대폰 키보드도 그때 내려간다). 적용된 검색어를 `[×]`로 지워도 결과 제목으로 간다. 검색창은 **위에 붙지 않는다** — 입력칸은 한 벌이다(두 벌이면 치던 글자가 갈린다)
- **왼쪽 필터 열은 없다.** 모든 폭에서 칩 한 줄(`카테고리 · 상태 · 장소 · 기간`)이고, **칩 하나가 묶음 하나만 연다**(2026-10-03 회의 ③). 칩이 무엇을 여는지가 칩 이름 그대로다

| 칩 | 여는 것 | 반영 |
|---|---|---|
| 카테고리 · 상태 | 그 묶음의 칸만 있는 메뉴(`menu` + `menuitemradio`). 맨 앞 `전체`가 지우기다. 고른 칸은 **채운 점**(하나만 고르기) | 누르면(Enter · Space · 누름) **바로 걸리고 닫힌다.** `[적용하기]` · `[초기화]`가 없다. 화살표 · Home · End는 **옮기기만** 한다 — 네이티브 라디오처럼 화살표에서 값이 바뀌면 지나가기만 해도 목록이 다시 불러와진다(WCAG 3.2.2) |
| 장소 · 기간 | 두 칸이 **한 판**(`장소 · 기간`)을 같이 쓴다. 누른 칩의 칸으로 포커스 | 글자 · 날짜를 치는 칸이라 바로 걸지 않는다. `[지우기]`는 **이 판에 보이는 칸만** 비운다(적용 전 입력값 — 카테고리 · 상태 · 검색어는 그대로, 원칙 "지우기는 보이는 것만 지운다"), `[적용하기]`에서 한 번에 건다 |

- 좁은 화면(48rem 미만)은 작은 바텀 시트(엄지 자리), **48rem 이상은 가운데 다이얼로그가 아니라 누른 칩 바로 아래 펼침 칸**이다(`impeccable` "가로막을 필요 없는 일에 모달 금지"). 넓은 화면에서 같은 칩을 다시 누르면 닫힌다. 닫기 · Esc · 바깥 누름은 아직 걸지 않은 입력을 버린다. 열 때는 고른 칸(메뉴) · 누른 칩의 칸(판)에 포커스가 서고, 반영하면 같은 묶음의 칩으로 돌아온다
- 조건 하나를 거는 데 3탭 → 2탭(카테고리 · 상태). 둘을 걸어도 4탭 그대로다
- 걸린 칩은 잉크로 채우고 값과 `[×]`를 붙인다(`카테고리: 지갑 ×`). 걸린 칩을 앞으로 모은다. 값은 12em에서 말줄임 — 전체 값은 마우스를 올리면(`title`) · 칩을 눌러 열면 보인다. 스크린리더는 잘리지 않은 이름을 읽는다. 펼친 칩은 선이 잉크로 바뀐다
- `[전체 해제]`는 **칩 줄 맨 앞**이다(글자 버튼 + 가는 세로선). 결과 제목 줄 끝에 두면 생길 때마다 그 줄이 접혀 피드가 밀렸다. 누르면 결과 제목으로 포커스
- **같은 일을 하는 버튼은 한 화면에 하나.** 조건 검색이 0건이면 빈 상태의 `[필터 초기화]`가 같은 일을 하므로 칩 줄의 `[전체 해제]`를 숨긴다
- **칩 줄은 스크롤해도 헤더 아래에 붙는다**(회의 ④ — ⑥ [더 보기]와 한 묶음) — 화면 **높이 40rem 이상 · 폭 22.5rem 이상**에서만. 헤더(57) + 칩 줄(44) = 101px가 높이의 1/6을 넘지 않는 곳이다. 짧은 화면(가로 휴대폰 · 200% 확대)과 320 폭(칩이 두 줄)에서는 붙이지 않는다 — 가리는 면이 너무 크다. [더 보기]는 결과 제목으로 올라가지 않아, 붙이지 않으면 96장 뒤 조건을 바꾸려고 ≈16,500px를 되돌아가야 한다
  - 붙어 있는 동안만 바탕과 아래 가는 선을 깐다(`IntersectionObserver` 하나 — 스크롤 이벤트 없음). 붙기 전에는 종이와 같은 색이라 아무것도 깔지 않는다
  - 결과 제목 · 카드로 포커스가 갈 때 붙은 칩 줄 밑에 숨지 않게 이 화면에서만 `scroll-padding-top`(헤더 + 칩 줄 + 16px)
- 폭마다 칩 줄 : **22.5rem 미만(320)은 줄을 바꾼다**(옆으로 넘기지 않는다 — 이 폭에서는 `기간` 칩이 화면 밖에 잘려 있었다, 붙지도 않는다) · 22.5 ~ 64rem은 화면 끝까지 밀어 옆으로 넘긴다 · **64rem 이상은 검색창 옆 칸 안에서 줄을 바꾸고 줄 가운데에 맞춘다**(UI-12). 줄이 늘면 아래로만 자란다. 칸을 자르지 않으니 첫 칩의 포커스 링도 잘리지 않는다
- **유형(분실/습득)은 칩 · 메뉴에서 뺐다.** 판단 근거
  - 같은 주소 값(`type`)을 고치는 곳이 둘이면, 한쪽을 바꾼 뒤 다른 쪽이 무엇을 말하는지 헷갈린다. 의도 선택은 늘 화면 맨 위에 보인다
  - 칩 줄이 하나 짧아져 320px에서 걸린 조건이 덜 숨는다
  - 그래서 `[전체 해제]` · `필터 초기화`도 **유형은 남긴다.** 검색어처럼 화면 위에 그대로 보이는 값이다. 유형은 `[×]`로만 푼다
- ⏳ 완료 글 기본 제외(회의 ⑧ — 상태 묶음 `진행 중` · `게시중` · `연락중` · `완료`)는 백엔드 `status` 여러 값이 머지 · 배포된 뒤에 붙인다. 그 전에는 흉내 내지 않는다

**결과 제목 줄**

- 제목 · 건수 · `이름표 안내`가 한 묶음이다. 제목은 휴대폰 18px/700(첫 화면 굵은 글자가 질문 24 > 의도 · 결과 제목 18 > 카드 16 세 단계, UI-7), 40rem 이상 한 단계 크게
- **`이름표 안내`(i)는 설명하는 대상 바로 뒤** — 건수 바로 뒤 8px에 붙는다(UI-8). **모든 폭에서 아이콘 + 글자**(`Toggletip showLabel` — 터치에서는 이름표가 뜨지 않아 아이콘만이면 무엇인지 모른다). 건수의 알림 영역 밖 형제로 둔다(건수가 바뀔 때 안내 이름까지 읽히지 않게)

**③ 사진 피드 — 카드 위계**

| 순위 | 요소 |
|---|---|
| 1 | 정사각 사진(없으면 포스터) + 제목(2줄에서 자름, 16px 굵게 · 넓은 칸 18px) |
| 2 | 사진 위 왼쪽 위 배지 — 유형(분실/습득), 그리고 연락중 · 완료. 스크린리더는 `분실, 연락중`처럼 끊어 읽는다 |
| 3 | 장소(핀 그림 + 스크린리더용 `장소`, 한 줄 말줄임) · 분실습득일(`분실일` / `습득일` 라벨) |

- 열 수는 **결과 칸의 폭**으로 정한다(컨테이너 쿼리) — 2열(320 · 375 포함) → 3열(34rem, 태블릿) → 4열(54rem, 데스크톱)
- 테두리 · 그림자가 없다. 사진의 사각형이 카드의 모양이다. 카드 전체가 제목 링크 하나(`::after`)이고, 포커스 링은 카드 전체를 두른다
- 문서 순서는 **제목 → 배지 → 장소 · 날짜 → 사진**이다. 사진은 CSS `order`로 위에, 배지는 카드 기준으로 띄워 사진 왼쪽 위에 올린다(화면 위치는 그대로)
- 사진 `alt=""` — 제목이 이미 카드의 이름이라 두 번 읽지 않는다. 첫 줄 네 장은 `loading="eager"`, 나머지는 `lazy`
- 누르면 카드 전체가 잠깐 옅어진다(전 화면 공통 눌림, 디자인품질기준 6장)
- **작성자 · 조회수는 뺐다.** "내 물건인가"를 가리는 데 쓰이지 않고, 좁은 두 칸에서 줄만 늘린다. 상세에서 본다
- **게시중은 표시하지 않는다**(기본값). 연락중은 종이색 칸 + 말풍선 아이콘, 완료는 잉크 도장 + 체크 아이콘. 색이 아니라 라벨과 모양으로 읽는다
- **완료** 카드는 사진 · 포스터를 흑백 + 대비 조금 낮춤(반투명 아님)으로, 제목 · 장소 · 날짜는 한 단계 흐린 글자(5.6:1)로 낮춘다
- 사진은 1:1로 자른다(`object-fit: cover`). 세로로 긴 사진도 카드 높이를 흔들지 않는다. 밝은 사진이 종이에 녹지 않게 아주 옅은 테를 두른다 — 테는 사진 바깥(`.media`)에 있어 완료 글의 흑백 필터를 타지 않는다. 포스터에는 두르지 않는다
- **사진 없는 글 = 포스터.** 유형 색의 연한 바탕 + 칠한 카테고리 그림(몸통 · 진한 윤곽 · 밝은 면) + 왼쪽 아래 카테고리 이름. 그림은 글마다 조금씩 다르게 기울인다. 스무 장이 전부 포스터여도 삽화 카탈로그처럼 보여야 한다
- **본문(`content`)은 카드에 싣지 않는다.** 백엔드 `PostListResponse`도 빼놨다. 5000자 × 20건이면 10만 자다
- **목록 썸네일**(`PostListResponse.thumbnailUrl`, 대표 사진 첫 장 · 없으면 `null`) — 백엔드 머지(2026-09-26) 뒤 연결했다. 있으면 사진, `null`이거나 주소가 깨지면 포스터. 사진을 받는 동안은 같은 크기의 옅은 면이 자리를 지키고, 다 받으면 제자리에서 떠오른다(투명도만 · 280ms · 캐시에 있으면 바로). 아무것도 밀리지 않는다
- 의도 · 검색 · 필터 · 펼친 수는 **URL 쿼리스트링**에 싣는다(`/?type=FOUND&keyword=지갑&page=2`). 뒤로가기 · 새로고침 · 링크 공유가 그대로 동작하고, 백엔드 파라미터 이름과 같아진다(`page`만 뜻이 다르다 — ④)
- 정렬은 등록일 내림차순 고정이다. 정렬 UI를 두지 않는다 — 서버가 `sort`를 무시한다
- 조건을 바꾸는 동안 직전 목록과 결과 수를 흐리게 남긴다(`keepPreviousData`). 결과 수는 `aria-live`로 알린다
- **누른 버튼이 사라지는 동작은 전부 결과 제목으로 포커스를 옮긴다** — 검색 보내기 · 검색어 `[×]` · `[전체 해제]` · 빈 상태의 `[필터 초기화]` · `[검색어 지우기]` · 오류의 `[다시 시도]`(응답이 온 뒤). 그냥 두면 포커스가 문서 맨 앞(body)으로 빠진다

**④ [더 보기] — 쪽 번호 대신, 모든 폭**(2026-10-03 회의 ⑥)

| | |
|---|---|
| 주소 | `?page=n`은 서버의 "몇째 쪽"이 아니라 **펼친 묶음 수**(1부터, **상한 4**). 폭과 상관없이 뜻이 하나라 공유받은 주소가 휴대폰 · 넓은 화면에서 같은 글을 보여 준다. 1은 주소에 쓰지 않는다. 예전 쪽 번호 링크(`?page=3` = 49~72번째)도 그대로 읽힌다 — 1~72번째를 펼치니 그 쪽의 글이 다 들어 있다. 상한을 넘는 값(`?page=9`)은 4로 읽는다 |
| 요청 | 한 묶음 24건(2 · 3 · 4의 공배수 — 몇 열이든 마지막 줄이 비지 않는다). **누를 때마다 처음부터 한 번에 다시 받는다**(`page=0` · `size=24×n`, 서버 최대 100 → 96건). 요청 하나 · 캐시 하나라 펼친 목록 사이에 겹침 · 빠짐이 없다 — 뒤 묶음을 따로 받아 이으면 그사이 새 글이 끼어 겹치거나 빠진다 |
| 기록 | **[더 보기]는 주소를 바꿔 쓴다(replace)** — 뒤로가기가 "덜 펼친 목록"이 아니라 이전 화면으로 간다. **조건을 바꾸면 기록을 쌓고**(뒤로가기 = 방금 고른 것 되돌리기) 첫 묶음으로 돌아간다 |
| 버튼 | 마지막 카드 줄 바로 아래 `[24건 더 보기]`(남은 수가 적으면 그 수) + `"58건 중 24건을 봤어요"`(버튼 설명). 좁은 화면은 폭 전체(엄지가 닿는 넓은 면), 넓은 화면은 가운데 20rem — 글자가 바뀌어도 폭이 그대로다. 받는 동안 `"불러오는 중…"` + 누름 무시(`aria-disabled`). 자동으로 이어 붙이지 않는다 |
| 펼친 뒤 | **이미 본 카드는 흐리게 하지 않고 제자리**에 둔다 — 그사이 맨 위에 새 글이 끼어도 보던 마지막 카드의 화면 위치를 맞춘다(그리기 전에, 차이가 없으면 0). **포커스는 새로 붙은 첫 카드**로, 알림 영역에 `"24건을 더 불러왔어요. 48 / 58"` |
| 실패 | 받아 둔 카드는 그대로 두고 버튼 자리에 서버 문장(`!` 아이콘) + `[다시 시도]` |
| 96건 너머 | 다음 묶음 대신 `"120건 중 96건을 봤어요. 여기서부터는 조건을 좁혀 보세요."` + `[필터로 좁히기]` — 칩 줄의 첫 칩으로 포커스(칩 줄이 붙어 있으면 스크롤 없이). 96장을 넘겨 내리는 사람에게 필요한 것은 다음 묶음이 아니라 더 좁은 조건이다 |
| 새로고침 · 뒤로가기 | 응답 전에 **펼친 수만큼 스켈레톤**(24×n)을 그려 문서 높이를 맞춘다 — `ScrollMemory`를 고치지 않고 보던 자리로 돌아온다 |

- 넓은 화면의 쪽 번호(`< 이전 1 / 2 다음 >`)는 없앴다. 내가 쓴 글(SCR-07)은 쪽 번호 그대로다
- 언제나 처음부터 받으므로 "끝을 넘은 쪽" 빈 상태(`"9페이지에는 글이 없어요."` · `[첫 페이지로]`)는 없어졌다

**⑤ 글쓰기 입구 — 의도를 고른 순간 · 결과 끝**(회의 ②)

떠 있는 글쓰기 버튼은 두지 않는다(1.10). 대신 흐름 안에 두 곳을 두고, 헤더 `[+]`와 같은 이름을 쓴다.

| 자리 | 언제 | 모양 |
|---|---|---|
| 결과 제목 줄 바로 아래 한 줄 | 의도를 골랐고 **확정된 건수가 5건 이상**일 때. 4건 이하 · 0건이면 숨긴다 — 두 줄 이하면 결과 끝 면이 같은 화면에 보여 같은 입구가 둘이 된다. 조건을 바꾸는 동안의 앞 목록 숫자로는 판정하지 않는다(떴다 사라지지 않게) | `주운 사람이 연락할 수 있게 [+ 분실 글 올리기]` · `주인이 찾아볼 수 있게 [+ 습득 글 올리기]`. **잉크 글자 + 밑줄 + 더하기 아이콘**(14px 글자, 누르는 높이 44px). 마리골드 글자는 흰 종이 위 1.7:1이라 개념 색 글자를 쓰지 않는다 — 뜻은 말이 싣는다 |
| 결과 끝 면 | 의도를 골랐고 **더 펼칠 수 없을 때**(끝까지 봤거나 96건 상한). 펼치는 중 · 펼치다 실패했을 때는 두지 않는다 | 아래 표. 연한 색 면 한 장 |

| 의도 | 문구 | 버튼(색) | 주소 |
|---|---|---|---|
| 잃어버렸어요 | `찾는 물건이 없나요?` / `분실 글을 올려 두면 주운 사람이 연락할 수 있어요.` | `[+ 분실 글 올리기]` 마리골드 | `/posts/new?type=LOST` |
| 주웠어요 | `주운 물건과 맞는 글이 없나요?` / `습득 글을 올려 두면 잃어버린 사람이 찾아볼 수 있어요.` | `[+ 습득 글 올리기]` 코발트 | `/posts/new?type=FOUND` |
| (고르지 않음 — 빈 결과에서만) | `찾는 물건이 없나요?` / `잃어버렸거나 주운 물건을 올려 두면 본 사람이 댓글로 알려 줘요.` | `[+ 글 올리기]` 잉크(옅은 면 위) | `/posts/new` |

- 비로그인이면 `paths.loginThenReturn`으로 로그인을 거쳐 돌아온다
- 한 자리에 면은 하나다. 빈 결과에서는 이 면이 회색 판을 대신한다(아래)

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 카드 스켈레톤을 **펼친 수만큼**(24×n — 2 · 3 · 4열 어디서든 줄이 찬다). 정사각 + 제목 2줄 + 장소 · 날짜 2줄로 실제 카드와 같은 격자 · 같은 높이. 결과 수 자리와 선택지 건수 자리도 잡아 둔다 |
| 비어 있음 (검색 · 필터 있음) | 돋보기 아이콘 + `"조건에 맞는 글이 없어요."` / `"검색어나 필터를 바꿔 보세요."` + `[필터 초기화]`(필터가 없으면 `[검색어 지우기]` — 검색어만 걸려 있어도 되돌리는 길을 남긴다). **검색어를 제목에 넣지 않는다**(SE2-3 — 주소로 남의 화면에 문장을 심는 통로가 된다. 검색칸에 이미 보인다). 회색 판은 깔지 않고, 아래에 등록 권유 면 하나(의도를 골랐으면 그 의도의 면, 아니면 잉크 `[글 올리기]` 면) |
| 비어 있음 (조건 없이 0건) | 회색 판 대신 **등록 권유 면 하나** — 의도만 골랐으면 잃어버렸어요 `"아직 누군가 주워 둔 물건이 없어요."` / `"분실 글을 올려 두면 주운 사람이 연락할 수 있어요."` + `[분실 글 올리기]` · 주웠어요 `"아직 주인이 찾는 물건이 없어요."` / `"습득 글을 올려 두면 잃어버린 사람이 찾아볼 수 있어요."` + `[습득 글 올리기]`. 의도도 없으면 `"아직 올라온 글이 없어요."` / `"잃어버렸거나 주운 물건을 올려 보세요."` + 잉크 `[글 올리기]`. 버튼 색이 올릴 글을 따른다 |
| 오류 | 서버 `message`(빈 상태와 같은 단계의 제목 `h3`) + `[다시 시도]`. 응답 자체가 없으면 `"연결하지 못했어요. 네트워크를 확인하고 다시 시도해 주세요."`. 펼치다 실패한 것은 ④ |
| 권한 | 해당 없음. 전체 공개, 소유자 동작 없음 |

오류는 사진 자리에 옅은 면 한 장으로 둔다. 흰 종이 위 빈자리는 고장처럼 보인다.

**⑥ 안내 — 온보딩 1층 · 2층**(2026-09-26, 상세는 `docs/온보딩설계.md` 3 · 4장)

- **1층** : 가입 직후 한 번(또는 헤더 `서비스 안내`) 세 단계가 이 화면 위에 뜬다 — ① 의도 선택 두 칸 ② 검색창 + 필터 칩 ③ 헤더 `[글 올리기]`. 대상은 잉크 테로만 두르고 화면을 덮지 않는다. 좁은 화면 바텀 시트 · 넓은 화면 대상 옆 카드. `[건너뛰기]`는 카드 양 끝 배치 그대로, 보조 버튼(선 버튼) 모양
- **테 안을 누르면 그 동작을 한다**(2026-10-03 회의 RV-10) — 가리킨 것을 누르는 게 가장 자연스러운 다음 동작이다. 안내를 닫고(스크롤 잠금이 풀린 뒤) **누른 점 아래의 조작**을 누른다. 글자 칸이면 포커스만(휴대폰 키보드가 뜬다). 누른 것이 시트를 열면 시트가 포커스를 가져가고, 닫히면 그 조작으로 돌아온다. 누른 점이 조작 사이 틈이면 그 대상의 **대표 동작**(아래). 테가 (새 자리에) 막 나타난 **0.5초 안에 시작된 누름은 무시**한다(SE-1과 같은 `usePressGuard` — `[다음]`을 두 번 누른 둘째 누름이 테에 떨어져도 실행되지 않게). 키보드는 카드의 버튼으로 닫고 대상에서 이어 간다(같은 길이 이미 있다)

| 단계(대상) | 틈을 눌렀을 때 대표 동작(`guideFallbackControl`) |
|---|---|
| ① 의도 선택 두 칸 | 없음 — 두 의도 가운데 무엇을 골랐는지 알 수 없다. 닫기만 한다 |
| ② 검색창 + 필터 칩 | 검색칸에 포커스(틀은 검색칸과 칩 줄을 덮는 빈 칸이라 그 안에 조작이 없다) |
| ③ 헤더 `[글 올리기]` | `[글 올리기]` 그 자체 |

- **2층 `이름표 안내`** : 결과 제목 줄 건수 바로 뒤, 누르면 펼치는 설명. 분실 · 습득 · 연락중 · 완료의 뜻(카드 위와 같은 모양) + 이름표가 하나뿐이면(게시중) 아직 찾는 글. 모든 폭에서 아이콘 + 글자. 저절로 뜨지 않는다
- **2층 상태 메뉴** : 상태 칩이 여는 메뉴 아래 한 줄 "연락중은 주인으로 보이는 사람과 이야기하는 글, 완료는 주인에게 돌아간 글이에요."(메뉴의 설명으로 읽힌다)
- 안내를 닫으면 연 자리(헤더 `서비스 안내`)로, 가입 직후라 연 버튼이 없으면 첫 화면 제목으로 포커스가 간다

**동작과 결과 고지** — 되돌릴 수 없는 동작이 없다. 다이얼로그를 띄우지 않는다.

- 필수는 6개다(`type` `title` `category` `location` `lostFoundDate` `content`). **필수를 늘리지 않는다.** 사진만 선택이다.
  필수가 기본이라 **선택인 칸만** 표시하고(`사진 선택`), 제목 아래 한 줄이 규칙을 말한다 — `"사진만 빼고 모두 적어야 올라가요."`
- **유형이 맨 먼저다.** 목록 첫 화면의 의도 칸과 같은 말 · 같은 색 면(분실 마리골드 · 습득 코발트). 고르기 전에는 두 칸 다 제 색, 고르면 고른 칸만 면으로 남고 다른 칸은 옅어진다. 진짜 라디오 두 개라 화살표 키로 옮긴다
  - **선택 표시는 채운 점**(2026-10-03 회의 ⑤-a — 하나만 고르기) : 오른쪽 위 둥근 고리, 고른 칸만 가운데가 찬다. 색만으로 고른 것을 알리지 않는다. 동그라미 ✓는 "완료" 표시 전용이라 쓰지 않는다
  - 아래 한 줄이 **누가 이 글을 보게 되는지** 말한다 — 분실 `"물건을 주운 사람이 이 글을 찾아봐요."` · 습득 `"물건을 잃어버린 사람이 이 글을 찾아봐요."`(온보딩 2층). 고르기 전에는 `"고르면 누가 이 글을 보게 되는지 알려 드려요."`
  - `?type=LOST|FOUND`로 미리 고른다. 모르는 값은 버린다. 유형에 따라 날짜 이름(분실일 · 습득일), 칸 안 예시 · 도움말, 종류 그림의 색이 바뀐다
  - 좁은 칸은 "물건을 / 잃어버렸어요" 두 줄. 점은 짧은 첫 줄 옆에 앉아 글자 자리를 비우지 않는다 — 320 폭에서도 단어가 끊기지 않는다(`keep-all`)
- **입력 순서는 브리프 그대로**(사진 → 제목 → 종류 → 장소 → 날짜 → 설명). 사진을 제목 앞에 둔 이유 — 주운 사람은 물건을 손에 들고 있어 먼저 찍는다. 잃어버린 사람은 사진이 없는 경우가 많아 `선택`을 붙여 건너뛰기 쉽게 했다
- 종류는 드롭다운이 아니라 **포스터 그림이 든 다섯 칸**. 사진 없이 올리면 이 그림이 목록에 대신 들어간다는 것을 고르는 자리에서 본다(`"사진 없이 올리면 목록에 이 그림이 대신 보여요."`). 유형을 고르기 전에는 무채색. 320 폭은 3 + 2 로 접는다. 고른 칸은 **선 두 겹 + 오른쪽 위 접힌 귀퉁이**(그림 칸의 선택 표시 — 설정의 화면 모드 칸과 같다, ⑤-a)
- **예시는 입력칸 안 안내 글**(`placeholder`, 회의 UI-9 b) — 제목 `예: 에어팟 프로 왼쪽 한 쪽`(습득) · `예: 검은색 가죽 반지갑`(그 밖), 장소 `예: 강남역 2번 출구 고객센터`(습득) · `예: 강남역 2번 출구`(그 밖). 칸 이름은 위에 그대로 있다 — 안내 글을 이름 대신 쓰지 않는다
- **도움말은 꼭 필요한 것만**(UI-9 a) — 장소 : 습득 `"주운 곳이나 지금 맡겨 둔 곳을 적어 주세요."` · 분실 `"잃어버린 것 같은 곳이면 돼요."`. 날짜 : 분실만 `"정확하지 않으면 마지막으로 본 날을 골라 주세요."`("주운 날이에요" · "오늘 이후 날짜는 고를 수 없어요"는 칸 이름과 날짜 칸(`max`)이 이미 말해 뺐다). 제목에는 도움말이 없다. 오류가 떠 있는 동안 그 칸의 도움말은 숨는다(1.7)
- 날짜 — 기본값 오늘, `max` 오늘(달력에서 미래를 못 고른다). 손으로 미래를 치면 벗어날 때 `"분실일은 오늘 이후로 고를 수 없어요"`. 날짜 칸을 여는 대신 누르는 `[오늘]` `[어제]`(알약, `aria-pressed`) — 고른 것은 알약 안 앞머리의 **채운 점**(칠한 알약은 주 버튼과 무게를 다퉈 쓰지 않는다)
- 설명 — 사진에 안 보이는 특징을 권한다. 분실 `"색, 브랜드, 흠집, 안에 든 것처럼 사진에 안 보이는 특징을 적어 주세요."` · 습득 `"어떤 상태로 어디에 두었는지 적어 주세요. 주인만 알 만한 특징 한두 가지는 적지 않고 남겨 두면 진짜 주인을 가려낼 수 있어요."`. 그 아래 결과 고지 한 줄 `"전화번호 · 집 주소를 적으면 누구나 봐요."` — 오류가 떠 있어도 남는다(`note`). 연락처를 실제로 적으면 감지 줄이 따로 알린다(아래)
- 글자 수를 제목 · 장소 · 설명에 둔다(100 / 100 / 5000, DB 제약과 같다). **한도의 80%부터 보인다**(80 / 80 / 4,000 — 그 전의 `0/100`은 늘 떠 있는 잡음이다, UI-9 c). 그 전에도 스크린리더는 "최대 N자"를 읽는다. **`maxLength`로 자르지 않는다** — 붙여 넣은 글이 소리 없이 잘리면 무엇이 빠졌는지 모른다. 넘치면 글자 수가 굵어지고 벗어날 때 문장. 앞뒤 공백은 잘라서 세고, 잘라서 보낸다(서버는 자르지 않는다)
- **연락처 감지**(2026-10-03 회의 SE-3, `shared/lib/personalInfo.ts`) — 제목 · 장소 · 설명에 전화번호 · 주민등록번호 · 카드 번호 모양이 보이면 그 칸 아래 한 줄 `"전화번호가 들어 있어요. 올리면 누구나 봐요."`(주민등록번호 · 카드 번호도 같은 틀, 여럿이면 가장 민감한 것 하나). **막지 않는다**(올릴지는 쓰는 사람이 정한다). 판정은 **입력이 0.6초 멈췄을 때 + 칸을 벗어날 때**, 칸이 비면 바로 내린다. 눈 아이콘 + 굵은 잉크 글자 — 빨강이 아니다(1.2). 줄은 비어 있어도 **알림 영역으로 늘 있어** 처음 뜰 때 한 번 읽힌다(`aria-live="polite"`, 칸의 `aria-describedby`). 자리는 오류 아래 · 도움말 위. **설명 칸은 제출 줄 바로 위라 글자가 있으면 줄 자리를 미리 비워 둔다**(`reserveDetected` — 줄이 생기며 버튼을 밀면 누름이 빗나간다). 판정 규칙 · 오탐 목록은 보안명세서 8장 "화면에서 지키는 것"(SE-3)
- **넓은 화면(64rem 이상) 오른쪽 칸 — "목록에서 이렇게 보여요".** 목록 카드(`PostCard`, 링크 없이)를 그대로 그려, 첫 사진이 대표로 들어가고 사진이 없으면 고른 종류의 포스터가 들어가는 것을 쓰면서 본다. 스크롤을 따라 내려온다. 종류도 사진도 없으면 그림을 지어내지 않고 빈 칸에 한 줄. 입력과 같은 내용이라 스크린리더에는 숨긴다. 1440에서 가운데 700px만 쓰고 양옆이 비던 것을 막는다
- 헤더 `서비스 안내`를 이 화면에서 누르면 목록으로 떠나지 않고 제목 줄 끝 **`쓰는 요령`**(누르면 펼침)을 연다 — 쓰던 글을 두고 가지 않는다. 습득 글의 "가린 이름 · 번호는 진짜 주인을 가려내는 질문이 돼요" 문장은 사진 칸이 아니라 여기 있다(SE-2 — 칸 아래는 한 줄로)
- 헤더 `[+ 글 올리기]`는 이 화면에서 "지금 여기"이고 눌러도 무시한다(1.10)

| 오류 | 칸을 **벗어날 때** 검사(비어 있으면 지나가는 중일 수 있어 제출 때까지 기다린다), 고치면 그 칸의 오류가 걷힌다. 벗어나며 생긴 오류 하나는 바로 읽어 준다. 제출이 막히면 **첫 번째로 틀린 칸으로 포커스**(라디오 묶음은 고른 칸, 없으면 첫 칸)하고, 칸마다 붙은 오류는 읽어 주지 않는다 — 제출 줄 위 **`"3곳을 더 채워야 올라가요"`**(수정은 `저장돼요`) 한 줄이 유일한 알림이다(회의 AR-10 · UI2-9, `role="status"`). 보내기 전 검사 결과로만 세고(서버 400은 첫 칸 하나만 알려 준다), 칸을 고칠 때마다 다시 세어 다 채우면 줄이 사라진다 |
| 권한 | 비로그인은 이 화면에 도달하지 못한다(로그인으로, 돌아온다) |

검사 문장 — 서버 문장("카테고리는 필수입니다" · "본문은 …")의 낱말은 화면에 없는 말이라 **화면 이름으로** 쓴다(디자인품질기준 3장 "제목을 입력해 주세요"). 여기서 먼저 막으므로 서버 문장은 보통 오지 않는다.

| 칸 | 문장 |
|---|---|
| 유형 | `잃어버렸는지 주웠는지 골라 주세요` |
| 제목 · 장소 · 설명 | `제목을 적어 주세요` · `제목은 100자까지 쓸 수 있어요`(장소 · 설명도 같은 틀, 설명은 5,000자) |
| 종류 | `물건 종류를 골라 주세요` |
| 날짜 | `분실일을 골라 주세요` · `분실일은 오늘 이후로 고를 수 없어요`(습득일 · 날짜도 조사를 맞춘다) |

- 한 줄 칸(제목 · 장소)의 Enter 는 제출이 아니라 **다음 칸으로** — 한 손으로 칸을 이어 간다. 한글 조합 중 Enter 는 건드리지 않는다(`isComposing`). `enterkeyhint="next"`, 입력은 16px(iOS 확대 하한), 자동완성은 끈다(주소 · 이름이 아니다)
- **휴대폰(48rem 미만) · 화면 높이 40rem 이상에서만 제출 줄이 화면 아래에 붙어 따라온다** — 긴 설명을 쓰다가도 `[올리기]`를 찾지 않는다. 엄지가 닿는 자리, `safe-area-inset-bottom`. 높이 40rem 미만(가로 휴대폰 · 확대)과 48rem 이상은 **폼 끝 제자리**(붙는 것 총량 규칙 — 1.10)
  - 포커스가 옮겨 갈 때 줄에 가리지 않게 `scroll-padding-bottom` = **줄의 실제 높이**(`--form-bar-h`, `PostForm`이 `ResizeObserver`로 잰다) + 16px. 줄은 남은 칸 수 · 보내는 단계 · 오류 한 줄로 높이가 바뀐다 — 예전 고정값(6rem)은 넘쳤다(RV2-7, WCAG 2.4.11)
  - 키보드가 올라오면 iOS 는 붙은 줄을 키보드 뒤에 둔다(레이아웃 뷰포트가 줄지 않는다). 키보드를 내리면 바로 보이고, Enter 가 다음 칸으로 이어진다. `interactive-widget` 메타로 뷰포트를 줄이는 방법은 앱 전체의 붙은 헤더에 영향이 있어 쓰지 않았다

**동작과 결과 고지**

| 대상 | 형식 | 문구 |
|---|---|---|
| 사진 개수 | **인라인** | `5장까지 고를 수 있어요`(고르기 면) · 카운터 `2/5` · `[사진 추가 3장 더]` |
| 6장째 선택 | **인라인** | `"사진은 5장까지예요. 2장은 넣지 않았어요."` — 고른 순간 UI가 막는다. 서버로 보내지 않는다 |
| 작성 중 이탈(링크 · 뒤로가기 · 로고 · 메뉴) | **다이얼로그** | `쓰던 글을 두고 나갈까요?` / `"나가면 쓰던 내용은 저장되지 않아요."` · `[계속 쓰기]`(기본 포커스) `[나가기]` |
| 새로고침 · 탭 닫기 | 브라우저 확인 | `beforeunload` — 문장은 브라우저가 정한다 |
| `[작성 취소]` | **다이얼로그 — 쓴 게 있을 때만** | `작성을 취소할까요?` / `"쓰던 내용이 사라져요."` · `[계속 쓰기]` `[작성 취소]`. 쓴 게 없으면(유형만 미리 골라져 있어도) 바로 떠난다 |
| 쓰는 중 로그아웃 | **다이얼로그 — 쓴 게 있을 때만** | `쓰던 글을 두고 로그아웃할까요?` / `"쓰던 글은 이 기기에 남기지 않아요."` · `[계속 쓰기]` `[로그아웃]`(1.10) |

- 이탈 확인은 **쓰던 칸 등록부**(1.7)다 — 폼은 "쓰던 글자 있음"(처음 값과 다르거나 사진을 고르거나 지움을 눌렀거나 보내는 중)만 알리고(`useDirtyField`), 막는 곳 · 확인 창은 레이아웃에 하나다(예전 `useLeaveGuard`는 지웠다). 같은 화면에서 주소의 `?` 뒤만 바뀌는 이동은 막지 않는다 — 쓰던 칸이 그대로다
- 확인 창의 물러나는 버튼을 `취소`가 아니라 **`계속 쓰기`**로 — "작성 취소"를 묻는 창에서 `[취소]`는 두 뜻으로 읽힌다(`ConfirmDialog`의 `cancelLabel`)
- 등록은 되돌릴 수 있다(바로 지울 수 있다). **제출에 확인 다이얼로그를 띄우지 않는다.** 저장이 끝났거나 확인한 이탈에는 붙잡지 않는다

**로그인이 끊겼을 때 — 쓰던 글을 잃지 않는다**(개선 목록 A-4)

1. 쓰는 도중 **재발급이 거절되면**(다른 기기에서 비밀번호를 바꿈 · 리프레시 만료) 폼을 내리기 전에 **글자만** 이 탭의 sessionStorage 에 넣는다(`post-draft:v1:create`, 회원 id · 시각 · 값 · 고른 사진 수). 직접 로그아웃했으면 넣지 않는다(공용 기기, 보안명세서 3장)
2. `SCR-05` 로그인 화면으로 기록을 바꿔 간다 — `?redirect=`(이 화면) + 폼 위 `"로그인이 만료됐어요. 다시 로그인해 주세요. 로그인하면 쓰던 글을 이어서 쓸 수 있어요."`(이 창에서 로그아웃했으면 `"로그아웃했어요."`, 쓴 게 없으면 뒷문장 없음)
3. 로그인하면 돌아오고, 폼 맨 위에 **`로그인이 끊기기 전에 쓰던 글이 있어요.`** + 제목 한 줄 + `"고른 사진 2장은 보관하지 못해 다시 골라야 해요."` + `[이어서 쓰기]` `[새로 쓰기]`
4. `이어서 쓰기` → 글자가 돌아오고 사진 칸 안에 `"전에 고른 사진 2장은 보관하지 못했어요. 다시 골라 주세요."`, 포커스는 사진 고르기로(사진이 없었으면 제목으로). 어느 쪽을 누르든 보관한 것을 지운다

- **사진은 보관하지 못한다** — 파일은 저장소에 담을 수 없다. 몇 장이었는지만 적어 두고 사진 칸에서 알린다
- 같은 회원에게만 묻는다(공용 기기에서 다른 사람이 로그인하면 보이지 않는다). 탭을 닫으면 사라지고 6시간이 지나면 버린다. 토큰이 아니라 사용자가 쓴 글이다(보안명세서 7장)
- 끊김을 알아채는 곳은 `app/usePostWritePage` — 한 번 로그인한 채로 본 화면에서 비로그인이 되면 폼을 내리지 않고, 폼이 보관을 끝낸 뒤 로그인으로 보낸다. 처음부터 비로그인이면 보관 없이 로그인으로
- **다른 창에서 로그아웃했는데 쓰던 글자가 있으면 떠나지 않는다**(회의 SE2-10) — 폼 맨 위에 자물쇠 + `"다른 창에서 로그아웃했어요. 쓰던 글은 이 기기에 남기지 않아요."` / `"아래 글자는 읽기만 할 수 있어요. 필요한 내용은 옮겨 두고 다시 로그인해 주세요."` + `[로그인]`, 그 줄로 포커스. 모든 칸은 읽기 전용, `[작성 취소]` · `[올리기]`는 흐리게 누름 무시(`unavailable`). 글자는 저장소에 넣지 않는다. 등록부는 그대로라 실수로 떠나려 하면 묻는다. 쓰던 글자가 없으면 로그인 화면 + `"다른 창에서 로그아웃했어요."`

**예외**

| 상황 | 화면 |
|---|---|
| 401 `INVALID_ACCESS_TOKEN` | 인터셉터가 재발급 후 재전송(사진 요청은 토큰이 1분 안에 끝나면 먼저 재발급). 재발급 거절 → 위 "로그인이 끊겼을 때" |

**연락 입구 — 댓글 쓰기**(2026-10-03 회의 ①)

쓰는 칸은 댓글 목록 끝이라 휴대폰에서 첫 화면 밖(390에서 y≈900~1,277)이다. 그래서 거기로 데려가는 **입구가 셋**이고, 셋 다 같은 일 하나(`open()`)를 부른다.

| 입구 | 언제 보이나 | 모양 |
|---|---|---|
| 배지 줄 오른쪽 `댓글 쓰기 N` | **모든 폭, 늘**(첫 화면 안 — 판단하는 순간 손이 있는 사진 · 이름표 곁). N은 0이면 붙이지 않는다 | 선 버튼(말풍선 + 글자 + 숫자, `size="sm"`). `이름표 안내`와 한 묶음이라 좁으면 둘이 같이 다음 줄 오른쪽으로 내려간다 |
| "댓글 N" 제목 옆 | **댓글이 1개 이상일 때만**(0건이면 쓰는 칸이 바로 아래다) | 같은 선 버튼, 숫자 없음(바로 앞에 숫자가 있다) |
| 휴대폰 하단 줄 `댓글 쓰기 N` | **폭 48rem 미만 · 높이 40rem 이상**에서만. 배지 줄 입구가 **화면 위로 나간 뒤**에 나타나고, 진짜 쓰는 칸(또는 로그인 권유 칸 · 복구 중 자리)이나 제목 옆 입구가 화면에 들어오면 숨는다 — **같은 입구가 둘 동시에 보이는 순간이 없다** | 화면 아래에 붙은 줄. 그림자 없이 위 1px 선, 채운 버튼 하나(이 화면에서 채운 강조는 이것 하나 — 쓰는 칸의 `[댓글 남기기]`와 동시에 보이지 않는다). 완료 글은 채움 대신 선 버튼(이미 돌아간 물건에 연락을 재촉하지 않는다). 기기 아래 여백(safe-area)만큼 길어진다 |

- 하단 줄의 판정은 `IntersectionObserver`로만 한다(헤더 56px 밑은 보이지 않는 것으로 본다). 스크롤 방향 · 댓글 수 같은 값으로 하면 다시 받는 사이 깜빡인다. 숨은 동안은 `inert` — Tab · 스크린리더가 보이지 않는 버튼에 닿지 않는다. 짧은 화면 · 가로 모드 · 크게 확대한 화면에서는 붙는 줄이 가리는 몫이 커서 저절로 꺼진다(1.10 총량 규칙)
- 하단 줄은 높이를 문서에 알린다(`useBottomInset` → `--bottom-inset` · `scroll-padding-bottom`) — 짧은 알림이 그 위로 비켜 뜨고, Tab으로 옮긴 포커스가 줄 밑에 숨지 않는다(API2-3)
- **누르면 그 이벤트 안에서 포커스**(①-a) — 로그인했으면 입력칸에, 아니면 로그인 권유 칸의 `[로그인]`에 **누른 그 이벤트 안에서** `focus()` 한다. iOS는 스크립트가 늦게 준 포커스에 키보드를 띄우지 않는다(UI2-2). 스크롤은 그 뒤에 따로(가운데로, 부드럽게 — 모션 줄이기면 즉시)
- 댓글 수는 제목 · 입구 · 하단 줄이 **같은 값**을 읽는다(`useCommentTotal` — 상세의 `totalCommentCount`를 따로 읽으면 1분 뒤 댓글을 다시 받는 사이 둘이 잠깐 달라진다)

**넓은 화면(64rem 이상)** — 두 칸. 왼쪽 사진 열은 스크롤을 따라 내려온다(sticky) — 댓글을 읽으면서도 물건이 보인다.
오른쪽 읽기 열은 30rem(80rem 이상 34rem = 본문 한 줄 34em). 1440에서 가운데 700px만 쓰고 양옆이 비는 것을 막았다.
40~64rem(태블릿)은 한 줄(700px)이고 사진 상자만 4:3으로 낮춘다 — 1:1이면 사진이 첫 화면을 다 차지한다.

**핵심 정보를 본문 앞에 둔 이유** — 브리프의 순서는 "본문 → 메타(작성자 · 분실/습득일 · 등록일 · 조회수)"였다.
장소 · 분실습득일 · 종류는 "내 물건인가"를 가르는 정보라 본문보다 먼저 읽혀야 한다. 셋만 유형 색의 옅은 면에 모으고,
누가 · 언제 올렸나 · 몇 명이 봤나는 본문 뒤 메타 한 줄로 뺐다. 메타는 가운뎃점 대신 간격으로 나눈다.
핵심 정보 면의 이름표(`장소` · `분실일` · `종류`)는 **글자만**이다 — 아이콘 셋을 뺐다(UI-14 a, 같은 말을 두 번 하는 장식이었다).

**완료된 글**(2026-10-03 회의 UI-11 · RV-5) — 링크로 들어온 사람에게 가장 먼저 알린다.

- 이름표의 완료는 목록 카드와 같은 **잉크 도장**(체크 + 완료, `StatusBadge surface="detail"`)
- 제목 · 이름표 아래 한 줄 `(체크) 주인에게 돌아간 물건이에요.` — **글쓴이가 아닐 때만.** 글쓴이에게는 바로 아래 내 글 관리가 같은 말을 한 번 한다(한 번만 말한다)
- 사진은 **컬러 그대로**다(목록 카드처럼 흑백으로 낮추지 않는다 — 상세는 단서를 봐야 하는 화면이다)

**사진**

- 1:1(태블릿 4:3) **비율 상자 안에 자르지 않고**(`contain`) 놓는다. 목록 썸네일은 스캔용이라 잘랐지만 상세는 이름표 글씨 · 흠집 같은 단서를 봐야 한다.
  남는 칸은 **같은 사진을 흐리게 깐다** — 가로 사진 위아래 · 세로 사진 양옆이 빈 회색 띠로 남지 않게(같은 주소라 한 번만 받는다, 읽지 않는 배경)
- 여러 장 : 손가락으로 넘긴다(가로 스크롤 스냅, 한 번에 한 장). 지금 몇 번째인지는 IntersectionObserver 가 센다(스크롤 이벤트 없음)
- 아래 줄 : 작은 사진(30rem 이상, 누르면 그 장으로) · `2 / 5` · 이전 / 다음. 끝에서는 `aria-disabled`(잠그지 않는다 — 누르던 버튼에서 포커스가 빠진다). **끝에 닿은 쪽 화살표는 그리지 않는다**(UI-14 c — 누를 수 없는 조작을 흐리게 남겨 두면 "눌러 볼 것"이 하나 더 보인다). 자리는 비워 두어 숫자 · 반대쪽 화살표가 움직이지 않고, 키보드로 그 버튼에 머물러 있으면(`:focus-visible`) 다시 보여 어디에 있는지 알게 한다
- 키보드 : Tab 은 사진 하나에만 걸린다(나머지 장은 `tabIndex=-1`). 사진에서 ← → · Home · End, Enter 로 크게 보기. 작은 사진 줄은 Tab 에 걸지 않는다(같은 일을 ← → 가 한다)
- 누르면 **크게 보기**(`PhotoViewer`, 네이티브 `<dialog>`) — 화면 전체 어두운 바탕, 자르지 않은 사진, 넘기기 · ← →, 열리면 [닫기]에 포커스, Tab 은 안에서 돈다, Esc 로 닫힌다. 닫으면 넘긴 자리의 사진으로 포커스가 돌아온다
- `alt` 는 게시글 제목(여러 장이면 `제목 (사진 2/5)`). "이미지"라고 쓰지 않는다
- 사진이 없으면 목록과 같은 포스터(1.8). 크게 놓일 때(26rem 이상) 물건 이름도 커진다. 주소가 깨진 장도 포스터로 바뀐다
- 첫 장은 바로(`fetchpriority=high`), 나머지는 스크롤에 닿을 때 받는다. 받는 동안 옅은 면 → 다 받으면 떠오른다(투명도 280ms)

**본문** — 사용자 입력 원문. `white-space: pre-wrap`(줄바꿈 그대로) + `overflow-wrap: anywhere`(띄어쓰기 없는 긴 주소 · 문자열이 칸을 밀지 않는다) + `keep-all`.
**링크로 바꾸지 않는다** — `href`에 사용자 입력을 넣는 순간 `javascript:` 검사가 필요해진다(보안명세서). `<script>` · `<b>` 도 글자 그대로 보인다(React 이스케이프, `dangerouslySetInnerHTML` 없음). 본문 URL 자동 링크는 회의에서도 **계속 보류**다(⑦).
메타의 글쓴이 닉네임은 방향을 격리한다(`<bdi>` — 뒤집는 글자가 옆 칸으로 번지지 않게, SE-6).

**권한** — `detail.memberId === me.id`(숫자 비교)일 때만 `내 글 관리`를 **렌더한다**. 비로그인 · 남의 글에는 자리도 없다.
세션을 되살리는 중(`unknown`)에는 그리지 않았다가 결과가 오면 붙는다 — 로그인한 사람에게 버튼이 먼저 떴다 사라지는 일이 없다.

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 실제 배치 그대로의 스켈레톤 — `목록으로` · 제목 두 줄 · 배지 둘 · 사진 상자(같은 비율) · 핵심 정보 면 · 본문 네 줄. 넓은 화면도 두 칸 그대로. **목록 카드로 들어왔으면 머리를 먼저 그린다**(API-3) — 목록 캐시에 있는 그 카드의 제목 · 이름표 · 첫 사진(요청을 더 보내지 않는다, 1분 넘은 캐시 · 무효화된 캐시는 쓰지 않는다). 가짜 상세를 만들지 않는다(`placeholderData` 금지 — 내 글 판정과 댓글 초기값이 틀린다). 먼저 그린 제목은 `h1`이 아니고 스크린리더에는 "글을 불러오는 중이에요"만 읽힌다(SE2-4 — 옛 제목을 읽히지 않는다). 탭 제목은 진짜 응답 뒤에 바뀐다. 진짜 화면으로 바뀔 때 아무 데도 포커스가 없으면 진짜 제목으로 데려온다 |
| 비어 있음 | 댓글 0건 → 작은 빈 상태 `"아직 댓글이 없어요."` + 유형별 한 줄(분실 글 `"이 물건을 본 적 있다면 댓글로 알려 주세요."` · 습득 글 `"내 물건 같다면 댓글로 알려 주세요."` · 내 글 `"누군가 댓글을 남기면 여기에 보여요."`) |
| 없는 글 | 404 `POST_NOT_FOUND` · 400(받아 주지 않는 id) · 숫자가 아닌 주소(요청하지 않는다, `toPostId`) → 본문 전체를 `"없거나 삭제된 글이에요."` / `"주소가 맞는지 확인하거나 목록에서 다시 찾아보세요."` + `[목록으로]` |
| 오류 | 그 밖 → 서버 `message` + `[다시 시도]`, 위에 `[목록으로]`. 받아 둔 글이 있으면 다시 받다 실패해도 그대로 둔다 |
| 권한 | 위 권한 절. 댓글 입력은 비로그인에게 `"로그인하면 댓글을 남길 수 있어요." [로그인]`(로그인 뒤 이 글의 댓글 자리로 돌아온다 — 아래 "로그인 뒤 돌아오기") |

> 없는 글의 문장을 서버 `message`("존재하지 않는 게시글입니다")가 아니라 프론트 문장으로 둔 이유 — 잘못된 주소는 요청을 보내지 않아 서버 문장이 없다.
> 두 경우가 같은 화면이어야 해서 "빈 상태 문구"(1.3의 프론트가 쓰는 문구)로 다뤘다.

**로그인 뒤 돌아오기**(2026-10-03 회의 ①-b)

- 로그인 권유 칸의 `[로그인]`은 `?redirect=/posts/{id}#comments`로 간다. 돌아갈 곳에 붙어도 되는 조각은 **`#comments` 하나**다(1.5, 문자열 비교)
- 돌아오면 **입력칸이 아니라 "댓글" 제목**(`id="comments"`)으로 데려가 포커스를 둔다 — 사용자 동작이 아니라 키보드가 갑자기 화면을 덮을 이유가 없다. 쓰던 댓글을 이어 쓸지 묻는 칸이 먼저 포커스를 가져갔으면 그쪽이 우선. 조각은 **바로 지운다**(기록 바꿔치기, 진입 상태는 그대로) — 새로고침 · 공유에서 또 끌려가지 않게. 경로가 같아 스크롤 기억 · 화면 이동 포커스는 건드리지 않는다
- **돌아왔을 때 받아 둔 상세가 있으면 다시 받지 않는다**(API2-1) — 상세 요청은 조회수를 센다. 로그인 때 세션 정리도 상세 키는 무효화하지 않는다(1.10). 없으면(5분이 지나 지워짐) 평소처럼 받는다
- 로그인 화면 · 가입 화면이 상세의 진입 상태를 모양 검사 뒤 되돌려 준다(API2-2) — 돌아온 상세의 `[목록으로]`가 보던 목록(필터 · 의도 · 스크롤)으로 **뒤로 간다**. 상세 → 로그인 · 로그인 ↔ 가입 · 로그인 → 상세가 모두 바꿔치기라 기록은 `[목록, 상세]`로 남는다

**동작과 결과 고지**

**① 게시글 삭제 — 확인 다이얼로그**(`shared/ui/ConfirmDialog`). 되돌릴 수 없다.

```
+--------------------------------------+
| 이 글을 삭제할까요?                    |
|                                      |
| 이 게시글을 삭제하면 사진 5장과 댓글 5개가 |
| 함께 사라져요. 되돌릴 수 없어요.          |
|                                      |
|              [취소]  [삭제하기]        |
+--------------------------------------+
```

- 숫자는 실제 값(`images.length`, `totalCommentCount` — 댓글을 쓰고 지우면 캐시가 따라 바뀐다). 0인 항목은 뺀다 — `"이 게시글을 삭제하면 사진 3장이 함께 사라져요. 되돌릴 수 없어요."` · `"… 댓글 5개가 …"` · 둘 다 없으면 `"이 게시글을 삭제하면 되돌릴 수 없어요."`
- `[삭제하기]`는 빨강(`Button variant="danger"`), 여는 `[삭제]`는 선 + 빨간 글자(`dangerQuiet`). **기본 포커스는 `[취소]`**
- **`[수정]`–`[삭제]` 사이 16px**(2026-10-03 회의 RV-3 · ⑦ — 위험 동작은 자주 쓰는 동작과 뗀다, 모양도 다르다). `[삭제]`를 줄 끝으로 옮기지 않는다 — 확인 창의 `[삭제하기]` 자리로 가면 두 번 누름이 통과한다(SE-1)
- **열린 뒤 0.5초 안에 시작된 마우스 · 터치 누름은 `[삭제하기]` · 바깥 닫기 모두 흘려보낸다**(SE-1, `shared/lib/pressGuard`) — `[삭제]`를 두 번 누르면 둘째 누름이 막 뜬 `[삭제하기]`에 떨어져 읽지도 않은 확인이 통과된다. 기준은 누름이 **시작된** 때(`pointerdown`)다. 키보드(`detail === 0`)와 `[취소]`는 즉시. 버튼 모양은 바꾸지 않는다(비활성처럼 보이면 "안 눌리네?" 하고 또 누른다)
- 포커스를 가둔다(Tab 이 안에서 돈다 — 네이티브 모달은 마지막 버튼에서 주소창으로 빠진다). Esc · 바깥 누름으로 닫고, 닫으면 연 버튼으로 돌아간다
- 요청 중에는 두 버튼을 `aria-disabled` 로 두고 누름 · Esc · 바깥 누름을 막는다(`disabled` 로 잠그면 포커스가 빠진다). 글자는 `삭제하는 중…`
- 성공(204) → 목록으로 `replace`(뒤로가기가 지운 글로 돌아가지 않는다) + 짧은 알림 `"글을 삭제했어요."`(`shared/ui/Flash` — 아래 가운데 잉크 한 줄, 4초, 알림 영역이라 스크린리더가 읽는다, 누를 것 없음)
- 404(다른 탭에서 이미 지움) → 성공과 같게 목록 + 서버 `message`. 403 · 연결 실패 → 다이얼로그 안에 `message`, 닫지 않는다(다시 누를 수 있다)
- 완료(`DONE`) 글도 삭제할 수 있다

| 전이 | 형식 |
|---|---|
| 게시중 ↔ 연락중 | **두 칸 스위치, 확인 없이 바로.** 누른 칸이 잉크로 찬다. 아래 한 줄 `"게시중과 연락중은 언제든 서로 바꿀 수 있어요."`(되돌릴 수 있음을 누르기 전에). "상태" 이름표는 스크린리더만 읽는다 — 두 칸 스위치가 스스로 말한다(UI-5) |
| → 완료 | 스위치와 **떨어진 버튼** `[✓ 완료로 바꾸기]` → 확인 다이얼로그 |

완료를 스위치의 세 번째 칸으로 두지 않은 이유 — 세 칸이 같은 모양이면 "언제든 오가는 것"과 "마지막 단계"가 같아 보인다. 모양으로 먼저 가른다.

```
+--------------------------------------+
| 완료로 바꿀까요?                       |
|                                      |
| 완료로 바꾸면 다시 게시중이나 연락중으로 |
| 되돌릴 수 없어요.                      |
|                                      |
|           [취소]  [완료로 바꾸기]      |
+--------------------------------------+
```

- 낙관적 업데이트를 하지 않는다. 요청 중에는 스위치 · 버튼이 누름만 무시하고 한 줄이 `바꾸는 중…`. 성공하면 배지 · 스위치가 바뀌고 스크린리더에 `"연락중으로 바꿨어요."`
- 같은 확인 창이라 SE-1 누름 무시가 같이 걸린다
- **연락중으로 바꾼 직후 한 번만** 상태 줄 아래 안내 한 줄(2026-10-03 회의 SE-4 — 연락을 시작하는 순간이 판단하는 순간이다). 습득 글 `"물건을 넘기기 전에 사진에 없는 특징을 물어 주인인지 확인해 주세요."` · 분실 글 `"돈을 먼저 보내 달라는 요청은 받지 마세요."`. 정보 아이콘, 빨강 아님. 스크린리더는 `"연락중으로 바꿨어요."` 뒤에 이어 읽는다. 다시 바꾸면 사라진다. 목록 · 첫 화면 경고로 넓히지 않는다(겁주는 예고는 읽히지 않는다)
- 완료가 되면 스위치 자리가 **읽기 전용**으로 바뀐다 — `(체크) 주인에게 돌아간 물건이에요. 상태는 더 바꿀 수 없어요.`(상세 머리의 같은 줄은 글쓴이에게 그리지 않아 여기서 한 번만 말한다). 누를 수 없는 버튼을 남기지 않는다. 연 버튼이 사라졌으므로 포커스는 `내 글 관리` 제목으로
- 내 글 관리 안의 두 묶음(상태 / 수정 · 삭제)은 **구분선 없이 24px**로 가른다(UI-5 — 근접성, 구분선으로 묶음을 대신하지 않는다)
- 409 `INVALID_STATUS_TRANSITION`(다른 탭에서 이미 완료) → 상태 줄 아래 서버 `message`, 상세를 다시 받아 읽기 전용으로 맞춘다. 403 도 같은 자리 + 다시 받는다

**③ 댓글** — 백엔드 `[5.1]` 머지 완료(PR #22). 전부 붙였다.

| 기능 | 엔드포인트 | 화면 |
|---|---|---|
| 목록(처음 20건) | `GET /api/posts/{id}` 응답의 `comments` | 상세 응답으로 바로 그린다(댓글 요청 없음) |
| 더 보기 | `GET /api/posts/{id}/comments?page=` | `[댓글 더 보기 25개]` — `page=1`부터, `size` 안 보냄 |

- 오래된 순. 이름(방향 격리 `<bdi>`) · (글쓴이가 단 댓글이면 **사람 아이콘 + `글쓴이`** — 아이콘이 있어 닉네임 `홍길동글쓴이` · 본문 첫머리 `(글쓴이)` 같은 글자로 흉내 낼 수 없다, SE-6) · `2026. 9. 24. 09:12` · `updatedAt`이 있으면 `(수정됨)`. 본문은 게시글 본문과 같은 규칙(pre-wrap · 링크 안 만듦). 상대 시간은 미뤘다(서버 시각에 시간대가 없어 9시간 어긋날 수 있다 — 개선 M5)
- `[댓글 더 보기 n개]` — 남은 수를 붙인다. 받으면 **새로 받은 첫 댓글로 포커스**(버튼이 사라져도 읽던 자리가 이어진다). 실패하면 버튼 아래 서버 `message`, 버튼을 다시 누르면 된다
- **방금 쓴 댓글은 목록 끝에 바로 보인다.** 마지막 페이지까지 펼쳐 두지 않았으면 캐시에는 개수만 늘므로, 등록 응답을 따로 들고 있다가 `[더 보기]` **아래**에 붙인다 — 사이에 `[더 보기]`가 있어 순서가 거짓말을 하지 않는다. 나중에 그 페이지를 받으면 id 로 하나만 남긴다. 나타날 때 4px 떠오른다
- 입력 : `댓글 남기기` 라벨 · 글자 수는 240자(80%)부터 `n/300`. **공개 게시판이라는 상시 문장은 뺐다**(2026-10-03 보안 결정 SE-3 — 늘 떠 있는 경고는 읽히지 않는다). 대신 전화번호 · 주민등록번호 · 카드 번호 모양이 **보일 때만** 한 줄 `"(눈) 전화번호가 들어 있어요. 올리면 누구나 봐요."` — 판정은 **입력이 0.6초 멈췄을 때 + 칸을 벗어날 때**(칸을 벗어나는 순간이 곧 `[댓글 남기기]`를 누르는 순간이라 벗어날 때만 보면 줄이 공개 뒤에 뜬다, SE2-1). 막지 않는다. **감지 줄은 제출 줄 왼쪽**에 둔다 — 칸과 버튼 사이에 줄이 끼면 버튼이 밀려 누름이 빗나간다(API2-12), 같은 줄이면 몇 줄로 늘어도 버튼은 제자리다. 줄은 알림 영역으로 늘 있다(처음 뜰 때 한 번 읽힌다). 빨강을 쓰지 않는다
- 보내기 전 검사(해요체) : 비었으면 `"댓글을 적어 주세요"`, 300자를 넘으면 글자 수가 굵어지고 `"댓글은 300자까지 쓸 수 있어요"`. 서버가 막으면 서버 문장이 그대로 온다. `maxLength`로 자르지 않는다(붙여 넣은 글이 소리 없이 잘리면 무엇이 빠졌는지 모른다). 칸은 줄을 따라 늘어난다
- 제출 중 입력은 읽기 전용, 버튼은 `남기는 중…` + 누름 무시(두 번 눌러도 한 건). 실패하면 입력을 지우지 않고 칸 아래 `message`. 쓰던 내용이 있으면 **쓰던 칸 등록부**에 알린다(1.7) — 앱 안 이동 · 새로고침 · 탭 닫기 · 로그아웃이 한 번 묻는다(`"쓰던 댓글을 두고 나갈까요?"` / `"나가면 쓰던 댓글은 저장되지 않아요."`). 예전에는 이 칸에 앱 안 이탈 확인이 없었다(AR2-2)
- 본인 댓글만 `[수정] [삭제]`(글자 버튼, 늘 보인다 — 마우스를 올려야 나오면 휴대폰에서 못 찾는다). **사이 16px**(RV-3). 수정은 그 자리 입력칸 + `[취소] [저장]`, Esc 로 그만둔다, 저장하면 `[수정]`으로 포커스가 돌아온다. 고치는 칸도 같은 감지 줄을 쓰고(SE-3), 고친 글자가 있으면 등록부에 알린다
- 고치던 중 로그인이 끊기면(만료 · 다른 창 로그아웃) 고치던 글자를 **읽기 전용으로 남기고** `"로그인이 끊겨 고친 내용을 저장할 수 없어요. 필요한 내용은 옮겨 두고 다시 로그인해 주세요."` + `[닫기]`(저장 버튼은 없다). 이 창에서 로그아웃을 골랐거나 고친 것이 없으면 그냥 닫는다. 저장소에는 넣지 않는다
- **댓글 삭제는 다이얼로그 대신 그 자리에서 한 번 더 묻는다** — `[삭제]` → `이 댓글을 삭제할까요? 되돌릴 수 없어요. [취소] [삭제하기]`(옅은 빨강 칸, `[취소]`–`[삭제하기]` 16px, 포커스는 `[취소]`, 요청 중 `삭제하는 중…`). 지우면 `댓글 n` 제목으로 포커스 + 알림 영역 `"댓글을 삭제했어요."` — 삭제 동작의 동사는 화면 어디서나 `삭제`다(버튼 글자와 같게)

> **댓글 삭제를 다이얼로그로 하지 않은 판단(2026-09-27)** — 되돌릴 수 없으니 확인은 받는다. 다만 잃는 것이 300자 한 줄이고, 결과가 그 자리에서 바로 보인다.
> 다이얼로그는 게시글 삭제 · 완료 둘에만 두어야 사용자가 그 문장을 읽는다 — 가볍게 자주 누르는 동작에도 띄우면 "다이얼로그 = 그냥 확인 누르기"를 배운다(1.6의 규칙 2).
> 그래서 설계서대로 **두 번 누르기 인라인 확인**을 따랐다. 확인 칸의 기본 포커스는 다이얼로그와 같게 `[취소]`

**예외**

| 상황 | 화면 |
|---|---|
| 404 `POST_NOT_FOUND` | 없는 글 화면(위). 댓글 등록 중 글이 지워졌으면 상세를 다시 받아 같은 화면으로 바뀐다 |
| 403 `FORBIDDEN_ACCESS` | 상태 줄 · 다이얼로그 · 댓글 칸 아래 `message`. 상세를 다시 받아 화면을 맞춘다 |
| 409 `INVALID_STATUS_TRANSITION` | 상태 줄 아래 `"완료된 게시글은 상태를 되돌릴 수 없습니다"`. 상세를 다시 받아 읽기 전용으로 |
| 404 `COMMENT_NOT_FOUND` | 수정 · 삭제 자리 아래 `message`, 댓글을 다시 받는다(삭제는 성공과 같게 정리) |
| 401 | 인터셉터 재발급 → 실패하면 비로그인으로 바뀌며 `내 글 관리`(와 그 안의 다이얼로그) · 댓글 입력이 사라진다. **댓글 칸에 쓰던 글자가 있었으면**(2026-09-27) 글자만 이 탭 sessionStorage(`comment-draft:v1:{글 id}`)에 보관하고 로그인 화면으로 보낸다 — `"로그인이 만료됐어요. 다시 로그인해 주세요. 로그인하면 쓰던 댓글을 이어서 쓸 수 있어요."` · 돌아올 곳 `보던 글`. 돌아오면 쓰기 칸 위에 `"로그인이 끊기기 전에 쓰던 댓글이 있어요."` + 글자 두 줄 + [이어서 쓰기] · [새로 쓰기], 그 칸까지 스크롤하고 포커스를 둔다. 같은 회원에게만 묻고 6시간이 지나면 버린다. 고르면 바로 지운다. 직접 로그아웃한 것 · 댓글 수정 칸은 보관하지 않는다 |
| 다른 창에서 로그아웃 | 댓글 칸에 쓰던 글자가 있으면 칸을 **읽기 전용으로 남긴다**(SE2-10) — 칸 위 자물쇠 + `"다른 창에서 로그아웃했어요. 쓰던 댓글은 이 기기에 남기지 않아요."` / `"아래 글자는 읽기만 할 수 있어요. 필요한 내용은 옮겨 두고 다시 로그인해 주세요."` + `[로그인]`(제출 줄 없음). 저장소에 넣지 않는다. 같은 사람이 다시 로그인하면 칸이 그대로 이어지고, 다른 사람이 로그인하면 글자를 비운다. 글자가 없으면 로그인 권유 칸으로 바뀐다 |
| `postId`가 숫자가 아님 | 요청하지 않고 없는 글 화면. 서버가 400 을 줘도 같은 화면 |

**목록 ↔ 상세 스크롤** — `app/ScrollMemory`가 맡는다. 단계 4에서 데이터 라우터(`createBrowserRouter`)로 옮겨 `<ScrollRestoration>`을 쓸 수 있게 됐지만 쓰지 않는다 — 아래 규칙(같은 경로의 주소 변경은 건드리지 않음 · 목적지 높이가 찰 때까지 기다림)이 이 앱에 맞춰져 있다.
새 화면으로 가면(PUSH · REPLACE, 경로가 바뀔 때) 맨 위에서 시작하고 — 목록을 내린 채 글을 누르면 상세가 중간부터 열리던 것 —
뒤로 · 앞으로(POP)는 떠날 때 위치로 돌아간다(목록 1400px → 상세 → 뒤로 = 1400px 확인). 목록의 필터 · [더 보기]처럼 같은 경로에서 주소만 바뀌면 건드리지 않는다.
위치는 기록 항목(`location.key`)마다 프레임당 한 번 적고, 새로고침에도 이어지게 sessionStorage 에 둔다. 브라우저 자동 복원은 끈다(`manual`).

**헤더 `서비스 안내`** — 상세에서 누르면 목록으로 떠나지 않고 이 글의 `이름표 안내`를 연다(보던 글을 잃지 않는다). 안내 자리까지 데려오고 포커스를 그 버튼에 둔다.
화면이 자기 안내를 헤더에 알려 두는 방식이다(`app/onboarding`의 `usePageGuide`). 등록 · 수정(SCR-02 · 04)의 `쓰는 요령`도 같다. 다른 화면은 그대로 목록으로 가며 1층 안내를 연다.

```
[(카메라) 새 사진으로 바꾸기]           +------------------------------+     | 저장하면 기존 사진 5장 대신     |
[(휴지통) 사진 전부 삭제]              | (!) 저장하면 기존 사진 5장이    |     | 이 사진 2장이 올라가요.         |
지금 사진 5장이 그대로 남아요.           |     모두 지워져요. 저장한 뒤에는 |     | [↶ 기존 사진 유지]              |
‘새 사진으로 바꾸기’를 고르면 5장이      |     되돌릴 수 없어요.            |     +------------------------------+
모두 바뀌어요.   <- 인라인 고지(상시)    | [↶ 기존 사진 유지] [새 사진 고르기]|    첫 장이 목록에 보이는 대표 사진이에요.
                                      +------------------------------+
```

- **상태(`status`)는 이 화면에서 바꾸지 않는다.** `[4.6]` 전용 엔드포인트가 따로 있다. 상세에서 바꾼다. 미리보기 카드는 지금 상태 이름표(연락중 · 완료)를 그대로 보여 준다
- 조회수·등록일·작성자는 바뀌지 않는다. 읽기 전용으로도 두지 않는다
- 완료(`DONE`) 글도 수정할 수 있다
- 처음 값은 **이 화면에 들어온 순간의 글**이다. 뒤에서 상세를 다시 받아도 쓰던 칸을 덮지 않는다(`EditForm`이 처음 값을 붙잡는다)

**동작과 결과 고지** — **이 화면의 이미지 규칙은 직관과 어긋난다. 화면이 말해줘야 한다.** 서버는 "그대로 · 전부 교체 · 전부 삭제" 셋만 안다(`PostImageChange`) — 한 장만 빼거나 더할 수 없다

| 사용자 행동 | 보내는 것 | 서버 동작 | 화면이 알리는 방식 |
|---|---|---|---|
| 사진을 안 건드림 | `images` 파트 없음 · `removeImages` 없음 | 기존 사진 **유지** | 지금 사진 + `[새 사진으로 바꾸기]` · `[사진 전부 삭제]` 바로 아래 **인라인 상시** `"지금 사진 N장이 그대로 남아요. ‘새 사진으로 바꾸기’를 고르면 N장이 모두 바뀌어요."` — 지금 상태를 먼저 말하는 **긍정문**(2026-10-03 회의 RV-8. 예전 "그대로 두려면 선택하지 마세요"는 하지 말라는 말로 끝났다) |
| 새 사진을 고름 | `images` 파트 1~5개 | 기존 사진 **전부 교체** | 새 사진 격자(등록과 같다) + 옅은 면 `"저장하면 기존 사진 N장 대신 이 사진 M장이 올라가요."` + `[기존 사진 유지]` |
| `[사진 전부 삭제]` | `removeImages=true` · `images` 파트 없음 | 기존 사진 **전부 삭제** | 지금 사진을 흑백으로 물리고 옅은 면 `"저장하면 기존 사진 N장이 모두 지워져요. 저장한 뒤에는 되돌릴 수 없어요."` + `[기존 사진 유지]` `[새 사진 고르기]` |

- **전부 삭제에 다이얼로그를 띄우지 않는다**(2026-09-27 변경 — 예전 정의는 "체크박스 + 확인 다이얼로그"). 누른 순간 지워지는 게 아니라 **저장 전까지 `[기존 사진 유지]`로 되돌릴 수 있다.** 되돌릴 수 있는 일에 다이얼로그를 띄우면 규칙 2(1.6)를 깬다. 되돌릴 수 없는 순간(저장)은 그 옅은 면이 먼저 말한다
- 체크박스 대신 **버튼**으로 — 체크박스는 "켜 두면 저장할 때 적용"이 눈에 안 보인다. 버튼을 누르면 사진 칸 전체가 "지워질 모양"으로 바뀌어 결과가 먼저 보인다. 빨간 글자 선 버튼(`dangerQuiet`)이지만 면을 칠하지 않는다(빨간 채움은 되돌릴 수 없는 확인 버튼만 — 1.2)
- 사진 속 개인정보 한 줄(SCR-02)은 새 사진을 고를 때(고르기 면 · 새 사진 격자)만 보인다. 이미 올라간 사진에는 두지 않는다
- 교체 · 삭제 뒤 `[기존 사진 유지]`를 누르면 새로 고른 사진과 삭제 선택을 모두 풀고 처음(유지)으로. 새로 고른 사진을 한 장씩 모두 빼도 유지(삭제를 눌러 뒀으면 삭제)로 돌아간다
- 사진이 0장인 글에서는 교체 고지와 `[사진 전부 삭제]`를 **둘 다 두지 않는다.** 알릴 것이 없다 — 등록과 같은 고르기 면
- 포커스 — `[사진 전부 삭제]`를 누르면 그 버튼이 사라지므로 `[기존 사진 유지]`로, 되돌리면 `[사진 전부 삭제]`로 돌아온다. 스크린리더에는 `"저장하면 기존 사진 5장이 모두 지워져요."` · `"기존 사진 5장을 그대로 둬요."`
- **같은 내용을 두 번 묻지 않는다.** 교체 · 삭제는 인라인 한 번이다. 저장 버튼에서 다시 묻지 않는다
- 작성 중 이탈(쓰던 칸 등록부, 1.7) : `고치던 글을 두고 나갈까요?` / `"나가면 고친 내용은 저장되지 않아요. 글은 고치기 전 그대로 남아요."` · `[수정 취소]`(고친 게 있을 때만) : `수정을 취소할까요?` / `"고친 내용이 사라져요. 글은 고치기 전 그대로 남아요."`
- 로그인이 끊기면 SCR-02 와 같다(`post-draft:v1:edit:{id}`, 만료일 때만). "전부 삭제"를 눌러 둔 것은 파일이 필요 없어 되살린다. 새로 고른 사진은 보관하지 못한다. 다른 창 로그아웃 · 쓰는 중 로그아웃 확인도 SCR-02 와 같다
- 제출 줄 · 남은 칸 수(`"N곳을 더 채워야 저장돼요"`) · 연락처 감지 · 예시 · 글자 수 · 선택 표시는 SCR-02 와 같다

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 로그인 확인 · 기존 값을 불러오는 동안 **폼 모양 스켈레톤**. 빈 폼을 먼저 보여주지 않는다 — 사용자가 입력을 시작해버린다 |
| 비어 있음 | 없는 글(404 · 받아 주지 않는 id · 숫자가 아닌 주소) → 상세와 같은 빈 상태 `"없거나 삭제된 글이에요."` / `"주소가 맞는지 확인하거나 목록에서 다시 찾아보세요."` + `[목록으로]` |
| 오류 | 불러오기 실패는 서버 `message` + `[다시 시도]`. 저장 실패는 SCR-02 와 같다(필드별 인라인 · 제출 위 한 줄) |
| 권한 | 작성자가 아니면 **이 화면을 렌더하지 않는다.** 스켈레톤인 채로 상세로 되돌리고 알림. 비로그인은 로그인으로(돌아온다) |

**예외**

| 상황 | 화면 |
|---|---|
| 403 `FORBIDDEN_ACCESS`(저장 중) | 상세로 이동(기록을 바꿔) + 알림 `message` |
| 404 `POST_NOT_FOUND`(저장 중) | 목록으로 이동 + 알림 `message`. 수정하는 동안 다른 기기에서 지운 경우다 |
| 400 `EXCEEDED_IMAGE_COUNT` | 교체 후에도 5장을 넘으면 서버가 막는다. UI가 먼저 막으므로 도달하면 안 된다 |
| 401 | 인터셉터 재발급 → 실패 시 글자를 보관하고 로그인으로(SCR-02 "로그인이 끊겼을 때") |

> **확인한 것(2026-09-27, 목 서버 multipart 로그)** — 유지 : 필드 6개만(`type` `title` `content` `category` `location` `lostFoundDate`) · 교체 : 필드 6개 + `images` 파트 2개(`image/jpeg`, 줄인 뒤 약 350KB) · 삭제 : 필드 6개 + `removeImages=true`, 파일 파트 없음. 등록 : 필드 6개 + `images` 3개(PNG 는 JPG 로 바뀌어 `screenshot_airpods.jpg`, 4032px 1.7MB → 233KB)

### SCR-05 · 로그인 · `/login`

| 항목 | 내용 |
|---|---|
| **대응** | `[3.2]` 로그인 → `POST /api/auth/login` |
| **권한** | 비로그인. 이미 로그인 상태면 `redirect` 또는 `/`로 보낸다(기록을 바꿔치기 — 뒤로가기가 로그인 화면으로 오지 않는다) |
| **구현** | 2026-09-26 단계 2 — `pages/login/LoginPage` · `features/auth/ui/LoginForm` · 공통 틀 `AuthLayout` |

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| 헤더 `[로그인]` · 로그인 필요 화면 진입 차단 · 세션 만료 · 비밀번호 변경 후 · 가입 직후 로그인 실패 · 상세의 로그인 권유 칸(`#comments`) | 성공 → `redirect` 쿼리의 경로, 없으면 `/`. 상세로 돌아가면 받아 둔 진입 상태를 되돌려 준다 |
| | `회원가입` → `SCR-06` (`redirect`와 진입 상태를 물고 간다 — **기록을 바꿔치기**(replace)해 로그인 칸이 기록에 쌓이지 않는다, API2-13) |
| | 잠금(423) 안내의 `로그인 없이 목록 보기` → `SCR-01` |

**돌아갈 곳(`?redirect=`)** — 우리 앱 안의 경로만 따른다(열린 리다이렉트 방지, `app/authRedirect.ts`).
`/`로 시작하고 `//` · `\` · 제어 문자가 없고, 같은 출처로 풀리며, `/login` · `/signup`이 아닐 때만. 나머지는 전부 `/`. 조각은 `#comments` 하나만 남긴다(1.5).

**헤더** — 로그인 · 가입 화면에서는 헤더 `[로그인]`을 숨기되 자리는 남긴다(1.10 — 지금 그 화면이다).

**진입 상태 들고 다니기**(2026-10-03 회의 API2-2) — 상세에서 왔으면(`redirect`가 글 상세) 기록 state 의 `returnEntry`를 **모양 검사 뒤 새로 만든 값만**(`readReturnEntry`) 받아, 로그인에 성공하면 상세로 돌려준다. 그래야 돌아온 상세의 `[목록으로]`가 뒤로 가기가 된다. 기록 state 는 누구나 만들 수 있어 그대로 넘기지 않는다.

- **돌아갈 곳을 누르기 전에 알린다** — `로그인하면 분실 글 올리기로 돌아가요.` 한쪽 개념에 묶인 곳(`/posts/new?type=LOST|FOUND`)이면 그 색을 옅게 입힌다(분실 마리골드 · 습득 코발트). 이름을 아는 곳 : 글 올리기 · 분실/습득 글 올리기 · 글 수정 · 보던 글 · 설정 · 내가 쓴 글 · 보던 목록. 모르는 곳이면 줄을 띄우지 않는다
- 비밀번호 보기/숨기기(설정 화면과 같은 칸 `PasswordInput`). 불안한 상태에서 한 손으로 입력하다 오타가 나고, **5회 실패하면 30분이 잠긴다**
- 자동완성 · 붙여넣기를 막지 않는다 — 이메일 `type="email"` · `inputmode="email"` · `autocomplete="email"` · 대문자 자동 · 맞춤법 끔, 비밀번호 `autocomplete="current-password"`
- 검사는 칸을 벗어날 때(이메일 형식)와 제출할 때. 보내기 전 검사 문장은 프론트가 짓는 문장이라 **해요체**다(2026-10-03 회의 RV-7 · ⑦, `features/auth/model/validation.ts`) — `이메일을 적어 주세요` · `이메일 형식이 맞지 않아요. 예: name@example.com` · `비밀번호를 적어 주세요`. 첫 낱말은 칸 이름(서버 문장을 칸에 붙이는 규칙과 같다). 서버가 같은 이유로 막으면 서버 문장(합니다체)이 그대로 온다. 칸을 벗어나며 생긴 이메일 오류만 바로 읽어 준다. 로그인은 비밀번호 길이를 보지 않는다 — 서버도 보지 않는다
- 이메일 형식은 **점 없는 도메인(`a@gmail`)도 막는다.** 서버 `@Email`은 받아 주지만 사람이 쓰는 주소에 그런 건 없고 대개 `.com`을 빠뜨린 오타다
- **넓은 화면(60rem~)은 두 칸** — 왼쪽 제목 · 돌아갈 곳 · 글 두 갈래 안내(`PostTypeGuide` : 분실 · 습득 이름표 + 무엇을 올리는지 한 줄), 오른쪽 폼(26rem). 가운데 좁은 칸만 덩그러니 남지 않게 하되 장식 도형은 두지 않는다. 안내의 이름표는 목록 카드와 같은 컴포넌트다. 휴대폰에서는 안내를 두지 않고(폼이 먼저), 태블릿(48~60rem)은 폼 아래에 둔다. 문서 순서는 늘 폼 뒤다
- 폭을 채운 주 버튼 — 엄지가 어디를 눌러도 닿는다. 전환 링크는 가는 선 아래 글자 링크(밑줄 · 굵게, 누르는 면적 44px)
- 추후 OAuth(구글 · 네이버) 자리 — 미구현. 버튼을 만들지 않는다(눌러도 아무 일 없는 버튼 금지). `AuthLayout`의 `alternatives`에 버튼 묶음을 넘기면 폼 아래에 `또는` 구분선과 함께 끼워지고, 폼 · 전환 링크 자리는 그대로다

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 제출 중 버튼 잠금(`aria-disabled`, 누름 무시) + `"확인 중…"`, 입력은 읽기 전용. 성공한 뒤 화면이 넘어갈 때까지 잠근 채로 둔다 |
| 비어 있음 | 해당 없음 |
| 오류 | 아래 예외 표. **입력한 이메일은 남긴다** |
| 권한 | 로그인 상태로 들어오면 이 화면을 보여주지 않고 되돌린다 |

**동작과 결과 고지** — 되돌릴 수 없는 동작이 없다.
단 **"5회 실패하면 30분 잠깁니다" 같은 예고를 미리 띄우지 않는다.** 아직 일어나지 않은 일이고, 정상 사용자에게 겁을 준다. 잠긴 뒤에 서버 메시지로 알린다.

|---|---|---|
| 보내기 전 검사 실패 | 해당 칸 아래 | 첫 번째로 틀린 칸 |
| 401 `INVALID_CREDENTIALS` | **폼 맨 위 한 줄**(옅은 면 + 아이콘 + 서버 문장). 어느 쪽이 틀렸는지 구분해 알리지 않는다 — 계정 존재 여부가 새어나간다. 로그인의 401은 재발급을 타지 않는다(`skipAuth`) | 비밀번호 칸, 글자 전체 선택(바로 다시 친다) |
| **423 `ACCOUNT_LOCKED`** | 폼 맨 위 **잠금 안내**(자물쇠 + 서버 문장 + `다른 계정은 이메일을 바꿔 로그인할 수 있어요.` + `로그인 없이 목록 보기`). 비밀번호 칸을 잠그고 로그인 버튼은 흐리게 두고 누름을 무시한다(`unavailable` — 포커스가 남고 잠금 안내를 설명으로 읽는다). **잠금은 이메일 단위라 이메일을 바꾸면 풀린다**(2026-09-26 개선 — 폼 전체를 잠그면 다른 계정까지 막힌다). 서버가 남은 시간을 주지 않아 **프론트가 세지 않는다**(잠긴 시각을 모른다 — 지금부터 30분이 아니다) | 잠금 안내 |
| 400 `INVALID_INPUT` | 서버 문장이 가리키는 칸 아래(문장이 `이메일` · `비밀번호`로 시작한다). 모르면 폼 위 한 줄 | 그 칸 |
| 응답 없음 · 500 | 폼 위 한 줄 | 그 줄 |
| 세션 만료로 들어옴 | 폼 위 `"로그인이 만료됐어요. 다시 로그인해 주세요."` — 등록 · 수정 화면 · 상세의 댓글 칸 · 내가 쓴 글이 보낸다(쓰던 글 · 댓글을 보관했으면 `"로그인하면 쓰던 글(댓글)을 이어서 쓸 수 있어요."`가 붙는다). 다른 창에서 로그아웃했으면 `"다른 창에서 로그아웃했어요."`. 다른 화면은 조용히 비로그인 | |
| 비밀번호 변경 후 들어옴 | 폼 위 확인 문장 `"비밀번호를 바꿨어요. 다시 로그인해 주세요."`(체크 아이콘) — 설정 화면이 `navigate(paths.login, { state: { notice } })`로 넘긴다 | |
| 가입은 됐는데 이어진 로그인만 실패 | 폼 위 `"가입했어요. 로그인해 주세요."` + 이메일 칸 미리 채움(비밀번호는 기록에 싣지 않는다) | |

> **423 잠금 화면은 그 자리에서 스크린샷을 남긴다.** 재현하려면 계정 하나를 5회 실패시키고 30분을 기다려야 한다.

### SCR-06 · 회원가입 · `/signup`

| 항목 | 내용 |
|---|---|
| **대응** | `[3.1]` 회원가입 → `POST /api/auth/signup` (+ 이어서 `[3.2]` 로그인) |
| **권한** | 비로그인. 로그인 상태로 들어오면 `redirect` 또는 `/`로 되돌린다 |
| **구현** | 2026-09-26 단계 2 — `pages/signup/SignupPage` · `features/auth/ui/SignupForm` · `useSignup` |

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| `SCR-05`의 `회원가입` 링크(`redirect`를 물고 온다) | 성공(201) → **방금 입력한 값으로 바로 로그인** → `redirect`의 경로, 없으면 `SCR-01` |
| | 가입은 됐는데 이어진 로그인만 실패 → `SCR-05` + `"가입했어요. 로그인해 주세요."` + 이메일 채움(진입 상태도 같이) |
| | `로그인` → `SCR-05` (`redirect`와 진입 상태를 물고 간다, 기록을 바꿔치기 — SCR-05 와 같다) |

> **가입 뒤 동선 판단(2026-09-26)** — 예전 정의는 "로그인 화면으로 보내며 안내, 자동 로그인하지 않는다(응답에 토큰이 없다)"였다.
> 바꾼 이유 : 방금 친 이메일 · 비밀번호를 다시 치게 하는 것은 사용자에게 아무것도 주지 않고 한 화면을 더 거치게 한다. 토큰이 없는 것은 `[3.2]`를 한 번 더 부르면 된다.
> 두 요청이 끝날 때까지 버튼은 잠긴 채다. 목록으로 갈 때는 **온보딩 신호**(`PostListEntryState { justSignedUp: true }`)를 기록에 싣는다 — 목록이 이것을 보고 온보딩 1층(`docs/온보딩설계.md` 3장)을 한 번 띄우고(`onboarding:v1:done`이 없을 때만), 신호는 읽자마자 기록에서 지운다(새로고침 · 뒤로가기로 다시 뜨지 않는다).
> `redirect`가 있으면(예: 글 올리기에서 로그인 → 가입) 온보딩보다 원래 하려던 일이 먼저다 — 그곳으로 간다.

**구성 요소**

```
회원가입
분실 글과 습득 글을 올리고, 댓글로 연락할 수 있어요.
+-----------------------------------+
| 이메일    [                    ]  |
| 로그인할 때 써요. 다른 사람에게는 보이지 않아요.   <- 도움말(오류가 뜨면 숨는다)
| 비밀번호  [                 ][보기]|
| 8~20자                             |   <- 오류가 떠 있는 동안 숨는다(1.7)
| 닉네임                     0/20   |
|           [                    ]  |
| 글과 댓글에 이 이름이 보여요. 가입한 뒤 설정에서 바꿀 수 있어요.
|          [ 가입하기 ]              |
| 이미 계정이 있나요?  로그인          |
+-----------------------------------+
넓은 화면 : SCR-05와 같은 두 칸(왼쪽 제목 · 글 두 갈래 안내)
```

- 입력은 셋뿐이다. **비밀번호 확인 필드를 두지 않는다** — 보기 토글이 같은 역할을 하고, 필수 입력을 늘리지 않는 것이 이 서비스의 규칙이다
- 규칙은 백엔드 `SignupRequest`와 같다 — 이메일 `@NotBlank` · `@Email` · 100자, 비밀번호 `@NotBlank` · 8~20자(문자 종류 규칙 없음), 닉네임 `@NotBlank` · 20자(DB `VARCHAR(20)`). 보내기 전 검사 문장은 해요체(`이메일은 100자까지 쓸 수 있어요` · `비밀번호는 8~20자로 적어 주세요` · `닉네임을 적어 주세요` · `닉네임은 20자까지 쓸 수 있어요`), 서버가 막으면 서버 문장 그대로. 벗어나며 생긴 오류만 바로 읽어 준다(1.7)
- 닉네임은 **보내기 전에 앞뒤 공백을 자른다**(서버는 자르지 않고 저장한다). 공백만 있으면 `닉네임을 적어 주세요`. 글자 수는 16자(80%)부터 `n/20` · `maxLength`
- 비밀번호에는 `maxLength`를 두지 않는다 — 붙여 넣은 긴 비밀번호가 조용히 잘리면 가입한 비밀번호를 본인도 모른다. 넘치면 벗어날 때 알린다. `autocomplete="new-password"`
- 이메일 · 닉네임 도움말은 **무엇이 공개되는지** 알린다 — 목록 · 상세 응답에 이메일이 없고(`PostListResponse` · `PostDetailResponse`), 닉네임은 글 · 댓글에 보인다
- 이메일 · 닉네임 중복은 **제출해야 안다.** 실시간 중복확인 엔드포인트가 백엔드에 없다. 임의로 만들지 않는다
- 추후 OAuth(구글 · 네이버) 자리 — 미구현. SCR-05와 같은 `alternatives` 자리

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 제출 중(가입 + 이어진 로그인) 버튼 잠금(`aria-disabled`) + `"가입하는 중…"`, 입력은 읽기 전용. 성공 뒤에도 화면이 넘어갈 때까지 잠근다 — 두 번째 요청이 `DUPLICATE_EMAIL`로 돌아오지 않게 |
| 비어 있음 | 해당 없음 |
| 오류 | 필드별 인라인. 칸을 벗어날 때 검사(비어 있으면 지나가는 중일 수 있어 제출 때까지 기다린다), 칸을 고치면 그 칸의 오류가 걷힌다 |
| 권한 | 로그인 상태로 들어오면 되돌린다 |

**동작과 결과 고지** — 되돌릴 수 없는 동작이 없다. 다이얼로그를 띄우지 않는다.

**예외** — 실패하면 포커스가 첫 번째로 틀린 칸으로 간다

| 상황 | 화면 |
|---|---|
| 409 `DUPLICATE_EMAIL` | **이메일 필드 아래** `"이미 사용 중인 이메일입니다"` |
| 409 `DUPLICATE_NICKNAME` | **닉네임 필드 아래** `"이미 사용 중인 닉네임입니다"` |
| 400 `INVALID_INPUT` | 서버 문장이 가리키는 칸 아래(`이메일` · `비밀번호` · `닉네임`으로 시작). 모르면 폼 위 한 줄 |
| 응답 없음 · 500 | 폼 위 한 줄, 포커스는 그 줄 |

### SCR-07 · 내가 쓴 글 · `/me`

| 항목 | 내용 |
|---|---|
| **대응** | `[6.1]` 마이페이지 → `GET /api/members/me/posts?status=&page=&size=` — 백엔드 PR #25(2026-09-27) |
| **응답** | 목록과 같은 `PagedModel<PostListResponse>`(`thumbnailUrl` 포함). 정렬은 서버가 `createdAt desc, id desc`로 고정. `status`를 빼면 전체 |
| **권한** | **로그인 필요.** 비로그인 진입 시 `/login?redirect=/me…`(보던 탭까지). 세션을 되살리는 동안은 같은 모양의 스켈레톤이고, 요청은 로그인이 확인된 뒤에 나간다 |

**진입 · 이탈**

| 어디서 들어오나 | 어디로 나가나 |
|---|---|
| 헤더 계정 메뉴 `내가 쓴 글` · 로그인 뒤 돌아옴(`?redirect=`) | 카드 → `SCR-03`(기록 상태 `from: 'mine'` — 상세의 되돌아가기가 `내가 쓴 글`, 삭제 뒤 보던 탭으로) |
| 상세에서 뒤로 · 삭제 뒤 | 빈 상태 [분실 글 올리기] · [습득 글 올리기] → `SCR-02`(`?type=`) |
| | 보는 중 로그인이 끊김 → `SCR-05`(까닭 한 줄 · 돌아올 곳) |

**구성 요소**

```
내가 쓴 글
글을 열면 '내 글 관리'에서 상태를 바꾸거나 고칠 수 있어요.
전체 9   게시중 4   연락중 3   완료 2          <- 상태 탭(링크), 고른 탭은 굵은 글자 + 잉크 막대
───────
[사진 피드 — 목록과 같은 PostCard 2 · 3 · 4열]
[페이지]
```

- **카드는 목록(SCR-01)과 같다** — 사진 · 포스터, 사진 위 유형 배지, 연락중 · 완료만 표시(게시중은 표시하지 않는 규칙 그대로), 제목 · 장소 · 분실습득일
- **카드에서 바로 하는 동작은 없다.** 상태 바꾸기 · 수정 · 삭제는 상세의 `내 글 관리` 한 곳에 모았다. 제목 아래 한 줄이 그 자리를 알린다
  - 삭제는 "사진 N장과 댓글 N개가 함께 사라져요"를 쓸 근거(사진 수 · 댓글 수)가 목록 응답에 없다
  - 완료도 같은 다이얼로그를 카드마다 띄우면 같은 경고가 두 곳에 생긴다(1.6 "한 번만")
- 상태 탭은 `?status=OPEN` · `?page=2` 처럼 URL에 싣는다. 탭을 바꿀 때마다 기록이 쌓여 뒤로가기가 직전 탭으로 돌아간다. 기본값(전체 · 1쪽)은 주소에 쓰지 않는다
- 탭은 ARIA 탭이 아니라 **링크 묶음**(`nav` + `aria-current="page"`)이다 — 탭마다 주소가 있어 새 탭 열기 · 새로고침이 된다. 필터 칩(알약, 켜고 끄는 것)과 모양을 가른다 : 글자 + 아래 막대, 색 없음
- 건수 : 상태마다 `size=1`로 물어 `totalElements`만 읽는다. 전체는 셋의 합. 모르는 동안은 숫자 자리 스켈레톤(탭이 옆으로 밀리지 않는다), 못 불러오면 숫자 없이
- 탭을 바꾸면 직전 탭의 글을 흐리게 남겨 두었다가 바꾼다(`keepPreviousData`). 직전 탭이 빈 상태였으면 그 문장을 남기지 않고 스켈레톤. 결과는 `"연락중 글 3건"`으로 알린다(`aria-live`)
- 쪽을 넘기면 탭 줄로 스크롤하고 포커스를 지금 탭에 둔다 — 거기서 Tab 한 번이면 첫 카드다
- 320px에서도 탭 넷이 한 줄에 들어간다(간격이 12px까지 줄어든다). 옆으로 넘기지 않는다 — 숨은 탭이 없다

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 카드 스켈레톤 8개(2 · 4열에서 줄이 찬다) + 탭 숫자 자리 |
| 비어 있음 (글이 아예 없음) | 탭을 그리지 않는다("0 0 0 0"은 소음). `"아직 올린 글이 없어요."` / `"잃어버렸거나 주운 물건을 올리면 여기에 모여요."` + `[분실 글 올리기]`(마리골드) `[습득 글 올리기]`(코발트) |
| 비어 있음 (이 탭 0건) | `"게시중인 글이 없어요."`(올린 글이 모두 연락중이거나 완료예요) · `"연락중인 글이 없어요."`(주인으로 보이는 사람과 이야기를 시작하면 글을 열어 연락중으로 바꿔 두세요) · `"완료된 글이 없어요."`(물건이 주인에게 돌아가면 글을 열어 완료로 바꿔 두세요) + `[전체 보기]` |
| 비어 있음 (끝을 넘은 쪽) | `"5페이지에는 글이 없어요."` / `"이 탭의 글 9건은 앞 페이지에 있어요."` + `[첫 페이지로]` |
| 오류 | `message` + `[다시 시도]`(5xx · 네트워크는 두 번 더 자동 재시도한 뒤) |
| 권한 | 비로그인은 도달하지 못한다. 응답 전체가 내 글이라 `memberId` 비교가 필요 없다 |

**동작과 결과 고지** — 이 화면에는 되돌릴 수 없는 동작이 없다. 상태 변경 · 삭제의 규칙과 문구는 SCR-03 한 곳이다.

**예외**

| 상황 | 화면 |
|---|---|
| 401 | 인터셉터 재발급 → 실패하면 로그인 화면 + `"로그인이 만료됐어요. 다시 로그인해 주세요."`(직접 로그아웃했으면 `"로그아웃했어요."`, 다른 창에서 로그아웃했으면 `"다른 창에서 로그아웃했어요."`) · 돌아올 곳 `내가 쓴 글` |
| 400 (모르는 `status`) | 주소의 모르는 값은 버리고 전체로 보낸다 — 요청까지 가지 않는다 |
| 그사이 상세에서 상태를 바꿈 · 지움 | 목록 캐시와 같은 무효화(`postKeys.lists()`)에 걸려 탭 · 건수가 다시 받아진다 |

### SCR-08 · 설정 · `/settings`

| 항목 | 내용 |
|---|---|
| **대응** | `[3.7]` 조회 → `GET /api/members/me` · `[3.6]` 닉네임 → `PATCH /api/members/me` · 비밀번호 → `PATCH /api/members/me/password` · 화면 모드(백엔드 없음, 1.11) |
| **권한** | **누구나 들어온다.** 화면 모드는 기기 설정이라 비로그인도 바꾼다. 프로필 · 비밀번호는 **로그인했을 때만** 그린다 |
| **바뀐 점** | 2026-09-26 `/me/settings` "내 정보"에서 옮겼다. 본인 손그림 목업 — 제목 "설정", 맨 위 프로필, 그 아래 "밝게" · "어둡게" 두 칸(칸 안에 화면 축소 미리보기), 그 아래 비밀번호 변경 |

비로그인일 때 — 프로필 자리에 옅은 면 한 장 `"로그인하면 프로필과 비밀번호를 바꿀 수 있어요."` + `[로그인]`. 비밀번호 섹션은 **숨긴다**(누를 수 없는 폼을 남기지 않는다). 화면 모드는 그대로 있다.

**① 프로필**

- **이메일은 읽기 전용 글자다.** 입력 필드로 만들지 않는다. 로그인 식별자라 변경 대상에서 빠졌다(`[3.6]`)
- 가입일은 `MemberResponse.createdAt`이 있을 때만 보인다
- 닉네임은 20자(`maxLength`, 글자 수 `n/20`). **보내기 전에 앞뒤 공백을 잘라 낸다** — 서버는 자르지 않고 그대로 저장한다
- 바꾼 게 없으면(잘라 낸 값이 지금 닉네임과 같으면) `[닉네임 저장]`을 흐리게 두고 누름 · Enter 를 무시한다(`unavailable`). `disabled`로 잠그면 저장한 순간 누르던 버튼에서 포커스가 빠졌다
- 비었으면 벗어날 때 `"닉네임을 적어 주세요"`(보내기 전 검사 — 해요체, 첫 낱말은 칸 이름. 서버가 막으면 서버 문장 그대로)
- 지금 닉네임과 다르게 고쳐 둔 채 떠나거나 로그아웃하면 묻는다(쓰던 칸 등록부, 1.7)
- 성공하면 이 화면에 머물고 버튼 옆에 `닉네임을 바꿨어요.`(`role="status"`). 헤더 닉네임은 `AuthProvider`가 `members/me` 캐시를 따라 바로 바꾼다
- **프로필 사진 영역 · 이메일 변경 · 회원 탈퇴를 두지 않는다.** 백엔드에 없다

**② 화면 모드**

- "밝게" · "어둡게" 두 칸. **진짜 라디오 두 개**(`role="radiogroup"`, 이름은 섹션 제목) — 화살표 키로 옮기고 스크린리더가 선택 상태를 읽는다
- 칸마다 **그 모드로 그린 목록 화면 축소 도식**(헤더 · 제목 · 두 색 면 · 검색창 · 카드 격자)이 들어간다. 이미지나 캡처가 아니라 실제 토큰으로 그린다 — 칸에 `data-theme`을 붙이면 그 모드의 토큰이 열린다. 장식이라 `aria-hidden`
- 고른 칸은 색만이 아니라 **선 두 겹 + 오른쪽 아래 모서리 표시**로 보인다 — 그림 칸의 선택 표시(등록 화면 종류 칸과 같은 접힌 귀퉁이 — 종류 칸은 오른쪽 위, 이 칸은 미리보기 그림과 겹치지 않게 이름 줄 끝, 2026-10-03 회의 ⑤-a). **동그라미 체크는 쓰지 않는다** — 그건 "완료"의 표시다. 안 고른 칸에는 표시가 없다
- 320px에서도 **나란히** 둔다(칸 138px, 미리보기 122px). 두 모드를 옆에 놓고 비교하는 것이 이 선택의 핵심이다
- 바꾸는 즉시 화면 전체에 적용한다. 되돌릴 수 있는 일이라 **확인 창을 띄우지 않는다**
- **한 번도 고르지 않았으면** 지금 그려지는 모드의 칸이 선택돼 있고, 그 칸의 모서리 표시는 **빈 테** + 이름 옆 `기기 설정` 이름표다(RV-11). 아래 한 줄이 `기기 설정에 맞춰 지금은 … 화면이에요.`라고 알린다. 그 칸을 누르면 그 모드로 **고정**되고 표시가 **채워진다** — 겉모습이 바뀌어야 고정됐다는 것을 안다(고른 적이 없는데 채운 표시를 두면, 밤에 기기가 어둡게 바뀌어도 앱이 흰 채로 남는 까닭을 모른다). 상태 셋은 `ThemePicker.state.ts`(`fixed` · `following` · `off`)
- 고른 뒤에는 `기기 설정과 상관없이 늘 … 화면으로 보여요.` + 글자 버튼 `[기기 설정 따르기]`. 누르면 저장값을 지우고 포커스를 선택된 칸으로 옮긴다. 목업이 두 칸이라 세 번째 칸("기기 설정")은 만들지 않았다

**③ 비밀번호 변경**

- 현재 비밀번호 · 새 비밀번호(8~20자) 두 칸, 각각 **보기/숨기기**(44px, `aria-pressed`). 한 손으로 치다 오타가 나고, 로그인은 5회 실패하면 잠긴다
- 비밀번호 관리자가 계정을 알아보도록 숨긴 아이디 칸(`autocomplete="username"`)을 둔다. `current-password` · `new-password`를 정확히 단다
- 비밀번호는 공백을 자르지 않는다
- 새 비밀번호는 `maxLength`를 두지 않고(가입과 같다 — 붙여 넣은 긴 비밀번호가 조용히 잘리면 바꾼 비밀번호를 본인도 모른다) 벗어날 때 길이를 본다(`"새 비밀번호는 8~20자로 적어 주세요"`, 오류가 떠 있는 동안 `8~20자` 도움말은 숨는다). 비어 있으면 제출할 때 알린다(`"현재 비밀번호를 적어 주세요"` · `"새 비밀번호를 적어 주세요"`) — 보내기 전 검사라 해요체, 서버가 막으면 서버 문장 그대로. 첫 틀린 칸으로 포커스
- 두 칸 중 하나라도 글자가 있으면 쓰던 중이다 — 떠나거나 로그아웃할 때 묻는다(등록부에는 있다/없다만, 글자는 넣지 않는다). 바꾸기에 성공해 로그인 화면으로 갈 때는 묻지 않는다(이미 끝난 일이다)

**④ 로그아웃 — 화면 끝**(2026-10-03 회의, 로그인했을 때만)

- 비밀번호 변경 아래, **선 하나 + 24px**로 뗀 조용한 `[로그아웃]` — 선만 두른 보조 버튼 하나, 섹션 제목을 달지 않는다(섹션이 아니라 나가는 문). 칠하지 않는다(이 화면의 채움은 저장 · 바꾸기다). 테 없는 글자 버튼은 섹션 제목처럼 읽혀 누를 수 있는지 안 보였다
- 바로 아래 4px로 붙은 흐린 한 줄 `"이 기기에서는 7일 동안 로그인이 유지돼요."`(SE-9 — 공용 기기에서 로그아웃해야 하는 이유를 버튼 곁에서 한 번, 버튼의 `aria-describedby`). 7은 백엔드 리프레시 토큰 수명(`REFRESH_TOKEN_DAYS`)이라 백엔드가 바꾸면 같이 바꾼다
- 동작은 계정 메뉴의 `[로그아웃]`과 같다 — 쓰던 글자가 있을 때만 묻는다(1.10). 비밀번호 바꾸기와 다른 묶음이라 되돌릴 수 없는 결과가 있는 버튼 곁에 붙이지 않는다
- `[비밀번호 바꾸기]`는 결과 고지 문장을 설명(`aria-describedby`)으로 가진다 — 스크린리더도 누르기 전에 듣는다

**폼 공통** — 이름은 입력 위, 오류는 입력 바로 아래(`!` 아이콘 + 굵은 글자는 `--error-text` 빨강, 칸 테두리는 잉크 두 배 선 — 빨강은 문장과 아이콘에만, 1.7). 두 폼은 분리하고 저장 버튼도 따로다. 보내는 동안 버튼은 누름만 무시하고(`aria-disabled`) 입력을 읽기 전용으로 둔다(`저장하는 중…` · `바꾸는 중…`). 비밀번호 변경이 연결 실패 · 서버 오류로 끝나면 `[비밀번호 바꾸기]` 위 한 줄(`FormAlert`)로 포커스.

**네 가지 상태**

| 상태 | 화면 |
|---|---|
| 로딩 | 세션 복구 중이거나 내 정보를 불러오는 동안 이메일 · 가입일 · 닉네임 칸 모양의 스켈레톤. 빈 입력창을 먼저 보여주지 않는다 |
| 비어 있음 | 해당 없음 |
| 오류 | 내 정보를 못 불러오면 프로필 자리에 오류 상태 + `[다시 시도]`. 저장 실패는 필드별 인라인 |
| 권한 | 비로그인에게 프로필 · 비밀번호를 **숨긴다**(로그인 권유 한 장). 화면 모드는 누구에게나 |

**동작과 결과 고지** — 둘 다 **인라인**이다. 되돌릴 수 있는 동작에 다이얼로그를 띄우지 않는다.

| 대상 | 문구 | 위치 |
|---|---|---|
| 닉네임 변경 | `"닉네임을 바꾸면 지금까지 쓴 글과 댓글의 이름도 함께 바뀌어요."` | 닉네임 입력 아래, 저장 버튼 위. 상시(결과 고지 `note` — 오류가 떠도 남는다) |
| 비밀번호 변경 | `"비밀번호를 바꾸면 이 기기를 포함해 로그인된 모든 기기에서 로그아웃돼요."` | 새 비밀번호 아래, 저장 버튼 위. 상시 |
| 로그아웃 | `"이 기기에서는 7일 동안 로그인이 유지돼요."` · 쓰던 글자가 있을 때만 확인 창 | `[로그아웃]` 바로 아래 |
| 화면 모드 | 고지 없음 — 누르면 바로 보이고, 다시 누르면 돌아간다 | |

- 비밀번호 변경이 전 기기를 로그아웃시키는 건 `MemberService.updatePassword()`가 `refreshTokenService.delete(memberId)`로 리프레시 토큰을 폐기하기 때문이다. **사용자가 예상하지 못하는 결과라 반드시 알린다**
- 204를 받으면 메모리 토큰 · 회원 캐시 · 로그인 상태를 비우고(`useUpdatePassword`) 로그인 화면으로 보낸다. 이미 발급된 액세스 토큰이 최대 5분 살아있지만 **화면은 즉시 로그아웃된 것처럼 동작한다.** 알린 내용과 화면이 어긋나면 안 된다
- 현재와 같은 닉네임으로 저장하면 서버가 200을 준다(멱등). 화면은 바꾼 게 없으면 애초에 보내지 않는다

| 400 `INVALID_INPUT` | 닉네임은 그 필드 아래. 비밀번호는 어느 칸인지 모르므로 `[비밀번호 바꾸기]` 위 한 줄 |

| 저장소가 막힌 브라우저 | 화면 모드는 이 탭에서만 바뀌고, 새로고침하면 기기 설정으로 돌아간다. 오류를 띄우지 않는다 |

| **권한** | 비로그인 가능 |
| **진입 · 이탈** | 정의되지 않은 경로 · 오타 · 오래된 링크 → `[목록으로]` · `[뒤로]`(앱 안에서 넘어왔을 때만) |

**구성 요소** — 다른 화면처럼 **왼쪽 정렬 페이지 제목으로 시작한다**(설정 · 글 올리기와 같은 머리, 2026-10-03 회의 UI-10 d). 예전의 회색 판 가운데 작은 글은 화면 아래 절반을 비워 "고장 난 화면"처럼 보였다. 다른 점은 **어떤 주소로 왔는지**를 보여 준다는 것.

```
없는 화면이에요.                              <- h1, 왼쪽 정렬(읽는 폭 700px)
[주소  /post/12]                              <- 이름표(4px) 모양 한 줄. 경로만 · 40자에서 말줄임
주소가 맞는지 확인하거나 목록에서 다시 찾아보세요.
[목록으로]  [< 뒤로]                           <- 주 동작이 먼저
```

- **주소는 경로만 · 한 줄 · 40자까지**(2026-10-03 보안 결정 SE-7) — 쿼리 · 조각은 보여 주지 않는다. 쿼리까지 풀어 여러 줄로 보여 주면 `/고객센터-점검-중-02-000-0000으로-연락하세요` 같은 링크가 우리 도메인 화면에 그 문장을 띄운다(콘텐츠 위조). `%인코딩`은 풀어서 보여 주고(풀 수 없으면 그대로), 글자(코드 포인트) 수로 자른다 — 한글 · 그림 글자가 반쪽으로 잘리지 않게. 넘치면 끝에 `…`. 칸 폭에서도 한 줄 말줄임이라 화면을 밀어 넓히지 않는다
- 주소는 글자로만 보여 준다(링크로 만들지 않는다). 잘못 적힌 한 글자(`/post/12` · `/posts/12/edits`)를 사용자가 직접 알아볼 수 있다
- 나갈 문 둘 : `[목록으로]`(늘 있다 — 막다른 길이 없다, 주 버튼, 먼저) · `[뒤로]`(앱 안에서 넘어왔을 때만 — 주소창 · 바깥 링크로 바로 열었으면 돌아갈 곳이 이 앱 밖이다)
- 아이콘 · 포스터 그림은 쓰지 않는다. 꼬리표 모양은 로고 · '기타' 포스터에만 쓰는 규칙(1.10)이고, 없는 화면에 물건 그림은 뜻이 없다
- 탭 제목 `없는 화면 | 분실물 찾기`. 화면이 4px 떠오르며 나타난다(모션 줄이기면 즉시)

**네 가지 상태** — 이 화면 자체가 다른 화면의 "비어 있음" 상태에 해당한다. 네 상태를 따로 갖지 않는다.

**동작과 결과 고지** — 없다.

**예외** — 없다. 배포에서 `/posts/3` 직접 접근이 S3의 403으로 새지 않도록, 기본 동작(`/*`)에만 붙인 CloudFront Function이 확장자 없는 주소를 `/index.html`로 돌린다(`deploy/cloudfront/spa-rewrite.js`, 기능명세서 11장). 커스텀 오류 응답(403/404 → `/index.html`)은 쓰지 않는다 — 배포 전체에 걸려 `/api/*`의 403 · 404까지 HTML이 된다. `/posts/1.5`처럼 숫자 뒤 점은 확장자로 보지 않아 앱으로 와서 "없는 글"이 된다

## 4. 백엔드 미구현 정리

화면은 정의됐지만 엔드포인트가 없어 지금 붙일 수 없는 것들이다. **프론트에서 임의로 만들지 않는다.**
`[5.1]` 댓글(등록 · 더 보기 · 수정 · 삭제)은 백엔드 PR #22 로 머지돼 2026-09-27 SCR-03 에 붙였다.
`[6.1]` 마이페이지(`GET /api/members/me/posts`)는 PR #25 로 머지돼 2026-09-27 SCR-07 에 붙였다. **지금 남은 미구현은 없다.**

의도적으로 **만들지 않은** 화면 — 백엔드에 없고 명세서에도 없다.

| | 이유 |
|---|---|
| 이메일 변경 | 로그인 식별자라 변경 대상에서 제외(`[3.6]`) |
| 프로필 사진 | `MEMBER` 테이블에 컬럼이 없다. DB 명세서 7장 확장성에 10/20 배포 이후 항목으로 올라 있다 |
| 회원 탈퇴 · 비밀번호 찾기 · 게시글 신고 | 명세서에 없다 |

프론트 구현에 영향을 주는 백엔드 사실 두 가지.

- `LoginResponse`에 회원 식별자가 없다(`accessToken` `tokenType` `accessTokenExpires`). 로그인 직후 `GET /api/members/me`를 한 번 더 호출해야 작성자 판정과 헤더 닉네임 표시가 가능하다
- 리프레시 쿠키의 `secure(true)`가 `AuthService`에 하드코딩돼 있다. 브라우저에 따라 로컬 개발에서 쿠키가 저장되지 않아 `[3.3]` 재발급이 막힐 수 있다(기능명세서 8장이 이미 지적한 항목)

## 5. 스크린샷 체크리스트

이 프로젝트는 백엔드 포트폴리오이고, 프론트는 "찍을 화면이 없다"는 약점을 메우는 수단이다.
**조건을 다시 만들기 어려운 화면은 만든 그 자리에서 찍는다.**
