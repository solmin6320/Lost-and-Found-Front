# 온보딩 설계

처음 가입한 사용자에게 **이 서비스가 무엇이고 무엇을 할 수 있는지** 알려주는 안내.

---

## 1. 무엇을 풀려는 문제인가

분실물 서비스는 첫 화면이 **글 목록**이다. 처음 온 사람에게는 이게 보인다.

- 카드에 붙은 **노랑/파랑 배지가 뭘 뜻하는지** 모른다 — 이 서비스의 가장 중요한 개념인데
- 내 물건을 **찾으러** 온 건지 **주운 걸 올리러** 온 건지에 따라 할 일이 정반대인데, 화면은 같아 보인다
- 상태(게시중·연락중·완료)가 뭘 의미하는지 모른다

즉 **기능 사용법**이 아니라 **개념**을 먼저 심어야 한다. 버튼 위치는 누르다 보면 알게 되지만, "습득물"이 뭔지는 알려주지 않으면 모른다.

---

## 2. 원칙

### 짧게, 그리고 한 번만

게임 튜토리얼이 실패하는 이유는 길기 때문이다. **3단계를 넘기지 않는다.** 4단계째부터 이탈률이 급격히 올라가고, 끝까지 봐도 정작 필요한 순간에는 기억나지 않는다.

### 순차 투어에만 의존하지 않는다

온보딩은 **두 층**으로 간다.

| 층 | 언제 | 무엇 |
|---|---|---|
| **1층 — 첫 진입 안내** | 가입 직후 1회 | 개념 3가지. 스킵 가능 |
| **2층 — 맥락 안내** | 그 기능을 처음 쓸 때 | 빈 상태 문구, 인라인 힌트, 입력 도움말 |

2층이 실제로 더 많이 작동한다. 사용자가 **그 기능 앞에 서 있을 때** 설명이 나오기 때문이다. 1층만 만들고 끝내지 않는다.

### 스킵을 방해하지 않는다

- 모든 단계에 **건너뛰기**가 보인다. 숨기거나 흐리게 하지 않는다
- ESC, 바깥 클릭으로 닫힌다
- 닫아도 다시 볼 수 있어야 한다 — 헤더의 `서비스 안내`(물음표). 메뉴 속이 아니라 헤더에 늘 보인다

### 되돌릴 수 없는 동작은 온보딩으로 설명하지 않는다

"완료로 바꾸면 되돌릴 수 없다"는 **그 버튼을 누르는 순간** 말해야 한다. 가입 첫날 본 안내는 2주 뒤 그 버튼 앞에서 기억나지 않는다. 이건 `front-design-rules` 의 결과 고지 규칙이 담당한다.

## 3. 1층 — 첫 진입 안내 (3단계)

가입 성공 후 목록 화면(`SCR-01`)으로 이동한 직후 1회. 헤더 `서비스 안내`로 언제든 다시 연다.

| 단계 | 제목 | 보조 문장 | 가리킬 것 (`data-guide`) |
|---|---|---|---|
| 1 | 먼저 내 상황을 골라요 | 잃어버렸다면 누군가 주워 둔 물건을, 주웠다면 주인이 찾는 물건을 모아 보여 드려요. + 실제 배지 `[분실] 잃어버린 물건` `[습득] 주운 물건` | **목록 맨 위 의도 선택 두 칸**(`intent`) |
| 2 | 물건 이름으로 찾아요 | 카테고리, 상태, 장소, 기간으로 더 좁힐 수 있어요. | 검색창 + 필터 칩(`finder`) |
| 3 | 찾는 물건이 없으면 글을 올려요 | 사진과 장소를 남기면 본 사람이 알아볼 수 있어요. | 헤더 `[+ 글 올리기]`(`create`) |

**개념 → 탐색 → 행동** 순서다. 마지막 단계가 행동 유도로 끝나야 온보딩이 다음 동작으로 이어진다.

### 1단계가 가리키는 대상 — "첫 카드의 유형 배지" → "의도 선택 두 칸" (2026-09-26 변경)

옛 판은 목록 첫 카드의 유형 배지를 가리켰다. 목록 재설계(2026-09-25) 뒤로는 맨 위 의도 선택이 서비스의 구조다.

- **이 서비스의 첫 개념은 "내가 잃어버렸나, 주웠나"다.** 배지 색은 그 결과로 붙는 표시일 뿐이다. 의도 칸은 고르는 순간 무엇을 보게 되는지(엇갈림 — 잃어버렸어요 → 주워진 물건)까지 한 번에 보여 준다
- **늘 그 자리에 있다.** 첫 카드는 글이 0건이면 없고, 불러오는 중에는 스켈레톤이며, 필터에 따라 바뀐다. 의도 칸은 어떤 상태에서도 같은 자리다
- 배지 색은 버리지 않았다 — 1단계 카드 안에 **실제 배지 두 개**(`TypeBadge`)를 넣어 "노랑 = 잃어버린 물건, 파랑 = 주운 물건"을 목록과 같은 모양으로 보여 준다. 더 자세한 뜻(연락중 · 완료)은 2층의 `이름표 안내`가 맡는다

### 표현 방식

- **테 하나로만 강조한다.** 대상 둘레에 잉크 2px + 아주 옅은 번짐 한 겹(반경 12px, 대상과 4px 간격). 화면을 어둡게 덮는 스포트라이트는 쓰지 않는다 — 뒤의 화면이 그대로 보여야 "이게 그 자리구나"가 이어지고, 어두운 막은 첫 화면의 두 색 면을 죽인다
- **좁은 화면(< 48rem)은 바텀 시트.** 필터 시트와 같은 모양으로 아래에서 올라오고, 엄지가 닿는 곳에 `[다음]`이 온다. 대상에는 테만 두른다
- **넓은 화면은 대상 근처의 작은 카드**(22rem). 아래가 먼저, 모자라면 위. 대상이 화면 오른쪽이면(헤더의 `[글 올리기]`) 오른쪽 끝을 맞춘다
- 대상이 보이는 곳(헤더 아래 ~ 시트 위) 밖이면 **부드럽게 스크롤**해 헤더 바로 아래로 데려온다. 스크롤이 끝나면 테와 카드가 나타난다. 헤더 안의 대상은 늘 보이니 스크롤하지 않는다
- 진행 표시는 **짧은 막대 세 칸**(지나온 곳까지 잉크). 스크린리더에는 "3단계 중 1단계"
- 버튼 : `[건너뛰기]`(1 · 2단계, 왼쪽 끝) · `[이전]`(2 · 3단계) · `[다음]` / 마지막은 `[시작하기]`. 카드 바깥을 눌러도 닫힌다
- 모션 : 테는 투명도만, 넓은 화면 카드는 6px 떠오르며, 좁은 화면은 단계가 바뀌면 글만 4px · 200ms. 시트가 처음 열릴 때만 아래에서 올라온다. 모션 줄이기면 전부 즉시, 스크롤도 즉시

### 접근성

- 네이티브 `<dialog>`의 `showModal()` — 바깥이 inert가 된다. 막(backdrop)은 투명하다
- **포커스를 카드 안에서 돌린다.** 마지막 버튼에서 Tab → 첫 버튼, 첫 버튼에서 Shift+Tab → 마지막 버튼(네이티브 모달은 주소창으로 빠진다)
- 열리면 `[다음]`에 포커스. `[이전]`이 사라지면(1단계) `[다음]`으로 옮긴다
- Esc로 닫기. 닫으면 **연 자리로 포커스가 돌아간다** — 헤더 `서비스 안내`. 가입 직후처럼 누른 버튼이 이미 사라졌으면 첫 화면 제목(`h1`, `tabIndex=-1`, 링 없음)
- `aria-labelledby`(제목) + `aria-describedby`(보조 문장). 단계가 바뀌면 문장 영역(`aria-live="polite"`)을 스크린리더가 읽는다. 포커스는 `[다음]`에 그대로
- 열려 있는 동안 뒤의 페이지 스크롤을 잠근다(대상까지 데려가는 스크롤은 코드가 한다)

## 4. 2층 — 맥락 안내

각 화면이 스스로 설명한다. 이쪽이 실제 사용률이 높다. **사용자가 직접 연다 — 저절로 떠서 화면을 가리는 안내는 두지 않는다.**

| 위치 | 내용 | 상태 |
|---|---|---|
| 목록 빈 상태(검색 0건) | "조건에 맞는 글이 없어요." / "검색어나 필터를 바꿔 보세요." + `[필터 초기화]` | ✅ 단계 1 |
| 목록 빈 상태(글 자체가 없음) | "아직 올라온 글이 없어요." + `[글 올리기]` · 의도만 걸었으면 반대쪽 글 올리기 | ✅ 단계 1 |
| 의도 칸 | 칸 아래 한 줄 "주워진 물건 12건 보기" — 무엇을 보게 되는지(엇갈림)를 칸 자신이 말한다 | ✅ 단계 1 |
| **목록 결과 제목 줄 `이름표 안내`** | 누르면 펼치는 설명(toggletip). 분실 · 습득 · 연락중 · 완료가 무엇인지 + "이름표가 하나뿐이면 아직 주인을 찾고 있는 글이에요"(게시중은 카드에 표시하지 않는다) | ✅ 2026-09-26 |
| **필터 시트 상태 묶음** | 제목 아래 한 줄 "연락중은 주인으로 보이는 사람과 이야기하는 글, 완료는 주인에게 돌아간 글이에요." | ✅ 2026-09-26 |
| 등록 화면 유형 선택 | 두 칸 아래 한 줄 — 누가 이 글을 보게 되는지. 분실 "물건을 주운 사람이 이 글을 찾아봐요." · 습득 "물건을 잃어버린 사람이 이 글을 찾아봐요." | ✅ 2026-09-27 |
| 등록 화면 사진 | 고르기 면 아래 "사진이 있으면 한눈에 알아볼 수 있어요." · 고른 뒤 "첫 장이 목록에 보이는 대표 사진이에요." ("찾을 확률이 크게 올라가요"는 근거 없는 약속이라 바꿨다) | ✅ 2026-09-27 |
| 등록 · 수정 `쓰는 요령` | 제목 줄 끝, 누르면 펼침 — 유형부터 · 첫 장이 대표 · 사진에 안 보이는 특징 · 전화번호는 적지 말고 댓글로 · 올린 뒤에도 고칠 수 있음. **헤더 `서비스 안내`를 이 화면에서 누르면 이것이 열린다**(쓰던 글을 두고 목록으로 가지 않는다) | ✅ 2026-09-27 |
| 상세 댓글 0건 | "아직 댓글이 없어요." + 유형별 한 줄 — 분실 글 "이 물건을 본 적 있다면 댓글로 알려 주세요." · 습득 글 "내 물건 같다면 댓글로 알려 주세요." · 내 글 "누군가 댓글을 남기면 여기에 보여요." | ✅ 2026-09-27 |
| 상세 댓글 입력 | 입력 아래 한 줄 "누구나 보는 댓글이에요. 전화번호를 적으면 모두에게 보여요." — 연락처를 적기 전에 | ✅ 2026-09-27 |
| 마이페이지 0건 | "아직 올린 글이 없어요" + 글쓰기 | 단계 5 |
| 상태 배지(상세) | 배지 줄 끝 `이름표 안내`(`PostStatusGuide`) — 이 글의 유형 하나 + 상태 셋, 지금 상태에 "지금 이 글의 상태". 끝에 "상태는 글쓴이가 바꿔요. 완료가 되면 더는 바꿀 수 없어요." **헤더 `서비스 안내`를 상세에서 누르면 이것이 열린다** | ✅ 2026-09-27 |

**빈 상태가 곧 온보딩이다.** 별도 UI를 만들지 않고도 설명이 되고, 화면이 비어 보이는 문제도 같이 해결된다.

- 이름표 뜻 문장은 한곳(`features/posts/model/labels.ts`의 `POST_TYPE_MEANING` · `POST_STATUS_MEANING`)에 둔다. 상세 화면도 같은 문장을 쓴다
- **카드 배지 자체를 누르게 하지 않았다.** 카드 전체가 상세로 가는 링크라, 배지를 누르면 설명이 뜨는 것은 숨은 동작이고 휴대폰에서 사진을 누르려다 설명이 뜬다
- `이름표 안내` : 아이콘만(좁은 화면, 이름은 `aria-label` · 마우스 · 키보드 이름표) → 30rem 이상 아이콘 + 글자. 닫히는 때 — 다시 누름 · Esc(버튼으로 포커스) · 바깥 누름 · 포커스가 밖으로. 펼친 내용은 알림 영역이라 스크린리더가 바로 읽는다
- 연락중 배지만 안내 안에서 선 배지다 — 사진 위 변형은 흰 칸이라 흰 판 위에서 테두리가 사라진다(라벨 · 아이콘은 카드와 같다)

## 5. 완료 여부 저장

```js
localStorage.setItem('onboarding:v1:done', '1')
```

- 백엔드에 온보딩 완료 컬럼이 **없다.** 만들 계획도 없다(10/20 일정)
- 기기를 바꾸면 다시 뜬다. 3단계짜리라 감수할 만하다
- **키에 버전을 넣는다.** 나중에 내용을 바꾸면 `v2` 로 올려 다시 보여줄 수 있다
- localStorage 접근은 `try/catch` 로 감싼다. 시크릿 모드나 차단 설정에서 예외가 난다

> 토큰을 localStorage에 두지 않는 규칙(`docs/보안명세서.md` 3장)과 충돌하지 않는다. 온보딩 플래그는 비밀이 아니고, 털려도 잃을 게 없다.

---

## 6. 하지 않을 것

- **4단계 이상의 투어.** 완주율이 떨어지고 정작 필요할 때 기억나지 않는다
- **강제 진행.** 건너뛰기 없는 온보딩은 이탈을 만든다
- **모든 버튼 설명.** 누르면 알 수 있는 건 설명하지 않는다
- **재방문 때마다 띄우기.** 1회 + 명시적 다시 보기
- **비로그인 사용자에게 저절로 띄우기.** 목록은 비로그인도 본다. 저절로는 가입 직후에만 뜬다. 헤더 `서비스 안내`는 비로그인도 누를 수 있다
- **없는 기능 안내.** 쪽지 · 소유 확인 · 알림은 백엔드에 없다. 댓글 쓰기(`[5.1]`)도 아직 없어 1층에서 "댓글로 연락"이라고 약속하지 않는다("본 사람이 알아볼 수 있어요")
- **어두운 막 · 스포트라이트 구멍 · 반복해서 깜빡이는 표시.** 테 하나로 충분하다
