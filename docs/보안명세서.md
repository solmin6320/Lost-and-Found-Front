# 프론트엔드 보안 명세서

분실물 찾기 서비스 프론트엔드(React). 백엔드 보안은 기능명세서 10장이 다룬다.

---

## 0. 대전제 — 클라이언트 코드는 비밀을 지킬 수 없다

이 문서의 나머지를 읽기 전에 이것부터 받아들여야 한다.

**브라우저에 내려간 코드는 전부 사용자의 것이다.** 번들은 내려받아 읽을 수 있고, 변수는 콘솔에서 바꿀 수 있고, 네트워크 요청은 조작할 수 있다. 난독화해도 시간만 벌 뿐이다.

그래서 프론트엔드 보안의 목표는 두 가지뿐이다.

1. **남의 스크립트가 우리 페이지에서 실행되지 않게 한다** (XSS, 공급망)
2. **사용자의 자격 증명이 새어나가지 않게 한다** (토큰 저장, 전송)

여기 들어가지 않는 것 — 로직 숨기기, 화면 숨기기, 도구 차단 — 은 보안이 아니다.

> **모든 권한 판정은 서버가 한다.** 프론트에서 버튼을 숨기는 것은 UX이지 방어선이 아니다. 숨긴 버튼의 API를 직접 호출하면 그만이고, 그때 막는 것은 백엔드의 `@PreAuthorize`와 소유자 검증이다.

---

## 1. 개발자 도구 차단 — 하지 않는다

"F12를 막아달라", "우클릭을 막아달라", "콘솔에 스크립트를 못 넣게 해달라"는 요구가 자주 나온다. **전부 구현하지 않는다.**

| 흔한 방법 | 왜 안 되는가 |
|---|---|
| `keydown`으로 F12·Ctrl+Shift+I 차단 | 메뉴에서 열면 그만. 모바일엔 키가 없다 |
| `contextmenu` 차단 | 단축키로 열면 그만. 복사가 안 돼 정상 사용자만 불편 |
| `debugger` 무한 루프 | devtools 설정에서 중단점 끄면 끝. 저사양 기기에서 페이지가 멈춘다 |
| 소스 난독화 | 시간을 벌 뿐. 네트워크 탭은 그대로 보인다 |

전부 **우회에 몇 초**가 걸리고, 그동안 **정상 사용자는 계속 불편**하다. 접근성 보조도구까지 깨진다.

### 그럼 self-XSS는 어떻게 막나

공격자가 "이 코드를 콘솔에 붙여넣으면 포인트를 드려요" 같은 말로 사용자를 속이는 수법이다. 기술로는 막을 수 없다 — 사용자가 자기 브라우저에서 하는 일이다.

**할 수 있는 것은 경고뿐이다.** 페이스북·구글이 쓰는 방식으로, 앱 시작 시 콘솔에 한 번 찍는다.
**구현했다**(2026-09-27, `src/main.tsx`). 개발 서버에서는 찍지 않는다(`import.meta.env.PROD`) — 매번 보이면 개발자부터 경고를 읽지 않게 된다.

```js
// main.tsx — 운영 빌드에서만. 색은 삭제 전용 빨강(tokens.css --danger)
if (import.meta.env.PROD) {
  console.log('%c잠깐!', 'color:#b3251b;font-size:32px;font-weight:bold')
  console.log(
    '%c누군가 여기에 코드를 붙여 넣으라고 했다면 사기입니다.\n계정을 통째로 빼앗길 수 있습니다.',
    'font-size:14px',
  )
}
```

8장의 "운영 빌드에 `console.log`를 남기지 않는다"의 유일한 예외다. 찍는 것은 고정 문장뿐이고 토큰 · 응답은 없다.

**진짜 방어선은 서버다.** 콘솔로 무슨 짓을 하든 남의 게시글은 수정할 수 없어야 하고, 그것을 보장하는 것은 백엔드의 소유자 검증이다.

## 2. XSS — 실제로 막아야 하는 것

React는 JSX에 넣은 문자열을 자동으로 이스케이프한다. **그 방어를 스스로 뚫지만 않으면 된다.**

### 금지

```jsx
<div dangerouslySetInnerHTML={{ __html: post.content }} />   // 금지
```

게시글 본문·댓글·닉네임은 전부 사용자 입력이다. 서버는 HTML을 정제하지 않고 그대로 저장한다.

리치 텍스트가 정말 필요해지면 **DOMPurify로 정제한 뒤에만** 쓴다. 정제 없이 쓰는 경우는 없다.

### 그 외 주의 지점

| 자리 | 규칙 |
|---|---|
| `href={userInput}` | `javascript:` 스킴이 실행된다. `http`/`https`만 허용하고 나머지는 링크로 만들지 않는다 |
| `<a target="_blank">` | 반드시 `rel="noopener noreferrer"` |
| `style={{ ...userInput }}` | 사용자 값을 스타일에 직접 넣지 않는다 |
| `eval` · `new Function` · `setTimeout("문자열")` | 쓰지 않는다 |
| URL 파라미터 | `useSearchParams`로 읽은 값도 사용자 입력이다. 검색어를 그대로 렌더할 때 이스케이프를 우회하지 않는다 |
| 이미지 `src` | 우리 S3/CloudFront 도메인만. 임의 URL을 그대로 넣지 않는다 — 응답의 사진 주소는 `postApi`가 받자마자 `shared/lib/url.ts`의 `safeImageUrl`로 거른다(`http:` · `https:`만, 제어 문자 · `javascript:` · `data:` · `blob:` · `file:`은 버림). 목록 · 내 글은 대표 사진을 `null`로(카테고리 그림), 상세는 그 사진만 뺀다. 출처(도메인)는 CSP `img-src`가 좁힌다(4장) |
| `location.state` | 같은 출처 스크립트만 넣을 수 있지만 모양은 다시 본다 — 로그인 안내(`readNotice`)는 문자열만, 상세 진입(`readPostDetailEntry`)의 `search`는 `^\?[\w=&%-]*$`만 따른다 |
| 쪽 번호(`?page=`) | 안전한 정수(`Number.isSafeInteger`) · 1 이상만. `1e400` 같은 값은 1쪽 |

**사용처 점검(2026-09-29)** — `href`는 건너뛰기 링크(`#main`) 하나, 나머지는 전부 `paths`가 만든 `<Link to>`. `window.open` · `location.assign` · `location.href =` 0건. `new URL`은 `safeRedirectPath` · `describeReturnTarget`(같은 출처로 풀어 검사) · `safeImageUrl`뿐. `dangerouslySetInnerHTML` · `innerHTML` · `eval` 0건(운영 CSP의 Trusted Types가 브라우저에서도 막는다, 4장).

## 3. 토큰 저장

| 토큰 | 저장 위치 | 이유 |
|---|---|---|
| 액세스 토큰(5분) | **JS 메모리**(모듈 변수 또는 Context) | XSS가 나도 `localStorage`처럼 통째로 긁히지 않는다 |
| 리프레시 토큰(7일) | **HttpOnly 쿠키** — JS가 못 읽는다 | 서버가 심고 서버만 읽는다 |

### 절대 하지 않는다

- `localStorage` · `sessionStorage`에 토큰 저장 — XSS 한 줄이면 전부 털린다
- 토큰을 URL 쿼리스트링에 싣기 — 브라우저 히스토리·서버 로그·Referer에 남는다
- 토큰을 콘솔에 찍기 — 운영 빌드에 남으면 사용자가 스크린샷으로 유출한다

### 브라우저 저장소에 두는 것 — 비밀이 아닌 것뿐

| 저장소 | 키 | 값 | 왜 괜찮은가 |
|---|---|---|---|
| localStorage | `theme:v1` | `'light'` \| `'dark'` | 화면 모드. 누가 읽어도 잃을 것이 없다. 읽기 전에 두 값 중 하나인지 확인하고, 아니면 버린다 |
| localStorage | `onboarding:v1:done` | `'1'`(첫 안내를 봤음) | 같은 이유. `'1'`이 아니면 안 본 것으로 둔다 |
| sessionStorage | `scroll:v1` | `[기록 항목 key, 스크롤 px]` 최근 50개 | 뒤로가기 · 새로고침 뒤 스크롤 위치(`app/ScrollMemory`). 탭을 닫으면 사라진다. 배열 모양이 아니면 버린다 |
| sessionStorage | `post-draft:v1:create` · `post-draft:v1:edit:{글 id}` | 쓰던 글의 글자 · 회원 id · 저장 시각 | 쓰는 도중 **세션이 만료됐을 때만**(7장 끝). 토큰이 아니라 사용자가 쓴 글이다. 6시간 · 같은 회원에게만 · 고르면 지움 · **직접 로그아웃하면 지움** |
| sessionStorage | `comment-draft:v1:{글 id}` | 쓰던 댓글 · 회원 id · 글 id · 저장 시각 | 같은 규칙(`features/comments/model/commentDraft`). 세션 만료 때만 넣고, 직접 로그아웃하면 지움 |

- 토큰 · 회원 정보(이메일 · 닉네임) · 게시글 응답은 넣지 않는다. 위 표에 없는 키를 더하려면 이 표부터 고친다(2026-09-29 전수 점검 — `localStorage` 둘 · `sessionStorage` 셋, 코드의 `getItem` · `setItem`이 이 다섯 키뿐이다)
- **직접 로그아웃하면 쓰던 글 · 댓글 보관을 지운다**(2026-09-29, `shared/lib/writeDrafts.ts`의 `clearWriteDrafts`, `AuthProvider.logout`). 공용 기기에서 로그아웃하고 자리를 뜨면 다음 사람이 개발자 도구로 읽을 수 있다 — "같은 회원에게만 되살림"은 화면의 검사일 뿐 저장소의 글자는 누구나 읽는다.
  세션 만료 때는 지우지 않는다(다시 로그인해 이어 쓰려고 둔 것이다). 등록 · 수정 화면도 **만료일 때만** 보관한다(`PostForm`이 `subscribeSessionExpired`로 가른다) — 쓰는 도중 직접 로그아웃하면 "로그아웃했어요." 한 줄만 뜨고 글자는 남지 않는다. 화면 모드 · 첫 안내 · 스크롤 키는 그대로 둔다
- 읽을 때마다 모양을 다시 검사한다. 저장소 값은 누구나 고칠 수 있다. 되살린 글자도 React 가 텍스트로만 그린다
- 로그인 뒤 돌아갈 곳(`?redirect=`)도 사용자 입력이다 — `app/authRedirect.ts`가 `/`로 시작하고 `//` · `\`(브라우저가 `//`로 읽는다) · 제어 문자가 없으며 같은 출처로 풀리는 경로만 따른다. 나머지는 `/`(열린 리다이렉트 방지)
- 가입 직후 로그인 화면으로 넘길 때 기록(history state)에는 이메일만 싣는다. 비밀번호는 싣지 않는다
- 저장소 접근은 `try/catch`로 감싼다. 사생활 보호 모드 · 쿠키 차단에서 던지는 예외로 앱이 멈추지 않게 — 그때는 기기 설정을 따른다

새로고침하면 메모리가 비므로 **재발급으로 복구**한다. 앱 시작 시 `POST /api/auth/reissue`를 한 번 호출하고, 실패하면 비로그인으로 시작한다.

### 401 인터셉터

- 재발급은 **동시에 한 번만** 나가야 한다. 진행 중인 Promise를 공유한다
- 여러 번 나가면 리프레시 토큰이 연속 회전하며 서로를 무효화해 **멀쩡한 세션이 끊긴다**
- 재발급도 실패하면 메모리 토큰을 비우고 로그인 화면으로 보낸다. 무한 재시도 금지

## 4. Content-Security-Policy

XSS가 뚫렸을 때의 **2차 방어선**이다. 스크립트 출처를 제한해 주입된 코드가 실행되지 않게 한다.

**두 곳에 같은 정책을 건다**(2026-09-29 — 심층 방어).

1. **운영 빌드의 `<meta http-equiv="Content-Security-Policy">`** — `vite.config.ts`의 플러그인(`lost-and-found:security-meta`)이 `vite build`에서만 `dist/index.html`의 `<meta charset>` 바로 뒤에 심는다. 정책 문자열은 `build/csp.ts` 하나에서 만든다. CloudFront 설정을 빠뜨리거나 다른 곳(S3 정적 호스팅 · 미리보기)에 올려도 정책이 따라간다
2. **CloudFront 응답 헤더 정책** — `docs/cloudfront-response-headers-policy.json`(11장 배포 구성). meta로는 안 되는 `frame-ancestors`와 나머지 보안 헤더가 여기 있다

둘 다 걸리면 브라우저는 **둘 다** 지킨다(교집합). 한쪽만 넓히면 좁은 쪽이 이긴다 — 사진 출처를 바꾸면 두 곳을 같이 고친다. `build/csp.test.ts`가 문서 JSON의 CSP와 `buildHeaderCsp()`의 결과가 글자 그대로 같은지 본다.

meta 정책(운영 빌드에 들어간 원문, 사진 출처는 기본값):

```
default-src 'self';
script-src 'self';
style-src 'self';
img-src 'self' blob: https://lostfound-images-solmin-seoul.s3.ap-northeast-2.amazonaws.com;
font-src 'self';
connect-src 'self';
object-src 'none';
base-uri 'none';
form-action 'self';
require-trusted-types-for 'script';
trusted-types 'none';
upgrade-insecure-requests
```

CloudFront 헤더는 이 뒤에 `frame-ancestors 'none'`을 더한다.

- `script-src 'self'` — 인라인 스크립트와 외부 스크립트를 모두 차단한다. Vite 빌드 결과는 외부 파일이라 문제없다. 플러그인은 `index.html`에 인라인 `<script>`가 있으면 **빌드를 멈춘다**
- **화면 모드 초기화 스크립트도 인라인으로 쓰지 않는다.** 어둡게를 고른 사람이 흰 화면을 한 번 보지 않으려면 첫 화면 전에
  `<html data-theme>`을 붙여야 해서 `<head>`에서 **동기로** 불러오는데, 인라인 `<script>`는 이 정책이 막는다.
  그래서 같은 출처의 파일 `public/theme-init.js`(`<script src="/theme-init.js">`)로 둔다. `'unsafe-inline'`이나 해시 · nonce를 더하지 않는다
- 그 파일은 `localStorage`의 `theme:v1`을 읽어 `'light'`/`'dark'`일 때만 속성을 붙이고 `theme-color`를 맞춘다. 다른 값은 버리고, 접근이 막히면 조용히 넘어간다.
  DOM에 사용자 입력을 넣지 않는다. 빌드가 건드리지 않는 파일이라(`public/`) 코드를 고치면 `src/shared/lib/theme.ts`의 키 · 색도 같이 고친다
- **`style-src 'self'` — `'unsafe-inline'`을 뺐다**(2026-09-29). React의 `style` prop은 CSSOM(`el.style.x = …`)으로 들어가 CSP가 막지 않는다. 막히는 것은 HTML의 `style="…"` 속성 · `<style>` 요소 · `setAttribute('style')`인데 앱과 번들에 없다(운영 빌드에서 위반 0건 확인)
- **글꼴은 같은 출처에서만 받는다**(2026-09-27). Pretendard를 jsdelivr `<link>`로 받던 것을 `pretendard` 패키지로 바꿨다 —
  `src/main.tsx`가 가변 동적 서브셋 CSS(`pretendard/dist/web/variable/pretendardvariable-dynamic-subset.css`)를 불러오고,
  Vite가 `@font-face` 92개를 앱 CSS(`/assets/index-*.css`)에 합치고 woff2 조각 92개를 `/assets/`로 내보낸다.
  그래서 `style-src 'self'` · `font-src 'self'`로 충분하고, 외부 출처(`cdn.jsdelivr.net`)를 더하지 않는다. 운영 빌드의 `dist/index.html`에 외부 주소가 없다.
  가장 작은 조각이 8KB라 Vite 인라인 한도(4KB)를 넘어 `data:` 글꼴이 생기지 않는다 — 한도를 올리면 `font-src`에 `data:`가 필요해지므로 올리지 않는다.
  CDN이 멈추거나 바뀌어도 글꼴이 흔들리지 않고, 남의 서버가 우리 페이지에 CSS를 내려보내는 통로가 하나 줄었다
- **`img-src` 사진 출처는 빌드 환경변수 `CSP_IMAGE_ORIGINS`**(공백으로 여럿). 백엔드 `AWS_S3_BASE_URL`과 같은 출처를 넣는다.
  - 비우면 지금 백엔드 로컬 설정의 서울 버킷(`https://lostfound-images-solmin-seoul.s3.ap-northeast-2.amazonaws.com`)을 넣고 빌드가 경고한다.
    로컬 버킷은 퍼블릭 읽기를 닫아 두어 사진 주소가 403이다 — CSP 위반이 아니라 버킷 권한이다
  - **배포 빌드는 CloudFront 도메인을 넣는다**: `CSP_IMAGE_ORIGINS=https://dxxxx.cloudfront.net npm run build`. 같은 값을 CloudFront 헤더 JSON의 `img-src`에도 넣는다(교집합)
  - `VITE_`를 붙이지 않는다 — 빌드(Node)만 읽고 브라우저 코드는 필요 없다(5장)
  - 값은 정책 문자열에 그대로 들어가므로 `build/csp.ts`의 `parseOriginList`가 검사한다. `https://host[:port]`만(경로 · 쿼리 · 계정 · `*` · `;` · `'` 없음), `http:`는 `localhost` · `127.0.0.1`만 — 어기면 **빌드를 멈춘다**. 조용히 버리면 운영에서 사진만 안 보인다
  - `VITE_API_BASE_URL`로 다른 출처 API를 부르도록 빌드했으면(CORS 확인용) 그 출처가 `connect-src`에 붙는다
- `img-src`의 `blob:` — 등록 · 수정 화면의 사진 미리보기가 `URL.createObjectURL`(`blob:` 주소)이다. 빼면 운영에서만 미리보기가 깨진다.
  `blob:` 주소는 이 탭이 만든 것만 열리므로 외부 이미지를 끌어오는 통로가 되지 않는다. **`data:`는 넣지 않는다**(예전 초안에 있던 것을 뺐다 — 쓰는 곳이 없다)
- `base-uri 'none'` — `<base>`를 끼워 상대 주소 스크립트를 남의 서버로 돌리는 것을 막는다. 앱은 `<base>`를 쓰지 않는다(예전 초안의 `'self'`보다 좁다)
- **Trusted Types**(`require-trusted-types-for 'script'` · `trusted-types 'none'`) — `innerHTML` · `eval` · `script.src` 같은 "문자열 → 코드" 통로를 브라우저가 막는다.
  번들에서 이 통로를 쓰는 곳은 React의 `dangerouslySetInnerHTML` 처리 · `<script>` 요소 생성 경로뿐이고 앱은 둘 다 쓰지 않는다. 정책을 하나도 만들지 않으니 `'none'`이다.
  운영 빌드(`vite preview`)에서 목록 · 상세 · 로그인 · 등록(사진 5장 · 미리보기) · 설정(화면 모드) · 로그아웃 · 새로고침을 돌려 **위반 0건**을 확인하고 넣었다(일부러 `innerHTML`을 넣어 보면 `TypeError`로 막힌다).
  지원하지 않는 브라우저는 이 줄을 무시하고 나머지 정책만 지킨다. 나중에 리치 텍스트(DOMPurify)를 넣으면 DOMPurify의 TT 정책 이름을 `trusted-types`에 더한다
- `upgrade-insecure-requests` — 섞여 들어온 `http://` 주소를 https로 올려 받는다. `localhost`는 브라우저가 올리지 않아 로컬 확인에 지장이 없다
- `frame-ancestors 'none'` — 클릭재킹 차단. **meta로는 걸리지 않는다**(브라우저가 무시한다) — CloudFront 헤더에만 있고, `X-Frame-Options: DENY`도 같이 보낸다
- `object-src 'none'` — 플러그인 차단

**개발 서버에는 걸지 않는다.** Vite HMR이 인라인 스크립트와 WebSocket을 쓴다. 플러그인은 `command === 'build'`일 때만 붙고, 개발 서버 · vitest는 `CSP_IMAGE_ORIGINS`를 검사하지도 않는다.

### Referrer — `same-origin`

검색어가 주소 쿼리(`/?keyword=지갑`)에 실린다. 운영 빌드에 `<meta name="referrer" content="same-origin">`을 넣고, CloudFront 헤더도 `Referrer-Policy: same-origin`이다.

| 정책 | 남의 출처(S3 · CloudFront 사진)로 | 우리 API로 | 판단 |
|---|---|---|---|
| `strict-origin-when-cross-origin`(브라우저 기본) | 출처만(`https://앱/`) | 전체 주소 | 검색어는 안 샌다. 그래도 어느 앱에서 왔는지는 보낸다 |
| **`same-origin`** | **보내지 않는다** | 전체 주소 | 사진 서버에 아무것도 주지 않는다. 우리 서버 로그 · 향후 Origin/Referer 검사는 그대로 |
| `no-referrer` | 보내지 않는다 | 보내지 않는다 | 우리 쪽에서 잃는 것만 있고 더 막는 것이 없다 |

`same-origin`을 골랐다. 버킷 정책을 Referer로 거는 핫링크 방지(`aws:Referer`)는 쓸 수 없게 되는데, 사진은 CloudFront OAC로 막는 것이 맞다(Referer는 위조된다).

### 함께 넣을 헤더 — CloudFront 응답 헤더 정책

원본은 `docs/cloudfront-response-headers-policy.json`이다. AWS CLI `aws cloudfront create-response-headers-policy --response-headers-policy-config file://docs/cloudfront-response-headers-policy.json`에 그대로 넣는 모양이고, SPA 동작(`/*`)에 붙인다.

| 헤더 | 값 | 이유 |
|---|---|---|
| `Content-Security-Policy` | meta와 같은 정책 + `frame-ancestors 'none'` | 위. 사진 출처는 배포 때 CloudFront 도메인으로 바꾼다 |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | https 강제. `preload`는 도메인이 정해진 뒤 따로 판단한다(되돌리기 어렵다) |
| `X-Content-Type-Options` | `nosniff` | 형식 추측 금지 — JS가 아닌 파일을 스크립트로 읽지 않는다 |
| `X-Frame-Options` | `DENY` | `frame-ancestors`를 모르는 옛 브라우저용 클릭재킹 차단 |
| `Referrer-Policy` | `same-origin` | 위 |
| `X-XSS-Protection` | `0` | 옛 브라우저의 XSS 필터는 오히려 공격 통로였다. 끈다(OWASP 권고) |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=(), usb=(), serial=(), bluetooth=(), browsing-topics=()` | 쓰지 않는 기능을 닫는다. 사진 고르기(`<input type="file">`)는 `camera` 권한과 무관해 휴대폰 카메라 촬영도 된다 |
| `Cross-Origin-Opener-Policy` | `same-origin` | 남의 창이 `window.opener`로 우리 창을 조작하지 못한다(팝업을 쓰지 않는다) |
| `Cross-Origin-Resource-Policy` | `same-origin` | 우리 JS · CSS · 글꼴을 남의 페이지가 끌어다 쓰지 못한다 |
| `X-Permitted-Cross-Domain-Policies` | `none` | 옛 플러그인(Flash · PDF)의 교차 출처 정책 파일 차단 |
| (제거) `Server` | — | 서버 종류를 알리지 않는다 |

- **COEP(`Cross-Origin-Embedder-Policy`)는 넣지 않는다** — 넣으면 CORP 헤더가 없는 S3/CloudFront 사진이 전부 막힌다. 쓸 기능(`SharedArrayBuffer`)도 없다
- `/api/*` 동작에는 CSP 대신 `nosniff` · HSTS · `Cache-Control: no-store`만 있는 가벼운 정책을 붙인다(JSON 응답, 백엔드 담당)

## 5. 환경변수 — `VITE_` 는 공개값이다

Vite는 `VITE_` 접두사가 붙은 값을 **번들에 문자열로 그대로 박는다.** 빌드 결과를 열면 누구나 읽는다.

| 넣어도 되는 것 | 절대 넣으면 안 되는 것 |
|---|---|
| API 주소, CDN 도메인, 기능 플래그 | AWS 액세스 키, DB 접속 정보, 서드파티 시크릿, JWT 서명 키 |

`.env`는 `.gitignore`에 있어야 하고, `.env.example`에는 **키 이름과 설명만** 둔다. 값은 두지 않는다.

**개발 서버만 읽는 값에는 `VITE_`를 붙이지 않는다**(2026-09-27). 프록시 대상은 `DEV_PROXY_TARGET`이다(예전 이름 `VITE_DEV_PROXY_TARGET`). `vite.config.ts`(Node)만 `loadEnv`로 읽고 브라우저 코드의 `import.meta.env`에는 들어가지 않는다. 접두사가 붙어 있으면 누가 앱 코드에서 한 번 읽는 순간 번들에 실린다.

비밀이 필요한 호출은 프론트에서 하지 않는다. 백엔드를 거친다.

## 6. 의존성 공급망

npm 패키지는 남의 코드가 우리 빌드에 들어오는 통로다. 실제로 유명 패키지가 탈취돼 토큰을 빼가는 코드가 배포된 사례가 반복해서 나왔다.

- `package-lock.json`을 **반드시 커밋**한다. CI는 `npm install`이 아니라 **`npm ci`** 를 쓴다 — lockfile을 그대로 재현한다
- 새 패키지를 넣기 전에 주간 다운로드 수, 마지막 업데이트, 의존성 개수를 본다. 한 줄짜리 유틸리티는 직접 짠다
- **CI(`.github/workflows/ci.yml`)의 공급망 단계**(2026-09-29)

  | 단계 | 실패하면 | 이유 |
  |---|---|---|
  | `npm audit signatures` | 멈춘다 | 받은 패키지가 레지스트리가 서명한 그대로인지. 지금 55개 서명 · 29개 출처 증명 확인 |
  | `npm audit --omit=dev --audit-level=high` | 멈춘다 | **운영 번들에 들어가는** 의존성(react · react-dom · react-router · tanstack query · phosphor · pretendard) 6개뿐이라 소음이 적다 |
  | `npm audit --audit-level=high` | 경고만(`continue-on-error`) | 개발 도구(vite · vitest · oxlint · typescript)는 개발 서버 쪽 알림이 잦고 번들에 들어가지 않는다. 막으면 남의 발표 하나로 CI 가 깨진다 |

  2026-09-29 기준 둘 다 **0건**이다
- **Dependabot**(`.github/dependabot.yml`) — npm · GitHub Actions, 매주 월요일 09:00(KST). 부 · 수 버전은 한 PR로 묶고 주 버전은 따로 온다.
  **새 버전이 나오고 7일 뒤에 제안한다**(`cooldown`) — 탈취된 계정으로 올린 악성 버전은 대개 며칠 안에 내려간다. 취약점 고침(보안 업데이트)은 기다리지 않는다.
  **자동 머지는 하지 않는다** — CI가 통과한 PR을 사람이 읽고 합친다
- **CodeQL**(`.github/workflows/codeql.yml`) — `javascript-typescript`, 빌드 없이(`build-mode: none`), `security-extended` 질의. push main · PR · 매주 월요일 03:00(KST). 결과는 GitHub Security 탭. 백엔드 리포와 같은 방식이다
- 주 버전이 밀린 것은 따로 판단한다 — 지금은 `typescript` 7 · `@types/node` 26이 있다(개발 도구, 취약점 없음)

## 7. 파일 업로드 (게시글 이미지)

클라이언트 검증은 **UX이자 심층 방어이지 방어선이 아니다.** 진짜 방어선은 백엔드다 — 지금 백엔드는 **파일 이름의 확장자만** 보고(`S3Service.extractExtension`), 파트의 Content-Type을 S3에 **그대로** 적는다(백엔드 개선 목록 24-5).

프론트에서 하는 것:

- 확장자 화이트리스트(jpg/jpeg/png/gif)로 선택 단계에서 거른다
- **앞 8바이트(매직 바이트)로 실제 형식을 본다**(2026-09-29, `shared/lib/image/format.ts`). JPEG `FF D8 FF` · PNG `89 50 4E 47 0D 0A 1A 0A` · GIF `GIF87a`/`GIF89a`가 아니면 **그 파일만** 빼고 이름과 이유를 알린다("JPG · PNG · GIF 사진이 아닙니다. 이름만 바꾼 파일일 수 있어요").
  고른 직후(`checkPostImageContent`)에 한 번, 보내기 직전(`preparePostImage`)에 한 번 더 본다. 형식은 이름이 아니라 이 바이트로 정한다 — 이름이 `.jpg`인 GIF는 GIF로 다룬다
- 5장 초과를 UI에서 막는다. 서버까지 보내고 400을 받지 않는다
- 파일 크기를 미리 확인한다(개당 10MB, 요청 60MB)
- 미리보기는 `URL.createObjectURL`을 쓰고 **`revokeObjectURL`로 해제**한다. 안 하면 메모리가 샌다

**사진의 위치 정보(EXIF GPS)를 올리지 않는다**(2026-09-29). 올린 사진은 상세 화면에서 누구에게나 내려간다. 분실물 글의 휴대폰 사진이면 집 · 직장 좌표가 그대로 샌다.

| 경로 | 무엇을 보내나 |
|---|---|
| JPEG · PNG, 다시 그린 것이 더 작다(대부분) | 캔버스로 다시 그린 JPEG — EXIF가 원래 전부 빠진다(방향은 적용된 채) |
| PNG, 다시 그린 것이 더 크다(단색 · 작은 그림) | 원본에서 `eXIf` · `tEXt` · `zTXt` · `iTXt` · `tIME` 덩어리와 `IEND` 뒤를 **걷어 낸** 원본(그림 바이트는 그대로) |
| JPEG, 다시 그린 것이 더 크다 | 원본에 메타데이터가 있었거나 구조를 끝까지 읽지 못했으면 **커져도 다시 그린 쪽**(걷기만 하면 방향 태그도 빠져 세로 사진이 눕는다). 메타데이터가 없던 원본만 그대로 |
| JPEG, 캔버스가 실패했다(메모리) | APP1(EXIF · XMP) · APP3~13(IPTC) · APP15 · COM · ICC가 아닌 APP2(MPF) · Adobe가 아닌 APP14 · 끝(`FF D9`) 뒤를 걷은 원본. JFIF · ICC · Adobe(색)는 남긴다 |
| GIF(움직임 때문에 다시 그리지 않는다) | 주석 확장 · 반복/ICC가 아닌 응용 확장(XMP) · 끝 뒤를 걷은 원본. 움직임 · 반복 · 투명은 그대로 |

- 구현은 `shared/lib/image/metadata.ts`. 형식을 끝까지 읽지 못하면(깨졌거나 모르는 구조) 추측으로 자르지 않고 `null` — 부르는 쪽이 다른 길(다시 그린 것)을 고른다
- 끝 뒤에 붙은 바이트도 버린다 — 다른 파일을 이어 붙인 polyglot, 휴대폰의 부가 이미지(MPF)
- 운영 빌드에서 GPS · 카메라 정보를 넣은 JPEG(큰 것 · 작은 것) · 글자 덩어리가 든 PNG · 주석이 든 GIF를 올려, 서버가 받은 바이트에 `Exif` · 표식 문자열이 없는 것을 확인했다

**보내는 파일 이름을 다듬는다**(`safePostImageBaseName`) — 서버가 `original_filename`에 그대로 넣고 상세 응답으로 누구에게나 내려준다.
경로 문자(`/` `\`) · Windows 예약 문자(`: * ? " < > |`)는 `_`, 제어 문자(C0 · C1) · 방향 제어(U+202A~202E · U+2066~2069 — `exe.jpg`를 `gpj.exe`처럼 보이게 뒤집는다) · 폭 없는 글자 · BOM은 뺀다.
탭 · 줄바꿈은 띄어쓰기로, NFC로 맞추고(macOS 한글), 앞뒤 공백 · 점을 떼고, 100자에서 자른다. 비면 `image`. 확장자는 실제 형식(`.jpg` · `.png` · `.gif`)으로 새로 붙인다.

이 모든 것은 **우리 화면을 거친 요청**에만 걸린다. API를 직접 부르면 아무것도 막지 못한다 — 백엔드가 매직 바이트 검사 · Content-Type을 확장자에서 정하기 · 메타데이터 제거를 해야 한다(보고서의 백엔드 항목).

**쓰던 글의 임시 보관**(2026-09-27, 등록 · 수정 화면) — 쓰는 도중 **세션이 만료되면** 입력한 **글자만** sessionStorage `post-draft:v1:*`에 넣는다(3장의 금지 대상인 토큰이 아니다).

- 탭을 닫으면 사라지고, 6시간이 지나면 읽지 않고 지운다. 이어 쓰기 · 새로 쓰기를 고르면 바로 지운다. 저장에 성공해도 지운다
- 회원 id 를 함께 적고 **같은 회원에게만** 되살려 준다 — 공용 기기에서 다음 사람이 로그인해도 보이지 않는다
- **직접 로그아웃하면 넣지 않고, 있던 것도 지운다**(2026-09-29, 3장)
- 읽을 때 모양을 다시 검사한다(Enum · 날짜 · 문자열). 저장소 값은 누구나 고칠 수 있다. 되살린 값도 React 가 텍스트로만 그린다
- 사진 파일 · 미리보기 주소는 넣지 않는다(넣을 수도 없다)

## 8. 그 밖의 규칙

- **운영 빌드에 `console.log`를 남기지 않는다.** 토큰·응답 본문이 찍히면 사용자가 스크린샷으로 유출한다. 빌드 시 제거하거나 개발 전용 래퍼를 쓴다
- **소스맵을 운영에 올리지 않는다**(`build.sourcemap: false`). 올리면 원본 코드가 그대로 공개된다. `vite.config.ts`가 `mode !== 'production'`일 때만 켠다 — `vite build`의 기본 mode는 production이라 꺼진다(2026-09-29 `dist/`에 `.map` 0개 확인)
- **오류 화면에 스택트레이스를 노출하지 않는다.** 서버 `message`만 보여준다
- **자동완성** — 비밀번호 입력에 `autoComplete="current-password"` / `"new-password"`를 정확히 지정한다. 비밀번호 관리자가 제대로 동작해야 사용자가 약한 비밀번호를 안 쓴다
- **로그아웃 시 메모리 토큰과 회원 캐시를 지운다.** 안 하면 다음 사용자가 이전 사용자의 데이터를 본다. 세션 만료 · 비밀번호 변경도 같다(`AuthProvider`의 `forgetMember`)
  - 지운다(`removeQueries`) : 내 정보(`memberKeys.all`) · 내가 쓴 글(`postKeys.mines()`) · **요청 기록**(mutation 캐시 — 비밀번호 변경의 현재 · 새 비밀번호가 몇 분간 메모리에 남는다)
  - 다시 받게만 한다(`invalidateQueries`) : 공개 게시글 · 댓글. 누가 봐도 같은 데이터라 지킬 것이 없다
  - 처음에는 `queryClient.clear()`로 통째로 비웠다(2026-09-27 바꿈). 보던 상세가 스켈레톤으로 깜빡이고 높이가 줄어 스크롤이 튀었다. **회원 데이터 쿼리를 새로 만들면 지우는 목록에 더한다**

## 9. 배포 체크리스트

순서대로 한다. 괄호는 확인하는 명령 · 자리다.

### 9.1 빌드 전

- [ ] 사진 출처를 정했다 — 백엔드 `AWS_S3_BASE_URL`(운영 CloudFront 도메인)과 같은 값을 `CSP_IMAGE_ORIGINS`로 넣는다(4장)
- [ ] `docs/cloudfront-response-headers-policy.json`의 CSP `img-src`도 같은 출처로 바꿨다. 기본값(서울 버킷)을 바꿨으면 `build/csp.ts`의 `DEFAULT_IMAGE_ORIGINS`도 맞춘다 — `npm test`의 `csp.test.ts`가 둘이 어긋나면 실패한다
- [ ] `.env`가 git에 없음(`git log --all -- .env` 결과 없음) · `VITE_` 변수에 비밀값 없음(5장)
- [ ] `package-lock.json` 커밋됨, CI가 `npm ci` · `npm audit signatures` · `npm audit --omit=dev --audit-level=high` 통과(6장)
- [ ] CodeQL(Security 탭)에 열린 경고 없음 · Dependabot 보안 PR 없음

### 9.2 빌드

```bash
CSP_IMAGE_ORIGINS=https://dxxxx.cloudfront.net npm run build
```

- [ ] 빌드 로그에 `[security-meta] CSP_IMAGE_ORIGINS 가 비어 있어` 경고가 **없다**
- [ ] `dist/index.html`의 `<meta http-equiv="Content-Security-Policy">`가 `<meta charset>` 바로 뒤에 있고, `img-src`가 넣은 출처다 · `<meta name="referrer" content="same-origin">`이 있다
- [ ] 소스맵 없음(`ls dist/assets | grep "\.map$"` · `grep -l sourceMappingURL dist/assets/*.js` 결과 없음)
- [ ] `index.html`에 인라인 `<script>` 없음(플러그인이 있으면 빌드를 멈춘다) — 화면 모드 초기화는 `/theme-init.js`
- [ ] `dist/index.html` · CSS에 외부 출처 없음 — `grep -o "https\?://[a-z0-9.-]*" dist/index.html dist/assets/*.css`가 CSP의 사진 출처뿐

### 9.3 CloudFront

- [ ] 응답 헤더 정책을 만들었다 — `aws cloudfront create-response-headers-policy --response-headers-policy-config file://docs/cloudfront-response-headers-policy.json`
- [ ] SPA 동작(`/*`, 기본 동작)에 붙였다. `/api/*` 동작에는 붙이지 않는다(가벼운 정책 따로, 4장 끝)
- [ ] 뷰어 프로토콜 정책 `Redirect HTTP to HTTPS` · 최소 TLS 1.2
- [ ] SPA 새로고침을 위해 403/404 → `/index.html`(200)로 돌려준다. **`/api/*`에는 이 오류 페이지를 걸지 않는다**(API 404가 HTML로 바뀐다)
- [ ] `index.html`은 `Cache-Control: no-cache`, `/assets/*`는 해시 이름이라 오래 캐시 — 정책을 바꾼 뒤 옛 `index.html`이 남지 않게 무효화(`/index.html`)
