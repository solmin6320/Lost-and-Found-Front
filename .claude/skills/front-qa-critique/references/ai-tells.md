# AI 티 — 찾는 법과 사람 손길로 이끄는 법 (본인, 2026-10-11)

> "AI가 디자인했다고 티가 많이 나는 부분(폰트, 디자인, UI/UX, 색깔 조합, 애니메이션 등)도 'AI 티가 너무 심한데?' 하면서 지적해.
> QA는 너무 심한 AI 디자인 방향성도 잡아서, 사람이 고심해서 만들고 사람의 손길이 거친 듯한, AI 디자인 느낌이 나지 않는 길로 이끌어 줄 수 있어야 해"

기준 문서 : `docs/디자인품질기준.md` "AI 티를 아예 뺀다" · 스킬 `design-taste-frontend` 9장(AI Tells) · 14장(Pre-Flight) · `impeccable`(craft-floor).
**남겨 둔 예외**(그 문서 표 아래 목록)는 본인이 고른 것이라 지적하지 않는다. 다만 예외가 **늘어나는 것**은 지적한다.

## 1. 무엇이 "AI 티"인가 — 범주별 신호

| 범주 | AI 티 신호(보이면 의심) | 왜 티가 나나 |
|---|---|---|
| 글자 | 한 화면에 굵기 · 크기가 너무 많음 · 모든 제목이 같은 크기 비율(1.25 등비만) · 영문 장식 서체 · 의미 없는 대문자 꼬리표(OVERLINE) · 한글에 영문 기본 행간 | 생성기가 모든 화면에 같은 위계 공식을 찍어 낸다. 사람은 내용에 맞춰 위계를 정한다 |
| 색 | 보라→파랑 · 청록→보라 그라데이션 · Tailwind 기본 팔레트(`#3B82F6` `#8B5CF6` `#10B981` 등과 ΔE < 10) · 뜻 없는 강조색 남발 · 모든 카드에 연한 색 배경 · 반투명 유리판 | 기본값을 그대로 쓴 색은 어디서 본 화면처럼 보인다. 색마다 뜻이 있어야 사람이 고른 색이다 |
| 모양 | 모든 것이 크게 둥근 반경 · 모든 카드에 같은 그림자 · 테두리 + 그림자 + 배경 삼중 강조 · 이모지 아이콘 · 직접 그린 어설픈 아이콘 · 장식용 흐린 도형(블롭) | 위계 대신 장식으로 면을 채운다 |
| 배치 | 가운데 정렬 일색 · 똑같은 3열 카드 그리드 · 아이콘+제목+설명 세트 반복(특징 나열) · 의미 없는 섹션 구분선 · 여백이 모든 곳에서 같음 | 내용이 아니라 틀에서 출발한 배치 |
| 문구 | "손쉽게 · 간편하게 · 스마트하게 · 혁신적인" · 느낌표 · 빈 환영 문구 · 기능명을 그대로 버튼에 · em-dash(—) 남발 · "~해보세요!" 권유 말투 반복 | 사람이 실제로 쓰는 말이 아니다. 사용자가 하려는 일의 말로 써야 한다 |
| 움직임 | 모든 것이 페이드업으로 등장 · 호버마다 확대 · 튀는 스프링 · 이유 없는 반짝임 · 스크롤 따라 나타나기 | "부드럽게 이어 주기"가 아니라 치장이다(디자인품질기준 6장) |
| UI/UX | 기능마다 모달 · 토스트 남발 · 빈 상태에 큰 일러스트 + "아직 없어요!" · 단계 표시가 필요 없는 곳의 진행 막대 · 아무도 안 누를 보조 버튼 | 실제 사용 흐름이 아니라 "있어 보이는" 부품 조합 |
| 이미지 | 스톡 일러스트 느낌 · 3D 아이소메트릭 · 사람 얼굴 생성 이미지 · 가짜 대시보드 스크린샷 | 서비스의 실제 물건 · 실제 화면이 아니다 |

## 2. 지적하는 법 — "AI 티가 너무 심한데?"로 시작하되 근거로 끝낸다

- 신호 하나로 끝내지 않는다. **어디서 · 무엇이 · 어떤 기본값 · 공식과 닮았는지**를 쓴다
  - 예 : "로그인 카드 제목 40px · 설명 16px · 링크 14px — 1.25 등비 공식 그대로. 제목만 크고 내용과 무관한 위계 → AI 티(글자)"
  - 예 : "강조 버튼 색 `#2563EB` = 흔한 기본 파랑과 ΔE 1.2 → AI 티(색). 프로젝트 코발트 `#2F5FB1`을 써야 함"
- 색은 **ΔE**(CIEDE2000)를 계산해 기본 팔레트와의 거리로 말한다. 10 미만이면 "같은 색"으로 본다
- 움직임은 **무엇을 이어 주는지** 물어 답이 없으면 치장이다(지속 시간 · 이징 실측 포함)

## 3. 이끄는 법 — 사람이 고심한 쪽으로

지적에는 **방향**을 붙인다. 막연히 "덜 AI 같게"가 아니라, 아래 질문으로 사람의 결정을 만들게 한다.

| 방향 | 개발팀에 주는 질문 · 처방 |
|---|---|
| 내용에서 출발 | "이 화면에서 사용자가 1초 안에 알아야 할 것 하나는?" → 그것만 크게, 나머지는 굵기 · 색으로 낮춘다 |
| 서비스의 실물에서 색 | "분실물 보관소 · 안내 창구 · 종이 꼬리표"처럼 이 서비스의 현실 사물에서 색 · 질감을 고른다(이미 정한 마리골드 · 코발트 · 잉크 · 흰 종이). 새 색은 그 목록 밖이면 거부 |
| 불균형을 허락 | 모든 간격 · 반경 · 크기를 같게 두지 않는다. 묶음 안은 촘촘히, 묶음 사이는 크게 — 리듬이 사람 손이다 |
| 장식 대신 정보 | 면을 채우는 도형 · 그림자 대신 **실제 사진 · 실제 숫자 · 실제 상태**로 화면을 채운다 |
| 사람 말 | 화면 문구를 사용자가 친구에게 하는 말로 바꿔 본다. 마케팅 말 · 느낌표 · em-dash 제거 |
| 움직임은 연결만 | 이전 상태와 다음 상태를 이어 줄 때만, 짧고(150~250ms) 조용하게. `prefers-reduced-motion` 존중 |
| 한 가지 고집 | 화면마다 "이 서비스만의 것" 하나를 남긴다(예 : 꼬리표 모양 로고 · 칠한 포스터 그림 · 완료 도장) — 그 외에는 덜어 낸다 |

## 4. 등급

- AI 티가 **첫인상(첫 화면 · 로그인 · 등록)** 에 있으면 `높음`, 그 밖은 `보통`
- 프로젝트 결정 · 남겨 둔 예외와 부딪히면 지적하지 않고, 예외가 새로 늘었는지만 본다
- 대안을 낼 때는 비교 캡처(현재 / 제안)를 요구한다 — 본인이 고른다(디자인품질기준의 예외 규칙과 같다)
