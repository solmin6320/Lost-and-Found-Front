# 프론트엔드 보안 규칙

**전문은 리포의 `docs/보안명세서.md` 에 있다. 보안이 걸린 작업이면 그 파일을 먼저 읽어라.**
아래는 자주 틀리는 자리만 뽑은 것이다.

## 대전제

**클라이언트 코드는 비밀을 지킬 수 없다.** 브라우저에 내려간 것은 전부 사용자의 것이다.
프론트엔드 보안의 목표는 둘뿐이다.

1. 남의 스크립트가 우리 페이지에서 실행되지 않게 한다
2. 사용자의 자격 증명이 새어나가지 않게 한다

**모든 권한 판정은 서버가 한다.** 프론트에서 버튼을 숨기는 것은 UX이지 방어선이 아니다.

## 개발자 도구 차단은 구현하지 않는다

F12 차단, 우클릭 차단, `debugger` 루프, 난독화 — **전부 만들지 않는다.** 우회에 몇 초가
걸리고 그동안 정상 사용자만 불편하다. 요청받더라도 `docs/보안명세서.md` 1장을 근거로
설명하고, 대신 운영 빌드의 **콘솔 경고**(self-XSS 방지)를 제안한다.

## 절대 하지 않는 것

| | 왜 |
|---|---|
| `dangerouslySetInnerHTML` | 게시글 본문·댓글은 사용자 입력이다. 서버가 정제하지 않는다 |
| `localStorage`·`sessionStorage`에 토큰 | XSS 한 줄이면 전부 털린다. 액세스 토큰은 **메모리** |
| `VITE_` 변수에 비밀값 | 번들에 문자열로 그대로 박힌다 |
| 토큰을 URL 쿼리스트링에 | 히스토리·서버 로그·Referer에 남는다 |
| 운영 빌드에 `console.log` | 토큰·응답이 찍히면 스크린샷으로 유출된다 |
| 소스맵 배포 | 원본 코드가 공개된다 |
| `eval`·`new Function` | |

## 자주 놓치는 것

- `<a target="_blank">` 에 `rel="noopener noreferrer"`
- `href={userInput}` — `javascript:` 스킴 차단. `http`/`https` 만 허용
- 401 재발급은 **동시 요청에서 한 번만**. 여러 번 나가면 리프레시 토큰이 연속 회전하며
  서로를 무효화해 멀쩡한 세션이 끊긴다
- 로그아웃·세션 만료·비번 변경 시 메모리 토큰을 비우고 **개인 데이터 캐시(`memberKeys.all`, 내가 쓴 글 `postKeys.mines()`, mutation 캐시)를 제거**한다. 안 하면 다음 사용자가 이전 데이터를 본다. 공개 게시글·댓글은 `invalidateQueries`만(2026-09-27 — `queryClient.clear()`는 보던 화면을 스켈레톤으로 되돌려서 바꿈, `AuthProvider.forgetMember()`)
- 파일 확장자·개수 검증은 **UX이지 보안이 아니다.** 진짜 방어선은 백엔드다
- CI는 `npm install`이 아니라 **`npm ci`**. `package-lock.json` 을 반드시 커밋한다

## 배포 전

`docs/보안명세서.md` 9장의 체크리스트를 그대로 수행한다. CSP·HSTS 헤더는 CloudFront
응답 헤더 정책에 넣는다. **로컬에는 걸지 않는다** — Vite HMR이 인라인 스크립트를 쓴다.
